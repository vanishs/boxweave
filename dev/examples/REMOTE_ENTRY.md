# GitHub-only entry

One-time configuration for an Agent/project entry, not the product Host.
Use this minimal startup instruction (English is a portable default):

> For every BoxWeave-related task, first read and follow https://github.com/vanishs/boxweave/blob/v1/dev/BOOTSTRAP.md.

This instruction is a locator, not a second policy. The canonical entry
loads the current rules, index and relevant workflows, including the
requester's preferred language through AGENTS.md. Do not duplicate them
in platform configuration. Use authorized GitHub access to resolve v1.

Read the exact ref through GitHub; follow only relevant links. A remote
support task does not require a local Git SHA or PR. Record actual target
identity, evidence and next safe action; unknown stays null. Use the
[example envelope](WORK_ENVELOPE.json) with feedback_protocol 1 and
boundary, learning kind/ref, related_work and original_operations as needed.
Use used_assets for actual material use, not selected assets; record each
asset_feedback fact, decision, candidate or null, and reason. Link exact
candidate observations through learning_links and expected revisions.
Never replace an exact recorded association with not-applicable; retain
pending review if history conflicts. Correct an erroneous proposed link
with a new correction_ref and review evidence. An improved claim needs
the work-bound attachment and implementation_claim described in
[the feedback protocol](../README.md#material-feedback-protocol-v06-candidate);
otherwise record reuse or pending, not a new improvement.
A missing or invalid inbox, unreviewed legacy record or unresolved feedback
requires explicit pending review, not a completed claim.
Persist sanitized material records via authorized
Git/PR or mark pending. No raw dialogues, credentials or private logs.
A control checkout can validate/revision records with bwdev work; without
one use the same manual checklist, not a fabricated CLI result.

Inspect [inbox](../LEARNING_INBOX.md) and latest learning revisions via
GitHub; match domain, kind, failure signal, asset and follow-up condition.
Never overwrite old revisions; reconcile divergent histories. A tiny
question needs no issue or PR solely to satisfy BDH.

Verify actual activation with a fresh Agent session on each supported
surface and an ordinary prompt without per-task BDH reminders. This
instruction is deployable, not proof that it is installed.
