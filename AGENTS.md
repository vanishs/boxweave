This file contains **durable rules, not a dated development-status report**. Start here; read linked documents **only for the current task**. Do not preload the entire repository or treat old acceptance reports as proof for today's source, binary, or host.

Establish the requested scope, repository/branch/HEAD, relevant open PR, local changes, and (for native work) the **actual** installed version, host/layer, owned resources and original Operation IDs. ## Product and security boundaries

- BoxWeave is a **single-host, external-Agent-controlled, owned-Box MCP plane** using the official Go MCP and Incus SDKs. The **20-tool catalog is the v1 target**, not a claim that all tools are merged or released. Verify implemented tools against current source and actual MCP discovery. Do not expand scope without an explicit product decision: no general host shell/files, foreign Incus administration, guest-resident Agent/orchestrator, generic ACL editor, Caddy, Web console, snapshot/backup platform, extra MCP tools or replacement native APIs.
- Restrict each read/effect to the **actual owned Box UUID/incarnation, Project and authorized identity**, independently verifying native poststate. Names, IPs and SDK `UseProject` alone do not prove ownership. MCP must never gain a host-admin Incus socket, foreign credentials or arbitrary host/device privileges. `box_exec` runs **inside the owned guest**, not on the host.
- Only scoped **admin/viewer** credentials; viewer is read-only yet **can read sensitive guest files and operation output**. Require current caller authorization, including on reconnection and delayed reads. Do not equate revocation, timeout or a disconnected reader with cancellation of already dispatched work.
- Persist each mutation's **caller idempotency key, exact intent, Tracking ID and distinct BoxWeave/native Operation identities** before dispatch. Preserve original operation/output receipts. An uncertain native effect remains `UNKNOWN` until independently reconciled; **never blindly replay, adopt, wipe or delete it**. See [operations](docs/design/OPERATIONS.md) and [manual recovery](docs/process/UNKNOWN_MANUAL_RECOVERY.md).
- File changes must honor the [safe guest-file contract](docs/decisions/PRODUCT_BOUNDARY.md): native exclusive create is supported; do **not** fake atomic conditional replace/delete using read-then-write. Return `UNSUPPORTED` where point-of-use safety is unproven. Use approved guest Exec/Git for larger edits.
- Network changes use only the owned, restricted [native ACL/peer/forward design](docs/design/NETWORK.md), after current-phase implementation and safety proof. Default deny; no unapproved host-wide Incus/Scriptlet changes, public bind, foreign impact or custom proxy daemon. Treat nested Incus/AppArmor/BPF behavior as **environment-specific evidence**, not an unlimited-depth guarantee.

## Authority, development and evidence

- Technical access is **not** operator permission. Ask for fresh, exact-target authorization before physical-host installation, shared Incus/ACL changes, credential exposure, disruptive upgrades, public network exposure or destructive/irreversible actions. Existing authorized disposable tests may proceed within their stated limits. Do not co-install v1 with legacy `main` on a dedicated v1 host, force-push or silently modify foreign resources.
- Execute the requested bounded task end to end: inspect → implement → focused tests → native/independent verification **where required** → fix and rerun → record facts and hand off. A blocked subcase must retain its original IDs and honest `BLOCKED`/`UNKNOWN` status; continue only unrelated safe work. Fake/native-mock, source CI and earlier-version PASS do **not** establish current installed-native acceptance.
- Record meaningful decisions, original failures, exact source/binary identities and observed acceptance limits in the [execution log](docs/development/EXECUTION_LOG.md), without credentials. Keep source, public interfaces, tests and documentation in English; discuss with the user in their chosen language.
- **Before each commit, pass the applicable formatting gate; never commit unverified source.** For Go, run and verify `gofmt` **before committing**, including commits through GitHub API (which bypass local Hooks). If verification is unavailable, report the limit rather than claiming PASS or committing unverified Go. Detailed local/docs-only checks and PR rules are in [CONTRIBUTING](CONTRIBUTING.md).
- Use a topic branch and PR for `v1`. Preserve the protected required `quality-gate` on the exact candidate; code/config changes need the applicable complete CI and phase gates. **Green CI alone is not release acceptance.** A real candidate release/host promotion requires the explicit [versioning and publication contract](docs/process/VERSIONING.md), authorized native acceptance and independent evidence. Do not infer stable-release readiness from an RC artifact or a version string.

For detailed agent procedures, consult [AGENT_WORKFLOW](docs/development/AGENT_WORKFLOW.md) only when relevant. Use [documentation index](docs/INDEX.md) to locate specific evidence instead of copying old status into this entrypoint.
