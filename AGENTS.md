## Pre-release breaking changes — Owner directive, effective immediately

**Until the first formally supported release OR an explicit separate Owner compatibility/retained-data promise, backward compatibility is NOT required.** This applies to SQLite schema, API, MCP Tools, OAuth Scope/roles, tokens/Grants, CLI flags, SDK-facing behavior, installers, scripts, acceptance fixtures and disposable development environments. Earlier RC labels alone do not create a compatibility promise.

- **Remove suitable legacy baggage directly** when it adds avoidable architecture, maintenance cost or ambiguity. Refactor source, tests, native probes, CI, active docs and examples **together**. Prefer one clean implementation to aliases, migration layers, dual authorization paths, old-role fallbacks, deprecated fields and release-era compatibility scaffolding. Do not ask for fresh permission just to remove obsolete development-only behavior already covered by this directive. Explain consequential design/security changes.
- **Notify the Owner/users clearly whenever adoption requires rebuilding the environment.** State exactly which controller install, SQLite database, credentials/OAuth clients, external MCP connections, test fixtures and disposable Boxes must be recreated, which data or permissions will not survive, and the high-level safe reinitialization sequence. Make this visible in the change log, handoff and release/deployment notes **before** recommending rollout. Do not quietly imply an old environment will continue working.
- **No automatic data/resource destruction.** This policy allows incompatible code, **not** unilateral deletion or adoption of a running Incus Project/Box, guest data, original native Operation/UNKNOWN, host ACL/Scriptlet or shared service. Old schemas and unrecognized credentials must **fail closed** with an actionable recreate notice. Inspect/safeguard original receipts and native ownership before any separately approved environment reset. Use isolated fresh DB/Projects/Boxes for tests.
- Once a supported release or explicit retained-data promise exists, define the affected compatibility and migration obligations deliberately; do not assume this pre-release exception survives that boundary.

## Required source and verification gates

1. Read [CONTRIBUTING](CONTRIBUTING.md), [quality gates](docs/process/QUALITY_GATES.md) and only the active phase card before modifying the relevant implementation. Prefer the sole development PR; never force-push or bypass protected `v1` rules.
2. Update current contracts and evidence with the code. Use the repository-local hooks (`make hooks`) and `make verify`: Go `gofmt`, `vet`, module verify/tidy diff, race test, formatting/UTF-8/YAML/JSON checks and available script checks. A local PASS does not substitute for exact-head GitHub Actions.
3. On any security-sensitive change, verify both authorized and refused actions using an isolated installed controller/Incus where required, and obtain independent same-SHA native evidence. Old signed CI results do **not** re-sign changed source. Record honest `PASS`, `NOT_TESTED`, `BLOCKED`, and failure/UNKNOWN with native IDs and source hashes.
4. Log nontrivial decisions, work, regressions and test evidence without secrets in [EXECUTION_LOG](docs/development/EXECUTION_LOG.md) and the active [cleanup plan](docs/development/V1_SINGLE_AUTH_AND_LEGACY_CLEANUP_PLAN_2026-11-18.md). Preserve dated verification documents as historical records; keep this entrypoint short and current.
5. Discuss results in the requester's language; project source, active docs, tests and API contracts are English.

## Permanent product and security boundaries

- **One narrow controller:** official MCP Go SDK and Incus Go SDK; typed MCP APIs only. Planned public Tool set is 20 baseline, plus the Owner-approved S4-C `box_wait_ready` and Activity `box_activity_get` (22 planned total; 18 currently registered). No public generic host shell, arbitrary REST host administration, Caddy, guest Agent, orchestration engine, generic ACL editor, patch platform or extra recovery service. [Product boundary](docs/decisions/PRODUCT_BOUNDARY.md) · [MCP catalog](docs/design/MCP_TOOLS.md).
- **Authentication is never optional:** valid Bearer credential, stable independent Actor, Token-ID liveness/revocation and current Layer/Project/owned UUID/incarnation. Separate Actor credentials can inspect same-Layer original Operation evidence for takeover, but cannot borrow each other's idempotency identity or access foreign resources. Work/Agent labels and MCP metadata are **not** credentials.
- **Native safety cannot be deprecated:** non-root host service, exact owned Incus resources, independent state checks, no native host shell, no unsafe Guest file overwrite/delete (return `UNSUPPORTED` where atomic guarantees are absent), limited output and explicit network ACL/IPv4/IPv6/anti-spoof barriers. Guest-root Exec is **inside an owned Box**, not on the host.
- **Never blindly replay UNKNOWN effects.** Every mutation needs a reusable original idempotency key and durable operation receipt with the true native Operation ID; failed/ambiguous effects retain their claims and require the approved host-local audited recovery. Revocation rejects fresh requests but does not undo already dispatched native work. [Operations](docs/design/OPERATIONS.md) · [UNKNOWN recovery](docs/process/UNKNOWN_MANUAL_RECOVERY.md).
- **Owner-approved host effects only:** Incus daemon upgrade, shared Scriptlet/ACL migration, actual deployment, tunnel exposure, reboot and native resource destruction require separate explicit local scope and reversible preflight. Do not weaken foreign Project isolation, legacy external TLS-client permissions or network safety to make a test green. [Network](docs/design/NETWORK.md).

**Start small:** consult [documentation index](docs/INDEX.md) and [implementation plan](docs/process/IMPLEMENTATION_PLAN.md) instead of loading every historical investigation. Continue safe work when a specific test is blocked; never mark its release gate PASS.
