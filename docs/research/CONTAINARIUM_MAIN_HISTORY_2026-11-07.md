# Containarium main and commit history — bounded lessons for BoxWeave v1

**Research snapshot:** 2026-11-07. **Upstream studied:** [FootprintAI/Containarium](https://github.com/FootprintAI/Containarium) `main` at [`cef021a674f64d10498c637b3ef946c26134a6ba`](https://github.com/FootprintAI/Containarium/commit/cef021a674f64d10498c637b3ef946c26134a6ba) (2026-11-06); latest tagged release seen during this pass: `v0.131.0` (2026-11-05). **Destination:** BoxWeave `v1` at `d48501e776d7b8614f14d901a15c8796391cb7bc`, a **design-only** baseline, not a verified running v1.

**Method and limitations:** Traversed all 2,577 commit **subjects** in upstream `main` history (2025-12-28 through 2026-11-06); selected relevant themes, inspected representative commit messages, diffs and test-file changes, and checked current implementations/documents. **This is not a line-by-line audit of all 2,577 diffs, a claim that every historical defect persists, or a native installed acceptance test.** The historical commit explains an upstream failure and its change; v1 requirements below are reasoned safeguards, **not observed v1 defects**. Some source patterns remain only *risks to test*. Upstream `main` can differ from the tagged binary. Use fixed commit links when judging code rather than assuming later `main` is identical.

## Discussion decisions — narrow implementation, no scope change

1. **Network:** Validate native Bridge NIC ACL and other *already approved* supported Incus topologies (including actual IPv4 and enabled IPv6 packets). If a topology cannot prove directional all-protocol `box_peer_set` plus default private deny, fail closed/`UNSUPPORTED`; do not build eBPF, firewall DSL or Caddy. A profile-inherited NIC may need a complete instance-local shadow with ETag; preserve unrelated native settings and foreign resources. An instance proxy device and a network-level forward have different cleanup lifecycles; keep exact owned native identities.
2. **Files:** Keep `box_file_list` / `box_file_read` / single-file `box_file_apply(create|replace|delete)`. Staging/rename proves whole-byte placement, **not** original-hash CAS under a concurrent guest writer. Validate true atomicity/point-of-use guarantees with the selected native Incus API; refuse conditional mutation if unavailable, never silently downgrade it or add a guest filesystem service.
3. **Operations:** Keep the minimal SQLite intent/receipt/UNKNOWN mechanism; native Incus Operation IDs are separate. No missing exit code => zero, no timeout => cancellation, no transient NotFound => deletion, no client reconnection => replay. Known failures may have verified partial effects. Do not reproduce Containarium's SSH/provisioning/state/platform machinery to solve these cases.

These are refinements to approved behavior and **remain unimplemented/unverified in v1**. If native feasibility tests contradict an accepted requirement, record the exact blocker in [open risks](../verification/OPEN_RISKS.md) and seek an explicit owner decision **before changing product scope**.
