# Official MCP Go SDK v1.8.0: small, high-leverage capabilities for v1

**Research 2026-11-10 UTC; status: current tagged SDK verified, recommendations not yet implemented.** Official [latest release v1.8.0](https://github.com/modelcontextprotocol/go-sdk/releases/tag/v1.8.0) (GitHub latest API checked 2026-11-10), [Go API](https://pkg.go.dev/github.com/modelcontextprotocol/go-sdk/mcp), [protocol guide](https://go.sdk.modelcontextprotocol.io/protocol/), [server guide](https://go.sdk.modelcontextprotocol.io/server/). Current v1 `go.mod` already pins `github.com/modelcontextprotocol/go-sdk v1.8.0` and `github.com/lxc/incus/v7 v7.6.0`; **no SDK upgrade prerequisite**. S1 is an accepted installed foundation: `internal/control/server.go` already has authenticated typed `host_status`, stateless `/mcp`, and `internal/state/store.go` has schema v1 with `operations`/`operation_events`. S2's 12 lifecycle/Exec/operation Tools are **not yet accepted**.

## SDK adoption matrix — prioritise value, not feature count

| SDK element / actual tagged contract | Value to BoxWeave | S2 recommendation / caveat |
|---|---|---|
| **Per-request `_meta`**, `CallToolRequest.Params`, typed `ServerRequest.ClientInfo/ProtocolVersion/ClientCapabilities` (2026-07-28) | Optional `work_ref`/`agent_ref` and diagnostics without client sessions; clientInfo indicates *software*, **not Agent identity**. | Use SDK parser, defined safe extension namespace, validate sizes and normalize once; client `_meta` is untrusted; not all clients can emit custom `_meta`. Provide same optional fields on **existing** Tool inputs as compatibility path if truly needed and verified. Never add these fields to access-control decisions. |
| **`Server.AddReceivingMiddleware`** | One redacted ingress/request-duration/typed-failure observation, request ID and safe context; no copied logging in 20 Tools. | Install a **single thin SDK-native middleware** when phase implementation warrants it. MCP request handler still reads the authenticated TokenInfo; middleware does not bypass per-Tool auth, nor log raw params/argv/stdout/tokens. Use atomic bounded metrics or protected local log; avoid new trace server. |
| **Typed `mcp.AddTool`, `CallToolResult.StructuredContent`**, schema generation | Stable original `operation_id`, `tracking_id`, native evidence status, next read hint; helps Agent find work after disconnect. | S1's `host_status` is already typed. S2 extend its ordinary response structs; return only existing authorized data and do not overload error codes as success. Test both modern structured JSON and legacy clients' text fallback/typed decode; no hidden second control API. |
| **`ProgressToken` + `ServerSession.NotifyProgress`** | Optional interim progress while an HTTP request is **alive**. | Only send if a token is supplied and a *meaningful* bounded phase is observed; never block S2 async admission to keep progress notifications flowing. A notification is not durable; compare client support at S2.5/S5 and leave disabled if UX gain is unproven. |
| **`ToolAnnotations`: ReadOnlyHint, IdempotentHint, DestructiveHint, OpenWorldHint** | Low-cost truthful hints helping many Agent clients avoid risky tool selection. | Mark read-only `box_list/get`, `operation_get/list/output_get`, `host_status` as read-only. For mutations, classify destructive risk accurately (notably `box_delete`, Exec, file delete, forwards). **Do not set IdempotentHint=true on arbitrary mutations** just because identical *idempotency keys* deduplicate: separate keys can produce separate effects. Annotations are advisory, not auth/security. |
| **`ServerOptions.SetCacheable`, `cacheScope`/`ttlMs`** (2026-07-28) | Prevent unsafe cross-token caching of private results and stale visibility. | SDK default may put **public** cache scope when unspecified. For authenticated private tools/discovery/list, explicitly review and prefer `private`, conservative `ttlMs` or 0. This hook can run while server lock held: do **not** call Server methods inside it. Not a substitute for read-time auth or endpoint security. |
| **SDK protocol discovery and versions**: `server/discover`, `initialize` fallback, stateless Streamable HTTP | Prevent old URL/negotiation mismatches from masquerading as native failures. | Keep the one SDK transport; test correct `/mcp`, wrong `/`, old/current protocol revisions, invalid Origin/Host/auth and true client Tool invocation. No bespoke version allowlist or OAuth; no public MCP admin bypass. |
| **JSON-RPC validation and typed errors** | Distinguish transport/malformed-call failure from admitted native operation UNKNOWN. | Preserve SDK InvalidParams/UnsupportedVersion semantics and fail closed before side effects. Business `UNKNOWN` must be a persistent Operation state, not a generic JSON-RPC timeout/failure. |
| **MCP Tasks extension `io.modelcontextprotocol/tasks`** | Future wire-level handle for deferred results/reconnect. | **RESEARCH ONLY**: official Go SDK v1.8.0 roadmap still treats Tasks as future. Keep protocol-neutral Operation snapshots; don't register raw tasks RPCs, a second worker/database, or advertise capability. [Future adapter study](MCP_TASKS_EXTENSION_SEAM_2026-11-10.md). |

## Other available SDK features deliberately **not** added

- **MRTR / InputRequiredResult**: on 2026-07-28 the SDK can request client input and *reinvoke* the handler; with older clients it can transparently conduct legacy elicitation then invoke again. For an admitted native mutation, that creates a dangerous double-dispatch boundary unless extra idempotency is correct; BoxWeave v1 keeps explicit local manual UNKNOWN recovery and existing caller key. No new remote human-approval feature.
- **`subscriptions/listen` / list-change notifications**: helps subscribed clients with live notifications but is not a durable event store and not a safe cross-Agent replay. No automatic event bus, subscription server or new public Tool.
- **`ping`/`KeepAlive`**: removed from protocol `2026-07-28`; SDK maintains only backward API support. It cannot tell whether an Incus write finished and is not a substitute for `operation_get`.
- **Legacy MCP Logging/Roots/Sampling**: deprecated in 2026-07-28; their presence in SDK is not justification for logging sensitive guest data or allowing the server to orchestrate the Agent.
- **Resources/Prompts/Completion**: optional MCP capabilities, but they would expand this intentionally narrow 20-tool management surface with no compelling v1 operator need. Do not add just because the SDK supports them.

## Concrete S2 integration seams, not speculative infrastructure

1. In `internal/control/server.go`, use real SDK request metadata + authenticated `req.Extra.TokenInfo` and one thin receiving middleware for redacted request ID, method/tool, duration, result class and optional validated correlation. Never trust `clientInfo` or `work_ref` as principal.
2. In `internal/state/store.go`, implement **versioned** schema migration with explicit safe backups/rollback and bounded indexed `work_ref`/`agent_ref` columns on *original admitted Operation* (not a new Task table). All duplicate-key replays return the **original** correlation snapshot unchanged. Protect a private DB and cap storage; read-time auth always first.
3. Keep official Incus v7.6.0 native `operation_id` separate from BoxWeave ID, verify postconditions, avoid `Operation.WaitContext(ctx)` for read-only polling: prior SDK probe found it may invoke native Cancel when context ends. Do not use `GetOperationWait` with an untested shared client transport because it mutates response timeout settings. Use bounded `GetOperation` and controlled polling until safe alternative tested.
4. Ordinary MCP `tools/call` returns typed short receipt and `next_action` **as advice only**, not a queued retry. `operation_get/list/output_get` are the only discovery/recovery surfaces. Progress notices only where caller requested/SDK supports, and only for live short waits.
5. Test client combinations: negotiated `2026-07-28` with `_meta`, legacy initialize with no custom metadata, two separate authenticated actors, revoked tokens, same-work distinct actors, privacy-safe Tool annotations/cache scopes and bursty operation readback. No hidden new MCP methods.

## Tagged-version caution

This is **tagged v1.8.0** behavior, not a promise about future SDK HEAD. Before implementing an SDK-dependent interface, inspect the exact pinned Go type/method signature and compile a small dedicated test.
