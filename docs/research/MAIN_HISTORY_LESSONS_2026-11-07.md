## Historical revision: late MCP→REST and subsequent fixes are primarily counterexamples

**Classification rule (owner correction):** The late v0.42+ selective REST work, the v0.49–0.50 unified REST/async push, and their follow-up patches are **not presumptive sources of good v1 architecture**. Study their changes as failure-mode evidence. Only retain general, independently justified invariants already needed by the direct Incus SDK design. Do not generalize “because main eventually patched it, v1 should implement the same compatibility subsystem.” Likewise, not every incident was demonstrably caused by REST itself: concurrent changes to transports, packaging, test harness and background coordination confound strict causal attribution.

### Owner retrospective and pinned v0.50.4 re-review (2026-11-07)

**Owner observation, not a measured incident-rate claim:** The owner recalls that BoxWeave became substantially more troublesome **after the MCP-to-REST changes began**, and wants that period treated primarily as **negative design knowledge**. This is an important first-hand chronology and selection of what to investigate, **not proof that the REST protocol itself caused every subsequent defect**. The practical anti-pattern is changing internal provider transports **while preserving the original SSH MCP relay, application Web/CLI, HTTP MCP, multiple journals, shared-claim machinery, guest-readiness rules and release/install contracts**. In v1, **the remedy is not "REST is bad, MCP is good"**: MCP stays the single *public* protocol; the *internal* provider is the official native Incus Go SDK, with no Containarium REST or MCP proxy.

**Immutable current-state evidence:** [main `654971c`](https://github.com/vanishs/boxweave/commit/654971c2af4be00c6ebfb614577e381add8d17ac), source `VERSION=0.50.4`, separate stable-installer pointer `PUBLISHED_RELEASE=0.43.1`. Reachable commit index: 814 subjects; tree: 516 files, including 70 `bwmini/` code modules, 92 `tests/` files and 269 `docs/` files. File and commit counts measure surface/maintenance load, **not automatically defect count**. Original source/fixture/live reports must remain separately graded.

**Concentration, not a defect-rate claim:** GitHub Releases v0.50.0 (2026-11-07 03:54 UTC) through v0.50.4 (08:21 UTC) were **five published versions in about 4 h 26 min**; their diffs show multiple integration/consistency corrections. A release count or chronology by itself cannot prove a protocol caused the incident count. The repeated *boundary repairs* are the actionable evidence.

**Reverse-design decision for v1:** Remove the condition that created the repairs—multiple simultaneously authoritative Provider paths and receipts—instead of copying each patch. Keep exactly one public MCP boundary, one checked domain admission, one native SDK invocation, one durable original Operation and one independently observed outcome; allow a later deliberate same-effect action after verified terminal completion. Where the native result is unavailable, the **public state and locks must both stay conservative**. This adds **no new v1 tools, daemon, REST transport, retry pathway or production policy**.

**Verification discipline:** A green source fixture does not validate the correctness of its asserted state semantics. See [v1 A-016, A-018, A-076, A-081–A-082](../verification/ACCEPTANCE.md); all remain **UNTESTED**. No old host, live Incus workload, v1 binary or installed acceptance was exercised during this retrospective.

### Independent invariants versus inherited workaround

1. **Independent invariants** worth retaining: actor authorization, exact resource identity, safe idempotency, clear observed vs unknown native outcome, bounded guest Exec, actual installed artifact provenance, and precise cancellation semantics. These are necessary even with a single Incus adapter.
2. **Workarounds not worth inheriting**: Containarium REST error-text parsing, MCP/REST compatibility bifurcation, arbitrary protocol fallback, multiple mutation gateways, translated pseudo-status codes, generalized R-04 cross-entry leases, monolithic diagnostic collectors and elaborate reacceptance orchestration.
3. **Required causal discipline**: cite a specific pre-existing bug and the associated diff before claiming its cause. If source and test evidence only establish “fixed after the migration,” write that—not “caused by REST.”
4. **Product-size gate:** a lesson should remove code or simplify one of the existing 20 tools/host-local CLI; if it adds services, tools, config modes or broad test infrastructure, it is **rejected by default** pending explicit owner approval.

## Scope control and outstanding discussion

**Do not port:** Containarium REST status patches, SSH enrollment/hostkey scanners, Caddy, OAuth, Web console, prompt graphs/model wizard, Tenant ACL/RBAC, general lease API, auto-sleep/wake, snapshot/backup, generic patch engine, complex signing platform or reacceptance daemon. These either duplicate Incus capability or exceed the owner-approved v1 product.

**Potential small refinements to discuss, NOT yet approved:** (1) installation config preservation and rollback checkpoint contract; (2) empty/stderr-only Exec completion contract and bounded output continuation; (3) exact nested creation state without post-create replay; (4) CI test inventory drift and package completeness guard; (5) targeted test selection vs full native/nested release gate. All fit existing 20 MCP tools and local CLI.

The scanned GitHub main commit history starts 2026-10-28. Imported legacy notes describe older work but are **not** a substitute for traversing older independent repository histories or private ignored research files. No claim that all 814 diffs or historical native setups have been independently executed.
