## Historical revision: late MCP→REST and subsequent fixes are primarily counterexamples

**Classification rule (owner correction):** The late v0.42+ selective REST work, the v0.49–0.50 unified REST/async push, and their follow-up patches are **not presumptive sources of good v1 architecture**. Study their changes as failure-mode evidence. Only retain general, independently justified invariants already needed by the direct Incus SDK design. Do not generalize “because main eventually patched it, v1 should implement the same compatibility subsystem.” Likewise, not every incident was demonstrably caused by REST itself: concurrent changes to transports, packaging, test harness and background coordination confound strict causal attribution.

### Independent invariants versus inherited workaround

1. **Independent invariants** worth retaining: actor authorization, exact resource identity, safe idempotency, clear observed vs unknown native outcome, bounded guest Exec, actual installed artifact provenance, and precise cancellation semantics. These are necessary even with a single Incus adapter.
2. **Workarounds not worth inheriting**: Containarium REST error-text parsing, MCP/REST compatibility bifurcation, arbitrary protocol fallback, multiple mutation gateways, translated pseudo-status codes, generalized R-04 cross-entry leases, monolithic diagnostic collectors and elaborate reacceptance orchestration.
3. **Required causal discipline**: cite a specific pre-existing bug and the associated diff before claiming its cause. If source and test evidence only establish “fixed after the migration,” write that—not “caused by REST.”
4. **Product-size gate:** a lesson should remove code or simplify one of the existing 20 tools/host-local CLI; if it adds services, tools, config modes or broad test infrastructure, it is **rejected by default** pending explicit owner approval.

## Scope control and outstanding discussion

**Do not port:** Containarium REST status patches, SSH enrollment/hostkey scanners, Caddy, OAuth, Web console, prompt graphs/model wizard, Tenant ACL/RBAC, general lease API, auto-sleep/wake, snapshot/backup, generic patch engine, complex signing platform or reacceptance daemon. These either duplicate Incus capability or exceed the owner-approved v1 product.

**Potential small refinements to discuss, NOT yet approved:** (1) installation config preservation and rollback checkpoint contract; (2) empty/stderr-only Exec completion contract and bounded output continuation; (3) exact nested creation state without post-create replay; (4) CI test inventory drift and package completeness guard; (5) targeted test selection vs full native/nested release gate. All fit existing 20 MCP tools and local CLI.
