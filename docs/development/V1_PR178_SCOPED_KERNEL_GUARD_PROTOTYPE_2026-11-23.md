## Tested source — no privileged execution path

- `internal/install/network_peer_scoped_guard.go`: pure `NativePeerGuardFromSnapshot` compiler produces `NativePeerGuardPlan{Table, Install, Replace, DigestSHA256}`. Uses exact Project+bridge-derived nftables table, one `bridge` `forward` chain at priority **-250** (Incus 7.6 per-NIC bridge chains observed at **-200**), and `meta ibrname` matching the exact owned bridge.
- Input must include every pinned native `{UUID, MAC, IPv4, IPv6}` owner (at most `networklimits.MaxProjectBoxes`), global confirmed and revoked directions, and a live managed dual-stack bridge. Validates exact canonical unicast MAC, UUID, canonical IPv4/IPv6 with subnet/gateway exclusions, duplicates/reuse, bridge/Project/ACL safe names, strict global peer snapshot via existing compiler, and *every* live or revoked peer's match against the supplied inventory. **Input is a claim, not native ownership proof**. The future Root dispatcher MUST independently verify global UsedBy, pinned leases, native incarnation/UUID, absence of foreign consumers, and complete entire inventory before applying.
- Guard permits an *approved directed* A→B packet only when both IPv4/IPv6 source/destination and MAC identities match. B→A only if `ct state established,related` (replies), not a new B→A connection.
- Terminal DROP matches **the full bridge IPv4/IPv6 prefixes**, not only pinned member IPs. Also DROP unapproved IPv6 link-local unicast `fe80::/10`→`fe80::/10`, retaining `icmpv6` neighbor solicitation/advertisement. It does **not** claim protection against all multicast and non-IP L2 schemes, nor against an altered/absent guard table, foreign bridge consumers, forged unknown prefixes, or unproved boot ordering.
- `Install` and `Replace` are *text only*: a bounded `nft -f` initial table and a single-batch `flush chain ...\nadd rule ...` update respectively. The compiler does **not** run `nft`, use the Host shell, touch systemd, modify Incus ACLs or expose anything via MCP. Guard state/readback, once installed, must be verified separately; successful process exit or digest of intent is never packet proof.
- `internal/install/network_peer_scoped_guard_test.go`: deterministic A/B/C/D, C→D preserved across A→B grant/revoke, dual-stack exact forward and stateful reverse, no unilateral B→A, deny-on-whole-subnet + link-local, invalid owner MAC/UUID/IP/reused address/foreign IP/hidden peer/Project-name injection cases. **Full isolated `make verify`**: `c6e78141ee0be4d2a5b03588deb11320`, durable Operation SUCCEEDED, **Guest exit 0** (Go/vet/mod/race all packages, Python MCP/uninstall/stable-gate/raw-witness). ## Critical remaining blockers / exact support boundary

- **No production Root/nft writer**: a live dispatcher MUST acquire the exact original and native/SQLite locks, validate immutable actor authorization, complete Project/bridge/ACL/native lease/UUID/UsedBy inventory, secure installed guard-table ownership and current kernel policy, and bind SHA/ETag+original to a durable journal. No execution if any evidence is missing. `NativePeerGuardPlan` alone cannot perform or authorize those tasks.
- **Boot persistence and safe recovery**: root-only initial install should provide an auditable bounded Host mechanism and guarantee that guard enforcement exists before *any* unquiesced peer ACL update. On absent/corrupt table or unknown actual grant, fail closed and keep original UNKNOWN/locks; do not silently disable other Boxes or blindly replace an unknown nft table. Startup dependency and live native rehydration after Host reboot are **NOT_TESTED**.
- **Full packet model**: IPv4+IPv6 unicast was shown for A/B; IPv6 C/D Forward, UDP, multicast/non-IP frames, link-local peer application tests, MAC/IP reincarnation, foreign bridge NICs, user-host routing, nft/Incus ack loss, concurrent grants, netlink partial failures, original journal crash recovery and prolonged C/D connections still need acceptance. Outer test AppArmor `unconfined` is not enforcing recursive security proof.
- **Autostart**: new Box default was fixed in first code slice, but the **current deployed Peer root barrier still stops ALL project consumers and retains `boot.autostart=false`**. This compiler does not change or mask that behavior. Automatic MCP grant/revoke is NOT IMPLEMENTED, Host still needs each one-original approval.
- **Threat model / bounded Host path options**: (A) one-time installed socket-activated fixed root binary, narrow Unix peer credentials + original ledger authorization, no shell/admin RPC, one original per activation, separate root-only network plan journal; (B) one-time installed fixed systemd template/batch service with restricted authorization for exact original, exit after each operation, no arbitrary ExecStart arguments. Both require repeatable trust-boundary testing of daemon compromise/forged SQLite/foreign actor and robust digest/lock/boot handling. Neither has been implemented or selected for general root deployment. Do NOT turn the current one-use service into an unrestricted reusable root shell.
- **Next code**: implement exact root-owned guard inventory/readback/fault fence; prove C/D UDP/IPv6 Forward and no leak through ACL fanout, migration into per-NIC ACL with zero unrelated restarts, bounded initial Host installer and MCP dispatcher, commit/restart/recover journal. Update #177 Doctor *after* verified #178 architecture is integrated; do not alter #177 now.
