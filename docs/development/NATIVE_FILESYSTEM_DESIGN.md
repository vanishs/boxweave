# Native Filesystem — design and delivery plan

Status: owner-directed design and R0 feasibility research. No feature acceptance, stable release, migration, or change to existing host configuration is implied. Target is the Resource-native design (C), absorbing useful Agent-facing operations from design B. This is a new product workstream, not BDH maintenance. Current implementation and policy remain authoritative until explicitly changed in this PR.

## 1. Motivation and evidence

BoxWeave v1 already has three file Tools, implemented in [control/file_tools.go](../../internal/control/file_tools.go) and [native/file.go](../../internal/native/file.go). Native SFTP is already the foundation; do not introduce a second transport to Incus. Current tools are Running-only, directory output bounded at 50 entries, underlying directory read bounded at 512 KiB / 4096 entries, file pages and exclusive creates bounded at 64 KiB. Read responses are base64, and there is no native conditional replace/delete. Historical RC14 argv cap was 4096 bytes per argument. These constraints lead external agents to use guest Exec for source upload, file assembly, and edits.

Evidence:
- [S3 native acceptance](../history/development/S3_FILE_TOOLS_PHASE2_NATIVE_ACCEPTANCE_2026-11-15.md): real concurrent exclusive-create, special path and large-directory negative tests; supervised guest scope, not adversarial path-race safety.
- [P0 SDK tests](../history/verification/P0_SDK_LAST_GATE_RESULTS_2026-11-08.md): actual intervening writes defeated hash-check-before-overwrite/delete; no native CAS.
- [BDH V3 transfer](BDH_V07_V3_PROGRESS.md): actual 81920-byte source, 18 core MCP calls, 34 supporting calls, 52 total; no true crash test or matched benefit.
- [BDH development record](BDH_DEVELOPMENT_PLAN.md) and [L014 rev39](../../dev/learning/BDH-L014/00000039.json): V4d lanes 73/250/81 calls, functional success but two independent REOPENs. Lane B used the planner but incurred receipt/page orchestration; C discovered but did not use it. Not a controlled causal comparison. Prior unrelated successful Operation/Tracking ID association defect was corrected; preserve original evidence association.
- [Existing continuity contract](../design/AGENT_OPERATION_CONTINUITY.md) and [Operations](../design/OPERATIONS.md): authoritative original receipt, not client label or a new synthetic job.

Objective: improve actual independent agent delivery on source editing, artifact delivery, large logs and stopped-Box repair, with less model-mediated byte traffic, fewer calls and less manual coordination. No claim of benefit until matched evaluation.

New CLI file list is a reference for metadata, not a new SDK file API; daemon forkfile fixes need native verification. Test dependency upgrade separately from new runtime behavior. Existing 7.6 hosts are not silently upgraded.
- Official MCP Go SDK v1.9.0-pre.1 as R0 candidate; use exact tagged stable 1.9 when available and revalidate, or retain stable 1.8 with compatible capability subset if prerelease blocks delivery. [Releases](https://github.com/modelcontextprotocol/go-sdk/releases), [Resources SDK implementation](https://github.com/modelcontextprotocol/go-sdk/blob/v1.9.0-pre.1/mcp/server.go). Verify protocol negotiation, request auth, JSON result and request limits, cache hints, actual notification support under our stateless JSON transport.

[Daytona](https://www.daytona.io/docs/), [E2B](https://e2b.dev/docs): separation of control and data; do not import agent runtimes or external services. Verify licenses/revisions before any code reuse. Patterns, not proven BoxWeave gains.

## 3. Architecture and scope

One Go controller per layer; one ownership, authorization, native connection, SQLite, Operation and recovery system. Tools and Resources share a bounded Filesystem Core; a future Files adapter invokes the same Transfer Core. No guest-resident agent, extra daemon, network share, raw host path, arbitrary URL fetch, global index, public SFTP listener, second database or vendor-specific MCP client adapter. No snapshots, backup, volume management, bidirectional sync, watch of arbitrary guest changes, or general archive extraction in first delivery. Storage volume SFTP is an upstream future seam only.

Proposed catalog: retain the three existing file Tools, add two (25 total). Update catalog, AGENTS/product boundary, strict schemas and discovery tests only after design is frozen; do not enable unproven operations. Explicitly preserve existing input/output defaults and semantics where compatible.

| Tool | Proposed scope | Read/mutate |
| --- | --- | --- |
| box_file_list | list, bounded tree, stat, batch stat, metadata and links | read |
| box_file_search | name, text, bounded regex, line/context, exclusions | read |
| box_file_read | text, lines, head/tail, bytes, batch, metadata/hash, links | read |
| box_file_apply | exclusive create, directory create; preview/dry-run and bounded edits/patch, move/delete/append only with explicit verified contracts; ordered batch | mutation except preview |
| box_file_transfer | within/across owned Boxes, staged upload, download reference or chunk, manifest, status and verification | stage/commit mutate; status/download read |

Avoid one giant untyped action schema. Use strict tagged modes with mutually exclusive fields, limits and typed errors. Freeze actual wire schema after R0; a pure preview must not create an Operation or alter content. Existing mutation annotations must not mislabel a preview or read as safe; consider splitting a mode or using a read Tool for preview if needed. No cross-file transaction claim. Server advertises usable capabilities and limits in existing host_status/box_get or file results, not a new capability service. Explicit return of unsupported modes.

## 4. Resource-native interface

Resource identifiers use canonical custom URI and bind layer, owned UUID and incarnation, never mutable names or host paths. Illustrative template: boxweave://boxes/{box_id}/{incarnation}/fs/{+path}. Reserve separately identified directory and bounded view resources; use RFC6570 expansion and strict canonical decode/roundtrip (encoded slash, traversal, NUL, control chars, duplicate query, normalization, wrong incarnation). Do not treat a URI as authorization or store tokens in URI. Generic static entrance/template metadata only; no per-file global registration or enumeration of private names. Every read reauthenticates current Actor and exact native ownership; recheck before response. Same Layer takeover remains governed by existing Actor policy, not work_ref labels. Resource Links and embedded resources in tool results point at same file service. Text uses UTF-8 only when valid; binary uses bounded blob or explicit transfer. Resource contents are untrusted guest data, not Agent instructions. Mutable live resources are observations, not immutable revisions; use explicit digest-addressed staging only where verified. Default private zero TTL; legacy clients lacking cache hints must still be handled. Do not promise subscriptions with current stateless transport; only implement if SDK/client/transport and revocation evidence support them; notifications limited to controller-observed changes.

Tools-only clients must complete all baseline tasks (including upload chunks) without needing resources/read. Resources-capable clients can read links; Files-capable clients may use negotiated external data flow. Test actual client behavior and not just SDK fixture. No client brand detection. Do not advertise experimental protocol support before both client and server proof. Resource links do not guarantee the host can fetch a file or that binary bytes avoid the model. MCP Files adapter, if approved, uses same-origin authenticated, scoped expiring references and byte streaming with appropriate TLS; no public anonymous endpoint or arbitrary external redirect. Keep the stable Tools fallback.

## 5. Incus native online/offline core

Use official GetInstanceFileSFTP / GetInstanceFileSFTPConn, pkg/sftp streaming, Lstat, handle Stat, ReadAt, WriteAt, directory enumeration, and negotiated extensions. Native forkfile mounts stopped LXC rootfs and applies disk idmap without booting guest. This is not equivalent to live runtime mounts. Restrict to owned Linux containers; never mount host storage directly. Support Running, Stopped and never-started when native probe passes; deny transitional, stale, frozen or unsupported state. Capture UUID/project/incarnation before and after access. Coordinate against start/stop/delete/resize and conflicting mutation with existing resource claims; ensure deterministic ordering for two-Box transfer. Connection reuse only for a bounded admitted request; no global cross-Actor session reuse. Native filesystem access is possible even if guest command readiness fails. No implicit start. Test UID/GID/mode, mount cleanup, storage driver and nested mapping; never weaken ancestor policy to get a green probe.

Safe path policy: component validation, no pseudo FS, no following symlinks by default, special file rejection, explicit hardlink provenance limitation, no arbitrary mount traversal. Current SFTP v3 does not guarantee atomic ancestor resolution; Incus 7.7 fixes do not prove BoxWeave's check/open race safety. Distinguish trusted supervised guests from stronger adversarial claim. Check extension advertisement and actual behavior, not just method existence. Bound scan work, memory, file count, depth, elapsed time, per-Box/global concurrency and wire bytes. pkg/sftp eager ReadDir limits remain a blocker for giant directories; fail with typed scan-limit coverage, not pretend server-side stable pagination. Search uses streaming bounded literal/RE2-style matching, no mandatory guest grep, and explicit incomplete coverage. For UTF-8 line views handle CRLF, long lines, split multibyte characters, no silent replacement, and bounded scan bytes. Batch results share one aggregate response budget, compact metadata, continuation and item error; not N independent full caps. Hash only covered bytes; full streamed observation not snapshot proof.

## 6. Mutation and conflict contracts

Exclusive create remains supported. Investigate no-clobber publication of verified staging data, same-directory atomic rename and extension availability; atomic visibility is not CAS and not necessarily crash durability. No fake check-hash-then-write, rename or delete. Existing conditional replace/delete stay UNSUPPORTED absent point-of-use proof. Owner must separately decide any explicitly non-CAS overwrite semantics after evidence; no hidden weakening. Stopped guests remove ordinary guest-process competition but not foreign native writers, attached shared storage or external host access. Never claim exclusive access from state alone. BoxWeave serializes its own writers, not external writers. Preview should return bounded diff and expected observation, not reserve a permanent lock. Revalidate apply and be truthful about preconditions. Patch parsing deterministic, bounded, reject ambiguous matches, duplicate/conflicting paths, unexpected bytes, malformed/unbounded patches; preserve newline and executable permissions where proven. No arbitrary command execution in patch engine. Directory create/rename/append must specify per-mode preconditions, failure and postcondition. Batch is ordered partial results, not atomic across files. No implicit recursive delete. Existing Exec remains for general guest build/test and user-authorized shell work; not a silent fallback for unsupported file Tool.

## 7. Transfer lifecycle

Data locations: client bytes, exact owned guest source/destination (same or distinct Boxes), bounded controller-private staging. No arbitrary host path or third-party source. SFTP-to-SFTP bounded streaming copy avoids model and guest network; no Peer grant needed. Source must remain consistent enough for claimed result; use handle metadata and digest, report observed-byte vs snapshot guarantees. Destination defaults no-clobber, verified before publication; preserve mode/time only explicitly and safely, no setuid/device/symlink import. Manifest binds source/destination UUID/incarnation, canonical relative paths, size, digest, safe attributes and ordered entries. Reject duplicates, collisions and path escape. Incremental copy by verified digest is later optimization, not first delivery prerequisite.

Prepare -> receive/copy -> verify -> publish -> complete. Reuse original Operation for durable intent, stage and evidence; no second public task system. Persist stable actor/key/fingerprint, transfer identity, bounded manifest, confirmed chunks/ranges and state; payload stored in quota-bounded private staging, not raw SQLite journal/log. Reuse exact original ID on retry; conflicting key/offset/digest denied before effect. Chunk acknowledgement only after required persisted data and metadata; validate offset/length/overlap, expected full size and digest. Reconnect uses compact verified progress and next missing range; not per-part manually transcribed Operations. Stream upload adapter shares state. No claim of true resumability until interruption at real write, ack, verify, publish, and controller restart is tested. Verify destination bytes and independent identity; uncertain publication stays UNKNOWN, no blind replay/delete or false no-effect. SFTP has no native async Operation ID; do not invent one. Reconcile exact original receipt and stage provenance, not only matching bytes. Disk-full, cancellation, expiry and revocation require explicit outcome, retain uncertain evidence and bounded cleanup of proven owned stages only. Do not hold SQLite transaction across network I/O. Per-request and global limits set from probes; enforce raw, encoded, JSON and model result sizes separately. Current 4 MiB HTTP cap and base64 expansion are distinct from file size. Proposed tests 80 KiB/75051/131019 bytes, 1 MiB, 64 MiB, 256 MiB; actual release cap selected by stress evidence, not arbitrary unlimited transfer. No server-side data retention beyond documented bounded policy. Keep quota, stale stage cleanup, restart and retirement/uninstall integration in scope.

## 8. Blocking decisions and R0 exit criteria

| Risk | First probe | Nonblocking fallback |
| --- | --- | --- |
| Incus 7.7 package/toolchain/nesting | exact package + SDK build, daemon client versions, restricted Project | report native blocker; source/SDK work continues; no host upgrade |
| offline mount/lifecycle | never-started and stopped read/write, start/stop race, cleanup | advertise only proven states |
| CAS/path safety | exclusive create, rename behavior, race and extension tests | keep conditional modes unsupported; no policy weakening |
| client Resources support | real core methods, links, auth and legacy/current discovery | Tools fallback |
| Files extension unstable | reviewed draft and actual negotiation, separate adapter feasibility | defer adapter; baseline transfer remains independent |
| transfer crash durability | actual failure at staging/ack/publication + restart | release only proven copy/create semantics, no resume claim |
| data bounds | 6000 entries, long lines, binary/UTF8, aggregate limits | typed incomplete/limit |
| schema compatibility | check schema 7 exact DDL, installer/retirement, stage cleanup | separate owner-reviewed schema decision, no migration/reset |
| CI/versions | exact base and required checks, source/installed/native distinction | isolate new probe from product gates until accepted |

R0 includes minimal native Go SDK probes in a disposable nested Box, not production code. Capture exact lab UUID, original Operation IDs, native and SDK versions, source, outputs, exit codes and excluded cases. Probe against fresh inner fixtures only; no outer daemon admin, no public listener. R0 closes only with tested capability matrix or explicit fallback/blocker for each risk. Existing code is not silently changed.

## 9. Delivery phases and acceptance

P0 dependency/contract: pin exact versions, run existing full source/native applicable tests, decide 25-tool and schema scope, preserve prior guarantees; review upstream changes. P1 native core: bounded online/offline access, identity, state and lifecycle coordination, metadata, limits. P2 Resources: shared core, templates, links, read and auth, Tools-only fallback; test both protocol surfaces and actual client. P3 Agent interaction: search, line/text/batch read, preview, proven mutation modes. P4 Transfer: same/across-Box streaming, bounded chunk fallback, manifest, journal/recovery, data cleanup and quota. P5 experimental MCP Files adapter: separate opt-in capability and actual client witness; defer if upstream/client immature. P6 combined acceptance: independent review, CI, real installed candidate and agent tasks. Each P uses R0 investigate/refine, R1 contract/baseline, R2 implement, R3 integrate/regress, R4 native/real use, R5 independent review; merge stages where no material extra value. Reuse consolidated CI/tests, avoid per-stage workflow proliferation.

Acceptance scenarios: actual source >64 KiB upload; batch source transfer; search and read relevant lines; edit/preview with safe conflict behavior; stopped/never-started prepare and repair; cross-Box build artifact copy; reconnect/restart, duplicate and mismatch; disk full, stale identity, revoked Actor, large directory, symlink/hardlink/FIFO, invalid URI, mixed binary/UTF-8. File tasks must not need Exec for the file work; build/test may use Exec. Separate Go deterministic protocol/negative tests from real native/installed proof and real Agent utility. Matched comparison against RC15/legacy workflow on same tasks, permissions, bytes, fixture and limits. Record success, actual calls including polls and retries, transferred bytes/model-visible bytes, time, manual intervention, false finish, restart/recovery and maintenance. No invented hidden token metrics. Freeze oracle before comparison and report unavailable client capabilities. Prior historical BDH records remain unchanged.
