Names below quote actual existing operation details where supplied; new Doctor issue identifiers are proposals, not implemented API. Keep observation, severity, coverage, resolved/history/current status and repairability separate.

| Explicit boot.autostart=false | User policy, not drift merely because default is true. Preserve across Peer and recovery. |
| Legacy one-original unit absent, ADMITTED | Not a routine Host approval wait. Check original, age, controller, exact claims and scoped lifecycle service. Stage and claim occur atomically before Root dispatch; do not require every observed ADMITTED to already have five claims. |

| SUCCEEDED with SCOPED_PEER_V2_GRANT_KERNEL_VERIFIED or SCOPED_PEER_V2_REVOCATION_KERNEL_VERIFIED | Historical verified terminal proof, not fresh live packet proof. CONFIRMED clears operation_id and retains last_verified_operation_id; REVOKED retains both pointing to verified revoke. Not an orphan solely because retained references exist. |
| UNKNOWN + complete published Root policy and independent current proof | Existing authenticated operation_recover inspect/reconcile on exact original; SCOPED_PEER_COMPLETED_NO_REPLAY / SCOPED_PEER_V2_COMPLETED_UNKNOWN_NO_REPLAY, native_retried=false.
