## Raw native Incus terminal boundary and stage exclusions

The durable BoxWeave Operation records include the **original real Incus native Operation UUIDs** and the original Guest stdout/stderr + exit status, independently correlated with unchanged Guest files/Git and separate native CI verification. **A separately fetched Incus daemon-native terminal Operation JSON was NOT collected in this live L1 acceptance.** The presently exposed 16 L1 MCP Tools deliberately do not include a raw parent Incus operation getter; executing commands inside its child is *not* an authorized way to inspect the parent daemon. Native daemon completion records can expire; no attempt will invent or retroactively replay them. An **optional future raw record** may be obtained *read-only on L1 host* from an exact still-present native operation (e.g. `sudo incus operation show <native_uuid> --project user-1001`), or captured **during a fresh isolated S4/S5 fault-injection run** with an independent host-native watcher while the original operation remains available. Raw daemon JSON is **additional audit strength**, not a mandatory `S3_MINIMAL_PASS` criterion under the [approved minimal stage gate](phases/03_FILES_AGENT_LOOP.md). The independent raw native record omission must never be labeled PASS.
