# S3/S4/S5 work rebalance — minimal S3, integration-heavy S4, independent S5 (2026-11-15)

**Approved direction:** minimize S3 while leaving its three public File Tools safe; move cross-layer runtime integration to S4 and comprehensive adversarial/Release quality to S5. This is a stage **ownership / exit-contract change**, not a reduction of BoxWeave v1's eventual product promises, an S3 PASS, a new Tool, a release, or authorization for more physical host changes. Work is committed solely to existing [S3 Draft PR #152](https://github.com/vanishs/boxweave/pull/152); merge its final *implemented* candidate to protected v1 only after the actual S3 limited exit and required CI.

## Precise scoped stage exits

**S3_MINIMAL_PASS** requires: all 3 File Tool schemas registered in a real installed official MCP client; read/list paged and owned; O_EXCL create single winner; replace/delete correctly deny UNSUPPORTED; viewer cannot mutate, unauthorized/foreign/traversal/symlink/hardlink/special file attempts do not change native bytes; bounded read and partial-file response honest; durable file mutation original ID and no uncertain replay; one **single Agent supervised** real guest Git failing→fix→passing test with independent Box/source/file postread; exact candidate Go quality plus affected S1/S2/S2.5 regressions and **one** independent native verifier. S3 uses only an approved disposable Box, no physical host daemon upgrades. Legacy RC6 and original UNKNOWN unmodified. Explicitly not signed: #148, #151, X-02/X-03 deep fault injection, full TC-015/016, network/host globals, Release.

**S4_INTEGRATION_PASS** requires: prior S3 File Tools still work; #148 proven stable same-grant at-most-once **before unattended/new network-changing mutations**; X-02/X-03 coherent original native Create/Delete record/tombstone across failure; four native network tools and dependent cleanup; native ACL/anti-spoof and supported L1/L2 topologies; truthful BH019 AppArmor/BPF/UID+GID support/UNSUPPORTED decision with real safety negatives; actual installed native and partial fault evidence. S4 ordinary restart safety smoke remains mandatory, but #151's long-run classification and full independent fault soak remain S5. An unsafe core behavior observed in S4 is an immediate S4 blocker, regardless of scheduled S5 work.

**S5_RELEASE_PASS** separately requires: #151 genuinely classified and repaired or explicitly blocked (never waived from publication), final TC-015/016 + TC-019/020, complete supported File apply mode truthfulness, 20/20 Tools/CLI, kernel/network/IPv6/full BH and original failure negative claims, real target/independent Verifier and exact source/install/release provenance. If a mandatory outcome stays UNKNOWN, keep S5 BLOCKED and continue independent tests; do not publish merely because S3 and S4 scoped exits succeeded.

## Minimal S3-to-S4 handoff artifact

One concise append-only row per accepted S3 Tool/negative/Agent smoke: source SHA + installed binary SHA, Box project/name/**UUID**, Incus version, role/actor **redacted**, Tool + mode + bounded input class, original BW/native operation IDs, observed Guest exit/output hash/bytes (no secrets), expected and observed native poststate, PASS/FAIL/UNSUPPORTED, evidence link. This is a test report, **not a new Tool, controller API, DB table or generalized framework**. S4 reuses it for forward/peer/actor/refusal; S5 extends it to independent full coverage. Do not require big new test harnesses in S3.

## Specific supported use before late gates

S3 may be used **supervised** with one trusted credential/grant and controlled single-shot workflow only. Do not allow unattended OAuth-token-refresh automatic native retries, second-Agent checkpoint claiming, or automated recovery of historical UNKNOWN. User-visible errors must distinguish UNKNOWN/pending from a confirmed guest exit/failure. The restricted S2.5 early-dev acceptance remains what it was, not a S3/S4/S5 signature.
