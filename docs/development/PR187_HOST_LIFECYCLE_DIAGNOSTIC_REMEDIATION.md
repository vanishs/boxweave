# Issue #187: host lifecycle, diagnosis/recovery and MCP responsibility remediation

Status: **analysis and proposed implementation contract; no runtime changes or new acceptance yet**. Owner direction, 2026-11-24: install/uninstall owns the entire BoxWeave installation lifecycle including owned Boxes, network effects and services; local CLI diagnoses and repairs BoxWeave itself; MCP owns routine user operations without Host intervention except actual BoxWeave faults. ## 2. Product boundaries and target UX

| Surface | Responsible | Not responsible |
| --- | --- | --- |
| install.sh | Trusted release selection, dependency checks, scoped bootstrap, owned native prep, units, DB, activation, verification, optional OAuth initialization/resume, actionable phase failure | Routine Box operations; installing/reinitializing shared Incus or creating external tunnels without separate product/owner approval |
| uninstall.sh | Own complete retirement, including normal owned dependency cleanup and safe offline retirement when recovery is impossible; exact native preimage, services, credentials, DB, journals and reviewed historical data | Deleting foreign Incus resources; requiring a functioning MCP client or per-Box manual cleanup |
| doctor / recover | Read-only diagnosis and reviewed repairs to existing installation and original durable operations; detect blockers, restore supported BoxWeave functionality, route to lifecycle coordinator when appropriate | Arbitrary root shell, arbitrary SQL writes, new business operations or a second uninstaller |
| MCP | Authenticated owned Box/exec/file/Peer/Forward lifecycle, readiness, durable original inspect/reconcile, routine internally authorized maintenance | Host provisioning, arbitrary host filesystem/commands, manual root approvals for ordinary scoped operations, unrestricted repair |

Preferred operator UX: one read-only plan and one guided approval/execution for a complete install or full uninstall; command names/options to be settled in implementation using current compatible entrypoints. Full uninstall must offer clearly reviewed retention versus permanent deletion, including exact historical archives; the complete erase option should orchestrate purge after retirement verification without a third mandatory manual phase. Keep safe resume of the same original for interruptions. Shared preexisting Incus/account/project/pool/bridge/images/tunnel are retained unless exact exclusive creation ownership and explicit deletion approval exist. Restore prior Project/Profile/bridge metadata rather than reset the host. "All BoxWeave things" means the exact proven owned set, not all names with a prefix. Neither install nor uninstall depends on external OAuth/MCP availability.

Internal Root privilege is acceptable for fixed, narrowly scoped service actions performed automatically through the existing verified helper; user-facing Host intervention is not. Do not expose the Root socket or general Host action via MCP. Keep 23 public tools and two local diagnostic entries. Existing scoped mode is primary; historical RC13 retirement support is a bounded incident-specific compatibility requirement, not legacy runtime migration or adoption.

## 3. Implementation phases and gates

### H1 — ownership inventory and lifecycle coordinator

Build a shared typed inventory/diagnosis model from exact manifest, trusted build identity, durable ledger, exact native UUID/incarnation, Root journals, service/unit/socket identities, preimages, ACL/proxy/guard references, and archives. List all blockers with evidence coverage, not first exception only. Separate normal cleanup, reviewable offline retirement, and hard ownership/foreign-resource refusal. Read-only plan must not start services, modify SQLite, stop Boxes, or install dependencies. Bind exact candidate, host, project, complete set of approved effects, retention choice and digest. Recheck after acquiring maintenance fence; drift must refuse before irreversible effect or leave resumable receipt if already started.

H1 acceptance: actual RC13 and RC14 artifact fixtures plus current candidate, nonroot refusal, unreadable/foreign/mixed or symlink/hardlink/mount drift, missing preimage, pending create identity ambiguity, stale approval, parallel writers, foreign ACL consumer, unrelated project present; verify no effects on refusal. Do not replace the installed old binary just to get a new retirement reader; support an explicitly verified matching-schema offline reader if needed, otherwise fail with precise reason.

### H2 — full uninstall and purge (highest priority)

Reuse existing normal retirement, scoped native retirement, exact unlink and archive/resume primitives. Normal path: coordinator internally orchestrates confirmed owned Peer/Forward cleanup, stop/delete exact owned Box set and then remove native effects. No dependence on caller running MCP. Keep service available only for bounded authorized cleanup until admission is fenced; prevent new operations and prove all writers/native operations are quiescent before offline effects.

Separate explicitly destructive offline full-retirement branch for proven owned inventory even with protected UNKNOWN or failed controller. This is a proposed narrow exception to ordinary UNKNOWN workflow requiring its own reviewed contract, NOT an unlock, retry, recovery success, or generic force flag. Prove scope/identity including possible partial creates; preserve original ledger/journals/receipt before any destructive step. If identity or native effect cannot be safely attributed/contained, refuse. Fence controller/helpers/admissions, drain native work; remove only exact owned instances and proxies, verify absence independently. Legacy: verify exclusive ACL consumers and allowed managed delta before restore of recorded baseline; retire exact completed/stale helper. Scoped: preserve fail-closed guard until native consumers/policy cleanup verified, then use existing preimage/guard detach sequence without restarting unrelated services or widening access. Handle remaining network references/leases/conntrack only by scoped supported proof, never host-global flush. Record original UNKNOWN as unresolved historical fact in a distinct retirement receipt; do not fabricate terminal business results. Verify empty owned inventory, exact native restoration, no owned listeners/services/guard/ACLs, audit archive consistency; then optional approved irreversible erasure of exact current and historical archives. If proof unavailable, keep evidence and return explicit blocker. Maintain durable phase checkpoints and idempotent resume. Do not erase STARTED evidence to make fresh install pass.

H2 acceptance: reproduce #187's legacy failed preflight and 11-owned-instance pattern (a smaller fixture may test logic, full original shape in isolated native lab); test legacy completed helper with active grants and UNKNOWN, scoped live Boxes with Peer and Forward, scoped pending and lost ACK, broken controller, interrupted each stage including purge, archive provenance, unauthorized/foreign consumer, rollback drift, independent postflight and immediate fresh RC14/current candidate install. Verify preserved unrelated Box process/connectivity and shared bridge/pool/Incus. No hand-edited SQL, no manual rm of live evidence, no stock PASS inferred from historical manual teardown.

### H3 — installer and two-command diagnostic UX

Installer: normalize one trailing slash only for otherwise valid HTTPS origin, keep strict rejection of userinfo/path/query/fragment/ambiguous domains, share validator or exact compatible contract, allow re-entry/defer with precise safe cause. Preserve successfully set password; never log passwords or tokens. Provide explicit controller-vs-OAuth status and targeted continuation, not reinstall. Default fresh scoped selection may be simplified only after compatibility/upgrade policy review; no automatic adoption. Reuse verified prerequisite and phase markers.

Doctor: root auto-derives installed scope when safe, one concise human-readable summary plus stable machine JSON (preserve compatibility), observed versus unavailable, exact next action and authority, distinction between healthy/degraded/unverified/blocked. Include installation/uninstall/purge readiness, service identity, root helper readiness and stale original, journal and ledger claims, native ownership/forward/guard/address capacity, active vs retained, known failure phase and proof gaps. Read-only doctor must work in safely supported partial install/failed-service cases without daemon activation. Fix IPv4 prefix discrepancy and distinguish expected nonroot coverage and deferred retirement from faults. Rate-limit repeated same-cause logs while preserving first occurrence, changed cause and counts. Root vs nonroot, actual running Forward policy, missing dependencies, malformed metadata, partial uninstall and credential privacy tests.

Recover: one guided review/apply experience (retain existing plan/apply machine API), stable original IDs and fresh digest, explicit local authority, atomic recheck, idempotent receipts, independent postcheck; never redispatch UNKNOWN. Separate pre-effect review refusal from lost/uncertain effect in future writes, record durable dispatch barrier and typed redacted stage evidence. Review/transport failure alone or missing journal alone is insufficient no-effect proof. Existing RC13 originals may remain unprovable; require independent authoritative native/kernel and original-stage proof or route to H2 offline retirement. Prioritize service/helper restoration only when exact installed contract and no unsafe effect can be established; if unsupported return actionable BLOCKED. Do not promise all faults automatically repairable. Test helper readiness timing, review drift, pre-effect refusal vs lost effect ACK, transaction races, stale approvals, unsupported proofs, repeated keys, interrupted repair, mode mismatch. Preserve #177 tests and known repair coverage.

### H4 — MCP contract and network capacity

No additional MCP tools initially. Audit all 23 descriptions, runtime results, attention, error codes and next_action against scoped vs legacy. In particular box_delete legacy-approval wording, box_peer_set, operation_get/recover, host_status and activity issue navigation. Prefer safe routine reconcile in MCP when evidence/authority already sufficient. Expose actionable redacted distinctions (normal wait, caller input, address/direction/history capacity, resource busy, actual controller/native fault, needs local repair), exact original IDs, and the local Doctor/Recover escalation only for real unresolved faults. Keep AUTHORIZATION/FOREIGN failures non-enumerating and never expose credentials, raw host paths or cross-tenant logs. Test existing clients and no new tools, duplicate/lost ACK, no Host action in ordinary scoped workflow.

Capacity is an explicit product decision, not a license to recycle addresses or erase history. Current /24 may exhaust after 253 cumulative distinct allocated IPv4 identities (depending on other reservations); 1024 logical live-Box bound, 8192 retired identities, 32 retained directions including revoked and 8192 root history are separate limits. Report active vs held and remaining upper bounds, advance warning and precise safe admission refusal consistently in Doctor and MCP; expose direction/history limitations before failure. Fresh install should show actual capacity before approval and offer documented approved exclusive sizing when supported, never silently resize an existing bridge. Evaluate a separate safe scoped identity/address/direction/history reclamation design: independent absence, incarnation/lease/guard/ACL/conntrack proof, replay/fencing invariants, crash recovery and unrelated traffic witness; normal safe reclamation should be automatic internally, not require per-Box Host operations. Implementation only after proof and owner decision on reuse/compaction policy; if not feasible, document real churn limit and separate follow-up, not pretend capacity fixed by warnings or a larger CIDR. No global resets or weakening isolation.

H4 acceptance: 4-Box physical pattern in isolated installed candidate, default deny/IPv4+IPv6 grant/revoke, continuous unrelated TCP flow and no unrelated restart/NIC/autostart change, explicit false preserved, Forward real loopback and cleanup, stop/start/delete, authenticated normal recovery and denied foreign access; churn and limit-boundary synthetic/real evidence distinguished. External Forward/quota and physical 1024 guests are separate scope gates, not inferred from this smoke.
