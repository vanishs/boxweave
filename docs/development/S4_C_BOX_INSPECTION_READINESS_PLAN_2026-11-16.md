## 1. `box_get(detail)`: exact contract

Implementation decision (2026-11-20): require the single-request `instance_get_full` Incus extension; refuse unsupported SDK name-based multi-read fallback rather than mixing observations across incarnations. Preserve native nullable JSON fields, opt-in detail and collection timestamp. Do not claim atomic snapshot or release readiness.

- Add an **optional boolean** `detail` default `false`. Short Agent-facing schema description: **"Set true to include runtime State, Snapshots, and Backups; otherwise return basic instance information."**
- `detail=false`: **preserve existing behavior/output** (`tracking_id`, verified `BoxState`, and S4-B confirmed peer/forward-related fields where applicable). Continue current `GetExactBox`/native `GetInstance` observation. No raw configuration dump, extra state calls, Guest Exec, waits or other effects. `box_list` remains lightweight and unchanged.
- `detail=true`: obtain `GetInstanceFull` **only after resolving the authorized SQLite-owned Box and scoped Incus Project**. Re-verify `volatile.uuid` equals the **requested exact owned UUID** and Project; reject foreign name reuse and changed incarnation. Include the existing normalized Box view **and a separately named `instance_full` field containing native `InstanceFull`**, including the full `Instance`, `State`, `Snapshots`, `Backups`; do not silently trim native fields while calling the result full. Preserve `guest_ready` as the actual Incus guest-declared signal, not an inferred flag from `Running`.
- **Authorization after the 2026-11-18 owner change:** `admin/viewer` roles no longer exist. `detail=true` is available to an **explicitly approved, live full-management Actor**, just like ordinary owned-Box operations; it remains opt-in and must recheck the actual Token ID and exact Project/UUID/incarnation before returning. Native `InstanceFull` can reveal `raw.lxc`, `cloud-init.user-data`, `ExpandedConfig` and secrets not necessarily readable via Guest-root Exec. Do not silently restore a viewer/admin split, relabel an unredacted response as harmless, or leak these values to audit logs, Tracking IDs, diagnostics or public test evidence. If a future product requires restricted secret disclosure, that is a new Owner decision, not a hidden compatibility role.
- Treat `State==nil`, absent IP/OS info, zero/unsupported timers, failed or unavailable Incus extensions **honestly**: no fabricated network readiness/0-use metrics; stopped Box can still have valid `Instance` metadata. Return a collection-time `observed_at` for the detailed observation. The native full view is **one observation, not an atomic/guaranteed-live snapshot**.
- Do not automatically substitute an extra `GetInstance` request **after** an expensive full read unless required for exact UUID/revalidation; minimize redundant queries but favor identity correctness. If a Box is replaced/stopped between lookups, do not combine mismatched observations.
- Inspect native API cost, response size and sensitive fields with a normal Box and one with many snapshots/large cloud-init. The performance/identity/error results decide whether additional conservative request/size caps are necessary; no arbitrary truncation labeled `full`.

## 2. `box_wait_ready`: an asynchronous, bounded verification Tool

Current source (2026-11-20): existing operations/events, OBSERVING and TIMED_OUT; no Schema5 DDL change. Waiting does not block ordinary mutation; short final verification/Exec uses existing dispatch fences. At most one fixed no-recorded-output native probe, verified nonzero exit FAILED, interrupted observation before probe FAILED, possibly dispatched probe UNKNOWN. Initialized unsupported and not advertised. See implementation checkpoint for acceptance limits. Heavy metadata stress deferred to S5.

Purpose: allow an Agent to wait for **specified observed conditions**, rather than repeatedly guessing readiness from native `Running` or an assigned IP. **Do not call it native Incus `guest_ready`**: that existing nullable field means Guest explicitly reported Incus Ready, and remains separate.

**Proposed typed input** (freeze after native/schema verification):

```json
{
  "box_id": "<exact owned UUID>",
  "idempotency_key": "<client-reusable key>",
  "checks": ["running", "exec", "ipv4"],
  "timeout_seconds": 600
}
```

- Defaults: `checks=["running","exec"]`; `timeout_seconds=300`, maximum **600**, bounded minimum as chosen by schema tests. Optional checks: `ipv4`, `ipv6`; explicit Guest initialization (`initialized`, e.g. cloud-init on confirmed supported images) is **conditional/opt-in** and may return `UNSUPPORTED` until native Guest tests prove reliable semantics. Do not require Internet access when `internet=false`; checking an IP does not establish DNS or external connectivity.
- Require a **live authenticated full-management Actor**: the `exec` check invokes a native Guest Exec and may never use an anonymous/revoked Token. No caller-provided argv, shell, script, URL, arbitrary host/native API or network target. Use a short, fixed, low-impact executable probe (e.g. `/bin/true` only if present/supported), enforce one outstanding probe/Box, fixed resource/time limits, no persistent stdout/stderr secrets.
- `running`: `GetInstance`/exact UUID/project/incarnation and native status. `exec`: `ExecInstance` on that exact running Guest, **only** mark `exec_ready=true` upon independently observed successful native Exec terminal **and guest exit code 0**; launching an Operation, `Processes>0`, or an arbitrary prior `box_exec` success does not suffice. Missing/nonzero exit stays `not_ready` or `unknown` by actual evidence. Do not silently use Guest agent; the official SDK uses the native Incus exec path.
- `ipv4`/`ipv6`: `GetInstanceState`, only the **expected verified owned NIC** and actual addresses of family `inet`/`inet6` and `scope=global` (not loopback/link-local). Linux scope `global` **does not mean public internet reachability**. Honor S4-B verified anti-spoof/ACL/address quarantine; an IP with unsafe/stale binding is not an accepted readiness proof.
- Sample results in the **existing `operation_get`**: original `operation_id`, `state`, exact `box_id`/incarnation, requested checks, `running`, `exec_ready`, `ipv4_assigned`, `ipv6_assigned`, `checked_at`, start/deadline, last safe error class and an explicit `ready=true` only when **every requested check passed for the same current Box identity**. An unrequested check is `not_checked`, not successful.
- Return an asynchronous durable receipt immediately, **never block HTTP/MCP for 10 minutes**. Continue after caller disconnect; users query using existing bounded `operation_get(wait_ms<=20000)`. No new `box_wait_status` Tool, second controller/DB, generic Agent scheduler or long-held native transaction. A wait is an **observation job**, not a Box native mutation; **do not reuse the current mutation Worker requirement for an invented native Operation ID**. Extend its typed Store/operation view as necessary while keeping original mutation journal semantics unchanged.
- The fixed Exec check **does create a native Incus Exec operation**. Keep original native ID and observed guest terminal evidence; do not fabricate an ID or blindly redispatch if a dispatch/ACK result is ambiguous. Repeated unambiguous `not_ready` observations may trigger a later distinct bounded probe; uncertain native dispatch remains `UNKNOWN` for that attempt until established otherwise. Persist the observation deadline; on restart either safely re-read/re-evaluate the same owned identity or surface a truthful interrupted/unknown state, never manufacture `READY`.
- No ten-minute exclusive lock on ordinary Box reads/mutations. Concurrent Stop/Delete/replace must invalidate the wait by exact UUID/incarnation. Check the same identity immediately before claiming `READY`; do not report a former container's successful probe as readiness of a replacement. Rate-limit active waiting and polling; protect against admission flood.
- Terminal taxonomy: `SUCCEEDED` **only** if requested checks are verified; `TIMED_OUT`/`FAILED` on proven deadline/terminal stopped or unsupported conditions as appropriate; `UNKNOWN` for ambiguous native work/evidence, never conflated with a slow boot. Support same actor/key/intent replay without creating another wait or Guest probe, conflicting intent refused.
