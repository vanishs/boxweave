## 2. D1: observation architecture and consistency

### 2.1 SQLite alternatives, concrete limits

Existing D0 proved cold mode=ro creates WAL/SHM, immutable=1 can miss live WAL. The extension proved:
- With a deliberately stationary open writer (auto-checkpoint disabled), copy main DB and WAL to private temp directory, omit SHM, then open private copy using existing RO reader: committed marker visible. Source inventory and byte contents of DB, WAL and SHM unchanged. Copying main only missed a committed row; in first run even table was absent. Never infer missing schema/records from incomplete file copy.
- Actual concurrent transaction test: initial RO transaction sees count 0; independent writer commits marker while read transaction stays open; same transaction sees 0, new read sees 1. One SQL transaction is an epoch, not the entire Doctor scan; do not compare changing data from different epochs as if atomic.
- This is a feasibility witness for an independently stable capture ONLY. No safe live filesystem copy algorithm proven; before/after hashes alone are not proof against transient changes or ABA; no copying live DB in arbitrary sequence, no immutable against potentially live files, no DB checkpoint or service stop to make Doctor work.
- Preferred D1 design: an observation interface separating running service and stopped/unavailable service. If running service can provide a bounded existing SQLite read transaction, reuse that safe path; do not add public privileged MCP endpoint just to get it. If standalone RO access requires shared-memory activity, explicitly assess and test no source-side-effect contract rather than falsely promise it. For offline use independently proven coherent stationary DB+WAL capture and private rebuild, or mark incomplete if cannot establish proof. Existing constraints require no new source sidecars or business changes. Temporary private snapshot must have restrictive mode, bounded size/time, no secrets in report, no export, and reliable cleanup. Do not call state.Open, init or backup/write helpers on source. Cold immutable only on verified private snapshot or independently immutable checkpointed source with no unaccounted WAL.
- D1 must cover nonroot read authority, source parent+inode ownership and no symlink/hardlink/swap (existing OpenNetworkAuditReadOnly closes initial fd then SQLite reopens path), WAL/SHM ownership/identity, path and permissions races, concurrent writer/checkpoint/restart, unavailable/corrupt DB, invalid schema, bounds/cancellation. These remain implementation gates; D0 proves constraints, not final strategy.

### 2.2 Authority and architecture

Use typed observation providers: host-local root reads fixed manifest/unit/journal metadata and approved native proof only; restricted service actor reads exact Project ledger/native; running daemon effective identity/config; optional workload observation. Do not execute arbitrary root shell or transfer authority to public MCP. The real N2 root vs service status experiment proves private Root evidence is inaccessible to restricted actor; current cmd/boxweave/recover.go recoverLocal calls install.Status before credential drop and performRecovery calls install.Status again under restricted worker, but internal/install/local.go Status invokes verifyScopedInstalled, which uses Root-only fresh journal/quarantine proofs. Even wiring ScopedPeerWitness into CLI alone does not fix this boundary. D1 split host proof from restricted observation; D3/D4 design a typed, bounded, root-authenticated handoff and revalidation at the privileged boundary, never trust caller-supplied JSON as root authority. No weakening journal 0700, broadening groups, or running restricted Native.Reader as root. Preserve legacy worker and existing local root approval.

Actual mode = manifest scoped_peer_mode + installed binary digest/build + effective daemon executable/arguments, exact scoped journal and guard/lifecycle unit provenance + correct restricted Project. A stopped service lacks live argv; report provenance and coverage, not automatically legacy. Mode disagreement or unreadable proof blocks mode-specific repair. Root evidence absent and Root evidence unavailable are different. Version-specific dependencies: current #178 controller Wants/After helper; old experimental builds Requires/After; Incus guard is required. Don't diagnose old deployment against uninstalled newer source. No secrets or raw environ/argv/logs in report.

### 2.3 Report and evidence contract recommendation

Separate stable IssueID (versioned domain+issue code+scope+immutable resource/original; canonical structured encoding, no timestamps or secrets), observation epoch/as-of/coverage, and review digest (fresh exact evidence, issue, scope, original revision, intended leaf, authority and effects). Stable ID is not proof of continued problem. Review digest is not permission. Never use user-provided file paths or resource strings as shell. Deduplicate observations only when exact identity and evidence agree; multiple symptoms can share an original without collapsing independent faults. Classify CONFIRMED, NORMAL, HISTORICAL, UNVERIFIED/IN_PROGRESS, NOT_APPLICABLE; severity and repairability separate. Retain compatible basic doctor/status JSON/exit contract; full report has its own explicit version and coverage. In D1 choose/verify exact CLI and exit behavior against existing scripts before changing defaults.

## 3. D2: verified false positives, incomplete classifications and coverage

### 3.1 Scoped retirement false positive (reproduced)

Valid scoped retired fixture from real state finalization APIs: two owned and one retired; all retired IPv4, IPv6 and MAC are held in ReadCreateAddressHolds. ReadIPv4RetirementStatus reports pending=1 because SQL counts DELETED + RELEASED binding without distinguishing scoped Create/Delete lineage. control.Service.Status adds RETIREMENT_HELPER_NOT_CONFIGURED if pending>0 and legacy helper socket absent. In scoped fresh, missing legacy retirement helper is expected; "pending retirement" is not a requested repair. D2 fix producer/read routing by proven mode, not hide a real orphan. Keep true legacy pending/compaction status. Scoped report separately tracks intentional retained identities and held addresses, and independent actual pool upper bound; no compaction/reset. Generic native ledger's healthy retired fixture already has zero orphans (original D0). Do not replace that correct behavior.

### 3.2 Scoped Peer navigation and cause classification (reproduced)

A staged scoped UNKNOWN (grant or revoke) reports Activity PROJECT_PEER_BARRIER / HOST_REVIEW_REQUIRED, while recovery navigation reports INSPECT_REQUIRED / RETAINED. With a synthetic complete authenticated witness, actual CommitRecovery settles original without native dispatch. Thus HOST_REVIEW_REQUIRED is a conservative hint, not final proof that Host is necessary. Stage and root original proof still require Project quiescence; do not simply rename PROJECT_PEER_BARRIER to claim unrelated mutations are safe. Distinguish operation admission fence from native traffic disruption, and report five exact live claims vs retained historical claim rows.

control/operation_diagnostic.go diagnosticCause currently maps SCOPED_PEER_V2_HISTORY_CAPACITY, SCOPED_PEER_V2_PRE_DISPATCH_REFUSED, SCOPED_PEER_V2_ROOT_OUTCOME_UNVERIFIED and RECOVERY_BLOCKED to UNCLASSIFIED. D2 add shared classification, preserving specific raw safe reason and no inferred native effects. History capacity is predispatch known failure, generic predispatch refusal may be any safety check; Root outcome unknown may have native effects despite absent native operation ID. RECOVERY_BLOCKED belongs to separate attempt, not evidence original failed or was released. Activity history includes failed recovery receipts, bounded five-item sample, not complete problem inventory; link attempt to original using recovery_navigation. ReadActivity uses bounded signed cursor; do not repurpose private cursor secrets for report or treat across pages as atomic.

## 4. D3: evidence-bound repair plans

Current recovery.Service.Inspect reads original and observes; it returns view, not approval or full proof digest. CommitRecovery re-reads original inside write transaction, compares exact RecoveryTarget, revalidates scoped receipt and writes audit/receipt atomically. No API currently accepts an approved D3 review digest. Recovery idempotency binds layer/actor/key/original/stream/attribution, not a standalone full Doctor plan. Do not equate an issue ID, recovery key or output view with permission to execute a stale plan.

D3 should implement a registry of typed repair leaves (not free-form shell): issue code, verified mode, exact resources and original, proof provider, privilege, effect, plan digest, revalidate function, existing executor reference, post-observation. Read-only plan must NOT call CommitRecovery, issue challenge, token issuance, uninstall apply or Root effect dispatch. Resolve current issue again; if gone, changed, incomplete, foreign or unsupported, report refusal/not-needed. Stable ID and review SHA distinct; include exact evidence revision and mode, original incarnation and actor scope, plan version/leaf, preconditions, bounded resources and postconditions. Do not expose raw private evidence. Bound time and state freshness; plan does not lock project or guarantee ability to apply. D4 re-observe and compare within actual effect boundary, not only CLI front end; if current legacy mechanism cannot accept/revalidate appropriate plan proof, route operator to existing reviewed path or block until adapter proven. MCP-first recommendation may point to existing operation_recover inspect then reconcile with new deliberate key; it is not a claim that old wire schema enforces D3 plan digest. No public schema expansion by default.

Scoped Root generic lifecycle socket accepts only original ID and branches DISPATCHING -> Peer apply, UNKNOWN -> read-only Peer recover, VERIFYING -> Create/Delete apply. New test recovery.Service.observe verifies ADMITTED/DISPATCHING/SUCCEEDED never call scoped witness; UNKNOWN requires RecoveryOnly, exact original/Project, COMPLETE_VERIFIED and four verified steps; partial/foreign/missing proof blocks. This is orchestration fixture, not socket race/native acceptance. Preserve current authenticated MCP recovery with exact UNKNOWN phase; new plan must use an explicitly read-only proof boundary, never expose generic Root dispatch as query. D3 must validate phase on Root side, not rely solely on caller-supplied state. Test malformed receipts and source proof digests, unavailable Root, phase changes, authorization denial, no source mutation.

Verified grant/revoke state-level experiments: blocked attempt commits separate FAILED receipt and original remains UNKNOWN. Same key replays BLOCKED even if new complete proof available; this is correct idempotency, not a fresh try. New distinct key only for a separately authorized logical recovery after fresh inspect, never automatic loop. Stale target revision, wrong proof digest and non-recovery receipt refuse without consuming key. Valid synthetic complete proof settles original, produces distinct SUCCEEDED recovery receipt without native ID, records RECOVERY_SETTLED audit, historical five claim rows remain but zero live claims. Same key returns same durable receipt. Preserve exact receipt after lost response and re-observe on new diagnostic request; replay marks NOT_REOBSERVED_REPLAY and cannot prove current health. Do not conflate FAILED recovery receipt with original terminal state. Test current authority at apply and replay; current scoped proof independently requires original credential still active.

Existing S5A2 tests also cover concurrent same/different keys, changed attribution/stream, transaction fault rollback and actor revocation; original #178 tests cover root partial journal/native non-replay, unrelated Forward traffic, guard continuity. Reuse, and add D4 plan-review-specific tests (changed proof before execution, wrong digest/leaf/identity, interruption, same-key outcome, independent fresh postcheck). No claim that D0 implements those adapters or native repaired state.
