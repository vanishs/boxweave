LAB and dedicated physical-host evidence are separate.

## Scope and security controls that cannot be waived

- **Networking:** prove before first start that owned NIC(s) are attached to an **installer-prepared exclusively-owned native ACL** (when required by the selected topology), default private ingress deny and egress policy, MAC/IPv4 and enabled IPv6 source anti-spoof or an independently verified safe disable of the *owned IPv6 path*. Verify actual packets/denial and absence of unauthorized sibling/host/foreign network access. Inner Incus uses an independently checked guest-local bridge/NAT when appropriate; never disable parent anti-spoof to make nesting work. This is a **minimal S2.5 safety prerequisite**, not completion of S4 peer/forward/Scriptlet. If a prerequisite actually depends on unfinished S4 work, move **only that necessary native implementation/negative proof** earlier under S2.5 with its original security standard, document the cross-phase dependency and **reaccept it in S4**; never substitute a global administrative Incus socket, ad-hoc host firewall or weakened bridge.
- **No early S4 promises:** no public/LAN forwarding, `box_peer_set`, dynamic ACL editor, host-global `authorization.client.tls-restricted=scriptlet` changes, S4 dependent-delete closure or 20/20 tools. These tests remain mandatory later. No new public MCP endpoint/tool beyond S1/S2; unimplemented catalog members are not advertised.
- **Authentication and real Agent usability:** real local Streamable HTTP MCP must initialize using the official SDK, authenticate `tools/list`/`host_status` and support a safe S2 Tool call. **HOST_GO additionally requires the actual intended development Agent/client** to complete its own end-to-end authorized Tool discovery, read and idempotency-keyed S2 write with native readback; a separate curl/test-token result is insufficient. If ChatGPT cannot use approved v1 Bearer authentication or the owner has not explicitly chosen a proven alternative Agent/client, mark **AGENT_PATH_BLOCKED / HOST_NO_GO** and do not claim that v1 replaced the old developer workflow. Operator-managed HTTPS `/mcp` may be tested with an approved client and require the newly owner-approved, independently tested **Go-native embedded OAuth** for ChatGPT when needed; never reuse legacy main's Flask OAuth/REST implementation, anonymous admin access or a public listener. Guest-local inner MCP remains loopback and inner tokens never appear in parent logs/stdout/argv.
- **Failure truth:** preserve original idempotency key, Tracking ID, BoxWeave Operation ID, native Incus Operation ID, UUID/incarnation, SQLite evidence and actual guest exit. Losing MCP reply, worker restart, token revocation, long wait or unavailable Cowsql **must not redispatch** a possible write. Verify early `host_status` vs business readiness, bounded read-only `operation_get(wait_ms)`, unknown/failed separation, no false success, and what a blocked Agent/client can or cannot recover.
- **Resource guard:** budget CPU/memory/actual disk/I/O/PSI and storage limits from measured host capacity, not the sum of guest quotas or absolute Box count. Start with **one L1 development Box and one L2 child**; do not run destructive fault or unbounded load experiments on the approved dedicated physical host. Stage those only in the disposable LAB. Apply load/IO-delay fault injection on a disposable host only; abort physical pilot on independently defined unsafe resource thresholds and report reasons.
- **Operations and rollback:** test failure of candidate v1 MCP/worker **without** depending on that same failed service to recover it. Keep independent host-local administrator status/CLI and prove a compatible rollback where available, or independently verifiable safe stop/fallback while preserving original S2 SQLite Operations/UNKNOWN and owned Boxes. Incompatible pre-release database or MCP interface changes may be made without migration shims, **but not by silently wiping possibly live Operations**. S2 is **not** obliged to migrate or downgrade disposable S1 lab databases; an incompatible old candidate must fail closed. S2.5 is an explicitly disposable **pre-release development** installation, not a supported customer data/ABI compatibility baseline. Record DDL/version/digest and original native receipts. On schema break, stop safely, reconcile all originals and require separate owner-approved cleanup/reprovision; do not automatically migrate, force a downgrade or wipe a live DB. Formal S5 release (or an independently approved retained-data contract) sets the future compatibility baseline. Verify there is no legacy `main` on the dedicated target and never force a native daemon restart.

**Optional protocol observation, not a new gate:** For the actual development Agent/client, record current negotiated MCP version and whether it advertises `io.modelcontextprotocol/tasks` (if observable without invasive instrumentation). See the [future Tasks adapter research](../../research/MCP_TASKS_EXTENSION_SEAM_2026-11-10.md). **BRIDGEHEAD must PASS or NO_GO using the existing S2 Operation receipts**; future Tasks support cannot substitute for a working actual Agent path, independent recovery evidence or a missing native result, and lack of Tasks support is **not** a failure of the currently agreed BH matrix.
