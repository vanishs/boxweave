# S2.5 — BRIDGEHEAD: controlled early development base acceptance

**English codename:** **BRIDGEHEAD** (a small, defensible forward development base). **Status: PLANNED / NOT_STARTED.** This is a **hard, evidence-based deployment checkpoint after accepted S2 and before S3**, not a sixth feature-building phase, permanent new product mode, lightweight release substitute or permission to modify today's physical host. **New public MCP tools: 0.** The five original feature phases S1–S5 and their exact acceptance standards remain intact.

**Why:** The older `main` controller is a potentially unreliable provider for the Boxes in which v1 itself is developed. A strictly scoped, independently accepted v1 L0 controller and nested development Box can reduce exposure to *old controller* failures, while recognizing that both controllers on the same native Incus/host storage still share that failure domain. [Incident evidence](../../research/LEGACY_MAIN_INCUS_MCP_INCIDENT_2026-11-10.md). Passing this checkpoint does **not** prove native Incus reliability or S4/S5 completion.

## Entry conditions and small reading set

1. **S2 independently accepted and merged**, including all **12 S2 tools** on the same known source/binary, full named [S2 acceptance cases](02_BOX_LIFECYCLE_OPERATIONS.md), secure guest networking preflight, durable admission, exact UUID/incarnation, async Exec/output, restart-safe UNKNOWN and negative auth. **S1 must remain accepted.** No “fast” incomplete lifecycle fork; no copy of `main` REST/MCP bridges.
2. Read only [this card](025_BRIDGEHEAD.md), [BRIDGEHEAD acceptance IDs](../../verification/BRIDGEHEAD_ACCEPTANCE.md), [current checkpoint](../EXECUTION_LOG.md#current-checkpoint), [nested requirements](../../design/NESTING.md) and [MCP loopback/proxy](../../design/MCP_BINDING.md). Fetch exact S1/S2/native/Incident evidence at the matching test, not the whole historical archive.
3. Establish the exact authorized physical-host context, live `main` footprint, foreign Projects/instances/ACLs, previous `UNKNOWN` tasks, Incus version/API extensions, storage pool/root mount/available capacity, real I/O pressure, native DB availability and recovery path **before any new Box or installation**. If native Incus is unavailable or storage/permissions cannot be independently trusted, stop; an alternate dedicated disposable native host/VM may be used to develop safely, but is **not** real-host PASS.

## Two deployments, two separate proofs

**A — isolated native rehearsal, mandatory before any host pilot.** On an independent, authorized disposable native Incus host/VM, install the **exact S2-accepted candidate bytes** through the existing S1 local installer (without needing a GitHub Release). Use no preexisting production Project. Run S1/S2 functional and negative matrix with native readbacks, deliberate service restart/crash, original dispatched/UNKNOWN preservation, security refusals and operator-only recovery. Verify that the candidate can be stopped and restored without native/foreign side effects. An independent Verifier must reproduce critical cases with the exact binary SHA. Label **LAB_PASS** only for this environment; never call it real-host installed PASS.

**B — controlled physical-host development pilot, explicitly authorized separately.** If and only if A passes and the owner authorizes that **specific host/Project/service/pool/ports**, install the pinned v1 candidate **side by side** on the physical host. Dedicated restricted OS user, Incus Project/namespace, SQLite dir, MCP port, token/key stores, native network/ACL and service name are required. Baseline and postflight every inherited/foreign resource and existing `main` behavior; never upgrade or restart shared Incus, seize old Boxes, modify old identities, switch default installer pointer, overwrite global TLS Scriptlet or redirect existing agents. If native daemon/DB/storage is already unstable, shared-resource isolation fails, or a host-global authorization/network change would be needed, **NO-GO**. A new independent physical host is preferable to pretending two controllers on one saturated host are isolated.

**L0→L1→L2 minimum owned development chain:** physical host **L0 v1** creates one owned, nesting-enabled **L1 development Box A** using the actual S2 MCP lifecycle and exact durable ID. Through authorized **guest Exec**, locally install independent Incus and the **same pinned v1 binary** inside A as **L1 controller**, with its own user/Project/SQLite/credentials/loopback HTTP MCP. An authorized, guest-local temporary MCP client initializes this L1 endpoint and, using the current L1 `box_create` and `operation_get`, creates and runs one owned **L2 child Box B**, executes a harmless workload, obtains output/exit/readback, stops and deletes it with native postverification, and retains the parent's Box A. The parent controller manages only A. **L2 here is a native managed child, not a claim of a complete v1 controller running at L2**; full recursive parity and network/forward/peer features remain S4/S5 acceptance.

## Scope and security controls that cannot be waived

- **Networking:** prove before first start that owned NIC(s) are attached to an **installer-prepared exclusively-owned native ACL** (when required by the selected topology), default private ingress deny and egress policy, MAC/IPv4 and enabled IPv6 source anti-spoof or an independently verified safe disable of the *owned IPv6 path*. Verify actual packets/denial and absence of unauthorized sibling/host/foreign network access. Inner Incus uses an independently checked guest-local bridge/NAT when appropriate; never disable parent anti-spoof to make nesting work. This is a **minimal S2.5 safety prerequisite**, not completion of S4 peer/forward/Scriptlet. If a prerequisite actually depends on unfinished S4 work, move **only that necessary native implementation/negative proof** earlier under S2.5 with its original security standard, document the cross-phase dependency and **reaccept it in S4**; never substitute a global administrative Incus socket, ad-hoc host firewall or weakened bridge.
- **No early S4 promises:** no public/LAN forwarding, `box_peer_set`, dynamic ACL editor, host-global `authorization.client.tls-restricted=scriptlet` changes, S4 dependent-delete closure or 20/20 tools. These tests remain mandatory later. No new public MCP endpoint/tool beyond S1/S2; unimplemented catalog members are not advertised.
- **Authentication:** real local Streamable HTTP MCP initialized using official SDK and authenticated `tools/list`/`host_status`/S2 calls. For external ChatGPT/Cloudflare, verify an independently configured trusted HTTPS `/mcp` connection *only when that client actually supports the approved v1 authentication*. **No legacy OAuth, anonymous admin access or public listener** to force early ChatGPT adoption. Guest-local inner MCP remains loopback and inner tokens never appear in parent logs/stdout/argv.
- **Failure truth:** preserve original idempotency key, Tracking ID, BoxWeave Operation ID, native Incus Operation ID, UUID/incarnation, SQLite evidence and actual guest exit. Losing MCP reply, worker restart, token revocation, long wait or unavailable Cowsql **must not redispatch** a possible write. Verify early `host_status` vs business readiness, bounded read-only `operation_get(wait_ms)`, unknown/failed separation, no false success, and what a blocked Agent/client can or cannot recover.
- **Resource guard:** budget CPU/memory/actual disk/I/O/PSI and storage limits from measured host capacity, not the sum of guest quotas or absolute Box count. Start with **one L1 development Box and one L2 child** in the pilot; no unbounded parallel creations or destructive load test on a shared physical host. Apply load/IO-delay fault injection on a disposable host only; abort physical pilot on independently defined unsafe resource thresholds and report reasons.
- **Operations and rollback:** test failure of candidate v1 MCP/worker **without** depending on that same failed service to recover it. Keep independent host-local administrator status/CLI and a proven rollback to previous v1 binary/config/SQLite-safe state or service stop, preserving owned Boxes and UNKNOWN records. Check legacy `main` service and all foreign state unchanged; do not destroy an unknown Box, wipe Incus DB or force shared daemon restart to “clean up”.

## Stronger mid-project acceptance contract

The authoritative [BH-001–BH-017 matrix](../../verification/BRIDGEHEAD_ACCEPTANCE.md) is **additional** to S1/S2, not an alternative to any S1–S5 A-/SDK-G case. Each MUST have actual scoped evidence (`I` installed MCP/CLI, `N` native Incus/kernel/packet and `V` independent native post-read/Verifier as specified), exact binary/source and host/layer identities, explicit negatives and cleanup/rollback. A single mandatory security, persistence, foreign-resource, nesting or rollback failure means **BRIDGEHEAD != PASS** and **no pilot promotion**.

- **LAB_PASS:** independent disposable host evidence all applicable lab cases satisfied, but physical-host pilot pending or forbidden; cannot call early host ready.
- **BRIDGEHEAD PASS / HOST_GO:** also proves explicit owner-scoped physical-host authorization, parallel v1/legacy noninterference, actual L0→L1→L2 chain, recovery/rollback, independent acceptance and safe workload envelope.
- **BLOCKED/NO_GO/UNKNOWN:** do not deploy or switch development dependency; retain original evidence and nonreplayed UNKNOWN. Continue independent **safe S3 implementation in existing disposable labs** if possible, but do not count BRIDGEHEAD as completed and do not reclassify full S4/S5 promises. Real-host pilot is *optional* and needs separate explicit authority at execution time; the authorization is **not** granted by approving this plan.

**Handoff to S3:** report exact `v1` candidate commit and binary SHA, S1/S2 acceptance matrix, BH-001–BH-017 and real native/host proof, project/ACL/bridge/storage inventory, tested guest kernel/Incus versions and L0/L1 identities, reliable operator fallback, cleanup and all unresolved native original IDs. Use BRIDGEHEAD for **development workflow only**, with further security/net changes through ordinary S4 acceptance; not a formal release or a stable production replacement.
