## Actually implemented (not just design)

1. `state.StagePeerGrant` stages **only `allow=true`** on a previously admitted canonical `box_peer_set` original. Checks admin credential and active Actor, correct Project/source/target UUID+Incarnation, exact ACL+two-Box durable resource claims, Project-wide sibling admission barrier, entire SQLite owned inventory/ETH0/IP/MAC and reserved IPv4+IPv6 lease fences, and pending/UNKNOWN peer conflicts. It persists exactly one `peer_grants(desired=1,status=PENDING,operation_id=original)`, with safe regrant only for the **same** previously REVOKED incarnation and identical IPs. A staged original stays ADMITTED; no ACL/nft SDK PUT, socket call, root access, guest resumption or false SUCCEEDED is performed.
2. `state.ReadPeerGrantSnapshot(project,bridge,acl,stagedOriginal)` produces a deterministic read-only allowlist of every already CONFIRMED direction plus *at most one* still-pending exact original, with full ledger checks. Unknown, unclaimed, stale/reused address, revoked token, unrelated active sibling, changed SQLite state and forged original are refused. Historical REVOKED rows are not grants. The root worker must STILL independently recheck host-native/SQLite/kernel identity.
3. `install.NativePeerACLFromGrantSnapshot` compiles the whole durable set into the existing B2 exact directional IPv4/IPv6 ingress+egress compiler, with strict canonical addresses and a 32-pair bound; it never emits broad CIDRs or writes an ACL. Earlier confirmed grant B→C is retained when staging A→B, regardless of SQL row order.
