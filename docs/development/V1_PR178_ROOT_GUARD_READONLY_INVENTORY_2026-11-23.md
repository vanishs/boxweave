**Status: TESTED PURE READ-ONLY VALIDATOR; NOT an installed Root collector, writer, network migration or MCP feature.**

This stage follows [the approved owner behavior](V1_PEER_MCP_AUTOSTART_NONDISRUPTIVE_OWNER_DECISION_2026-11-23.md) and the [separate Incus 7.6 kernel guard experiment](V1_PR178_SCOPED_KERNEL_GUARD_PROTOTYPE_2026-11-23.md). It addresses one dangerous assumption in per-Box ACL transitions: checking only A/B does not establish that an unrelated Box C/D or another Project did not share the native bridge or ACL.

## Code and exact acceptance

- `internal/install/network_peer_scoped_inventory.go`: `NativePeerGuardValidateScopedInventory(project, bridge, claims, allProjectNames, observed, rootNetworkUsedBy)`. Inputs are the fixed scoped ledger claims plus **independently root-SDK-read** complete Project instance names, each native Instance, its scoped ACL and ETag, and network-wide UsedBy. Output is only a slice of pinned `NativePeerGuardMember`, suitable for pure `NativePeerGuardFromSnapshot` compilation. **NO side effects, no root invocation, no MCP service.**
- Requires an exact safe `user-<uid>` Project and bridge; nonempty complete native lists and no duplicate IP/IPv6/MAC/UUID/name. Project inventory must have *exactly* the claimed Boxes, not simply contain A/B.
- Calls existing strict `native.ValidatePeerACLBox` for every native Instance: UUID, native Project and Box name, one default profile, bridge NIC, exact static IPv4 and IPv6 leases, exact MAC, anti-spoofing filters, default ingress reject and dedicated per-owner ACL. This validation is state-read only and allows the original `boot.autostart` choice; it does NOT silently change it.
- Derives the expected ACL name from Project+bridge+immutable UUID; rejects a foreign/wrong ACL, missing provider ETag, anything other than **one exact native Instance UsedBy**, including a second Box using that ACL or an ownership link with an extra URL query parameter. The target ACL itself must have the correct Project if provider supplies it.
- Parses each root network UsedBy URL and allows only the exact Project's **default profile** or individually owned Instances; denies any foreign Project, unrelated profile, added subresource, duplicate, absent inventory, malformed or unscoped URL. A target without network UsedBy provenance is refused rather than assumed safe.
- Native user-supplied strings, desired ACL policies, and root ETags **are not evidence of kernel enforcement**. This checker does not prove that a root client actually supplied its data, that the bridge has no out-of-band raw NIC/port or that an observed ACL matches the intended policy. The future privileged collector must establish these independently. The list must be repeated before each native effect and after every success/fault/ACK loss.
- **Separate tests** `internal/install/network_peer_scoped_inventory_test.go`: baseline two Boxes with explicit true and false autostart, no mutation, successful projection into the existing guard compiler. 20 named negative cases cover missing/foreign sibling, duplicate name, foreign profile/Project, omitted/forged UsedBy, wrong shared ACL consumer, stale ETag, ACL name/Project hijack, UUID/MAC/IPv4 pin drift, anti-spoof disabled and invalid profile/native status, plus SDK order independence. ## Correct integration order and failure semantics

1. Trusted local Host initial provisioning only: install a non-general-purpose bounded Root mediator. Read the protected original/actor/locks and complete native leased identity from SQLite. Obtain the root Incus Project, network and ACL readbacks from the admin socket; never accept MCP-supplied copies of these objects.
2. Verify cross-Project and raw-kernel bridge consumers (beyond Incus's UsedBy), then call this validator. Ensure exact ACL contents and ETag, root guard digest and nft kernel readback. Refuse missing/unknown data. The current helper is still pinned to one approved original and cannot be reused automatically.
3. Pin these facts to a durable original journal and per-affected-Box locks before **any** SDK/nft write. The non-disruptive guard candidate must remain installed across all A/B ACL fanout updates, and Root must independently confirm ingress/egress enforcement. On revoke, apply exact DROP plus exact dual-stack conntrack purge with final kernel proof. Do not stop C/D or mutate their boot flags; do not claim success from SDK readback alone.
4. Any incomplete bridge, missing guard, foreign consumer, ETag drift, uncertain kernel propagation, crash or lost-ACK must remain BLOCKED/UNKNOWN with explicit recovery. Do not auto-approve arbitrary requests; no generic shell, arbitrary ACL API or unauthorized cross-Project root rights.
5. Install/restart/reboot, full IPv6/UDP/Forward tests, concurrent grants, lease reuse, safety during guard table absence and original crash recovery remain **NOT_TESTED**. A/B/C/D manual network prototype is not a deployed candidate daemon. #177 Doctor remains frozen until verified #178 architecture is integrated.
