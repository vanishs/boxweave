# Owner decision: S4 flat-network-first, recursive nesting deferred — 2026-11-16 PT

**Effective for PR #153 from this checkpoint.** Supersedes earlier S4-C requirements to create L1/L2 inner Incus daemons or settle #150 recursive AppArmor/BPF delegation before completing unrelated S4 networking. Keep all historical failed experiments and original receipts unchanged. This is an execution-stage reallocation, **not** a declaration that unsupported recursive isolation is safe, a change in the number of public MCP Tools, or permission to publish a release.

## S4-B and S4-C: work in parallel sibling Boxes directly on L0

- Use the owner-approved existing **L0 BoxWeave RC7 / native Incus 7.6** as the primary exploratory platform. Create **new, identifiable, unprivileged, non-nested sibling test Boxes A/B/C** using authenticated BoxWeave MCP, read exact owned UUIDs/Incus identities, prove IPv4/IPv6 packet baseline, default ingress deny, egress and safe NIC configuration. Retain original L0 Boxes intact and account for existing resource reservations/UNKNOWN state. Stop/delete only the fresh test Boxes and independently re-read originals after each campaign.
- For actual shared-ACL GET/ETag/PUT, per-Box peer allow/revoke, native TCP/UDP proxy devices and fail-closed NIC reloads, **the current RC7 MCP exposes no such network mutation Tools**. Guest root and nesting do **not** confer permission to mutate L0 host Incus. Use previously verified independent native CI, new purpose-built *isolated/restricted* Incus SDK test harnesses and, when implemented, the four S4-B public Tools. Any daemon-global Scriptlet or bridge-wide ACL mutation on the shared L0 daemon requires a separate exact-host approval; this decision alone does not grant it.
- **S4-B2–B6** implement and accept owned shared ACL/identity/lease/anti-spoof, direction-specific `box_peer_set`, native TCP/UDP forwarding, dependent Delete, actual installed MCP and independent native packet/security evidence on the supported **flat L0 topology**. This network core remains security-critical: default deny, IPv4/IPv6/MAC spoof, ownership/foreign refusal, partial update/UNKNOWN and safe cleanup cannot be waived or moved out of feature acceptance merely because recursive Incus is deferred.
- **S4-C** performs scoped 20-tool integration and independent acceptance for the flat sibling Box topology and affected lifecycle/authorization; it may report nested features as unsupported/pending. Do not use successful `unconfined` inner daemon initialization as strong AppArmor delegation evidence. No mandatory L1→L2 inner daemon/recursive-bridge fixture to gate an otherwise safe S4 flat-network integration checkpoint.

## S5: separate #150 recursive capability track, no unsafe automatic promotion

- Move the deeper **inner Incus / AppArmor policy namespace/admin, cgroup-device BPF, descendant UID/GID mapping/quotas and L0→L1→L2+ recursive host security** investigation and acceptance to a **late S5 workstream**, after primary flat-network implementation. The exact owner can then choose to authorize a disposable dedicated host and deep tests or define a narrower honest supported product contract.
- The latest actual L0 RC7 native [retake](../verification/S4_B1_L0_RC7_RECURSION_RETEST_2026-11-16.md) showed: first L0 disposable `unconfined` Box initializes inner Incus, its `enforce` child reproduces AppArmor `exit 243`; guest-only `INCUS_SECURITY_APPARMOR=false` allows bridge init but deeper guest launch fails BPF EPERM and AppArmor label transition. These are blockers, **not workarounds or a released security claim**.
- S5 release must **either prove each capability advertised for recursive use with native negative tests, or obtain an explicit owner-approved scope/trust revision and corresponding docs/refusals/tests before release**. An unresolved mandatory advertised recursive feature leaves S5 release BLOCKED; a flat S4 scoped PASS must never be relabeled full v1 release readiness.

## Immediate experiment boundary

Begin with an L0 sibling A/B/C baseline and evidence for current RC7 default topology via BoxWeave MCP. Don't install Incus inside these guests, change the shared daemon's Scriptlet or ACL, access foreign resources, weaken AppArmor/BPF, or replay UNKNOWN operations. Advance ACL/peer/forward tests only once the necessary authorized narrow API exists. Capture actual IP, UUID, original BoxWeave/native Operation IDs, packet exit/output and cleanup receipts, preserving honest `NOT_TESTED` for unavailable native rights.
