## 3. Upstream source check (exact published commit)

- `internal/native/peer_acl_isolation.go`: `isolatePeerACL` validates *complete* owned bridge instance set, disables `boot.autostart` on **EVERY** consumer, stops **every** before ACL mutation, refuses drift; this is intentional global safety barrier.
- `internal/install/native_peer_root_grant_apply.go`: exact ACL PUT/conntrack/NFT proof under stopped barrier and safe resume; `nativePeerRootResumeGrantVerified` requires `boot.autostart=false` even after successful start. Do not simply undo this without changing formal safety proofs.
- `internal/install/native_peer_root_service.go`: one-original, one-SHA Host root service staged *inactive*; existing unit is exclusive and cannot be overwritten; lifecycle is not ordinary MCP work.
- `internal/control/forward_tools.go`: the `port_forward_list` Tool description **already says** `native_verified` verifies exact device, NOT packet/LAN reachability. The gap is incident presentation and actionable diagnosis, **not** that this boolean is wrong.
- `cmd/boxweave/main.go`, `internal/native/status.go`: `doctor` reuses process-local status, does not automatically import the daemon's policy.
- This report is from live Operations, not a new CI signoff. Do not accidentally treat original `box_exec` `SUCCEEDED` as Guest exit 0 without checking `diagnostic.guest_exit_code`.

## 4. Acceptance for #177 Agent

1. On a synthetic **`ADMITTED`** Peer original, report exact pending phase, lock fan-out and absent/helper-present trusted evidence; show that a cancel/recover cannot legally bypass Root approval. State should remain unchanged, absent database creation/WAL mutation.
2. When existing `boot.autostart=false` is observed, identify **barrier-owned** versus operator-owned configuration and the evidence boundary; no speculative restoration.
3. Forward device exists but Guest server process absent: `doctor` must not call it live/HTTP PASS. Guest-local check is a recommended separate probe, not implicit `doctor` write.
4. Real running service `all`, standalone CLI `disabled`: report sources separately, do not assert daemon broken; simulate inaccessible unit and mark `UNVERIFIED`.
5. Guest exit `124` / Operation `SUCCEEDED`: terminal record success vs guest command failure explicitly represented.
6. Anonymous MCP 401 vs authenticated MCP ready, external/loopback and L1-vs-L0 same port: correct scope distinction; no credential disclosure.
7. Active peer+forward packet success and unapproved third party denied are **retained RC13 evidence only**; #177 new code needs focused regression, not blanket re-execution of already passed physical Host tests.
8. Unsafe/uncertain Native/Root/SQLite: fail closed. New read-only Doctor must use a truly read-only DB connection (see existing #177 design), never write/initialize/repair or scan unrelated Projects.
