## Goal and boundaries

S4 delivers the complete **21-tool implementation** (the existing 16 plus **only** `port_forward_list`, `port_forward_create`, `port_forward_delete`, `box_peer_set`), verified on **supported isolated native environments** with safe authorization and resource lifecycle. S5 independently establishes final confidence and supports a first controlled v1 release. Moving expensive tests to S5 is **not permission to reduce an advertised safety property**. Mandatory unsafe/UNKNOWN S4 exposure or ownership fails S4, regardless of which stage owns a stress campaign. No new public tools, host root management API, generic ACL DSL, custom network proxy, patch engine or cross-layer controller orchestration.

## S4 required safety vs S5 full-environment evidence

S4-A cannot be marked PASS until #148's grant-refresh *post-SUCCEEDED replay* preserves original operation and exactly one Guest effect, while expired/revoked/foreign grants cannot borrow history or dispatch. X-02/X-03 must preserve native/SQLite coherence and UNKNOWN on genuinely uncertain results. Do not permit new peer/forward mutations or unattended automatic mutation until this early safety gate passes.

S4-B cannot be marked PASS if a source IP/MAC anti-spoof, IPv4/IPv6 isolation (when enabled), source-target UUID ownership, shared ACL default-deny, Scriptlet restricted-client compatibility, forwarded external bind or revoke leaves an unproven exposure. Scriptlet is **daemon-global**: first check old restricted clients and reconcile precise native ownership, require distinct explicit **host-local owner authorization**, and prove rollback on an authorized **disposable host**. An isolated functional green result is not authorization to mutate shared L0/L1 global settings. If the host policy switch cannot be proven safe, mark affected S4 feature BLOCKED and continue safe independent work.

S4-C requires the **21 public tool names and schemas** to be wired, real basic calls/permissions/negative paths for newly affected functions, bounded **L0 flat sibling A/B/C** network flow, actual native guest identity and core packet/cleanup/failure evidence, normal original receipt after restart. Recursive L1→L2 inner-daemon support is deferred to S5 rather than blocking this scoped checkpoint. Full 20-by-Tool-by-CLI exhaustive matrices and external physical-LAN/public-Internet IPv6 belong to S5. This moves only **environment-wide expensive witness coverage**, not mandatory S4 anti-spoof/default-deny functional safety checks.

The current RC7 nested lab needed **inner-only** `INCUS_SECURITY_APPARMOR=false` after a real AppArmor policy-admin denial while parent AA stayed enforced: that lab is **not** strong nested isolation proof. For #150, an early feasibility finding can establish `UNSUPPORTED` for hostile sibling/per-depth policy administration in the current kernel, but it cannot silently change the **final advertised trust model**. S5 must either prove strong properties for any advertised strong-security feature, or require an explicit product decision revising the promise. Do not weaken host AA, grant privileged/unconfined nesting or delegate parent Incus socket to “pass” tests.

## Native operation terminal observation: scope and proof

A BoxWeave durable `operation_get` record with `native_operation_id` and Guest `exit_code` is **not** the original Incus daemon terminal Operation object. Capture the native object *while the first fresh disposable operation is still retained* from an independently authorized native CLI or SDK witness. Save sanitized terminal status/class, original native UUID, project/Box UUID, timestamp, and compare to the **same original** BW operation journal, output and Guest marker exactly once. Do not persist credentials or raw sensitive stdout, and don't add a public Tool. A raw native object may have expired or never existed for synchronous SFTP; say `NOT_CAPTURED`/`EXPIRED`, **never** claim it was observed. This small pattern belongs in S4 so S5 #151 can reuse it; #151 historical uncertain original is not retroactively “fixed” by new tests.
