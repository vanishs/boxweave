# PR #178 — Scoped Peer v2 original and atomic SQLite staging (2026-11-23)

**STATUS: PACKAGE-LEVEL IMPLEMENTATION + DISPOSABLE SQLITE TESTS PASS. NOT AN INSTALLED MCP OR ROOT WORKER. Keep PR #178 Draft.**

This slice addresses the structural incompatibility documented in [per-Box SQLite ledger](V1_PR178_PER_BOX_SQLITE_LEDGER_DESIGN_2026-11-23.md): existing Peer originals require **one shared Project ACL** and use an ACL-global lock; native non-disruptive design requires **per-Box ACLs**, independent A/B updates and a separate bridge nft guard.

## Implementation and immutable boundaries

1. `internal/state/network_peer_scoped_original.go`: new **canonical v2** `ScopedPeerOriginalIntent` with schema 2, exact Project, bridge, source/target UUID and incarnation, and allow boolean. **No ACL/IP/MAC or network command supplied by MCP**; ACL names derive from separately owned `network_bindings` and `internal/peerscope`. The v2 projection lacks the old `acl` field, so legacy `ReadRootPeerGrant`, `ReadRootPeerRevocation` and old dispatcher cannot silently accept a v2 original.
2. `scopedPeerResourceClaims` requires **five exact resources**: `peer-guard:<bridge>`, both `acl:default/<per-box-ACL>`, and both `box:<uuid>`. `peer-guard:<bridge>` is intentionally the **primary internal ResourceKey**, while four supported ACL/Box keys are `ResourceKeys`. No public caller controls the set. Existing `Store.Admit` atomically retains the global Project peer barrier and a quarantined UNKNOWN continues blocking dependent operations.
3. `ReadRootScopedPeerOriginal` requires a **claimed DISPATCHING** original, exact canonical v2 intent and actor/token, active credential, complete per-Box Project inventory (every UUID/name/NIC/MAC/IPv4/IPv6/address fence), exact five resource claims, no conflicting in-flight sibling, and all historical/current `peer_grants` rows and incarnations. It derives deterministic **before/after active directions and revoke/drop tombstones**, preserving unrelated C/D grants. All checks are read-only in **one SQLite transaction**, with repeat inventory/original/credential checks before returning evidence. It has no native effect.
4. `ReadRootScopedPeerUnknownOriginal` explicitly permits **read-only recovery** of an exact UNKNOWN v2 original; it never authorizes native replay. Old shared-ACL grant/revoke readers refuse these originals, preserving v1 conservative security behavior.
5. `internal/state/network_scoped_audit_ledger.go` now exposes a package-private `readCompleteScopedNetworkAuditLedgerTx`, reused by both readers and stager under the **same transaction**. Old public read-only per-Box method still wraps its own transaction and passes all existing tests.
6. `internal/state/network_peer_scoped_stage.go`: **inert, internal** `StageScopedPeerOriginal` only. For an already-admitted, unclaimed v2 original, a single write transaction rechecks full project inventory, original actor/token/claims, all active/revoked rows, no UNKNOWN/PENDING sibling and no resource contamination. Atomically inserts a pending grant, marks a CONFIRMED exact grant pending revoke, or re-grants the same exact REVOKED incarnation. Repeated staging/foreign/partial ledger state refuses; no ACL, nft, conntrack or service restart occurs. A valid regrant records `SCOPED_PEER_V2_REGRANT_FROM_REVOKED` in the same transaction.
7. The new root proof distinguishes **`RevokedBefore` and `RevokedAfter`**: regrant carries the prior denied pair into the before-image, then clears it from the after-image; revoke adds an explicit A→B DROP tombstone to after-image. This prevents a future Root native compiler from assuming absence of a `REVOKED` row means the preexisting ACL must have no DROP. These are only evidence; actual Incus ACL/kernel readback remains required.
