# PR #178 — Per-Box ACL SQLite ledger groundwork, strict read-only v2 (2026-11-23)

**STATUS: TESTED READ-ONLY ALTERNATE LEDGER; NOT A WRITABLE MIGRATION, AUTOMATIC MCP ROOT ENGINE, OR FINISHED PRODUCT.** This corrects a structural mismatch identified during implementation: the current S4/B3/RC13 controller and Root worker assume **one shared ACL** in `network_bindings.acl` across every Project Box. The owner-approved [non-disruptive network target](V1_PEER_MCP_AUTOSTART_NONDISRUPTIVE_OWNER_DECISION_2026-11-23.md) instead requires a separate owned ACL per Box, protected by an independent nftables bridge guard.

## Root cause (DO NOT search/replace one native ACL command)

- Existing `state.ReadCompleteNetworkAuditLedger(ctx,project,bridge,acl)` rejects all owned Boxes unless **every** `network_bindings.acl == acl` and currently verified deleted/retired bindings refer to the same ACL.
- `state.ResolvePeerAuditScope` finds A and B by `network_bindings`, requires equal bridge **and ACL**, and reuses the above full-project shared-ACL snapshot. The existing `box_peer_set` route calls these exact methods.
- `ReadPeerGrantSnapshot`, `ReadPeerRevokedSnapshot`, `ReadRootPeerGrant`, `ReadRootPeerRevocation`, `nativePeerConntrackTargetFromStore`, `nativePeerBridgeAuditFromStoreWithClient` and the current Root helper all project that same shared-ACL identity and associated `acl:default/<acl>` resource locks. A per-Box ACL migration without adjusting these durable invariants would cause **false BLOCKED/UNKNOWN, or tempt a dangerous bypass of global provenance validation**.
- The current native Create/StageCreateBinding similarly persists one `VerifiedCreateBinding.ACL` and reserves it as part of the static binding. Existing data, pending grants/revokes, history/retirement and idempotent source ledger all need a formally reviewed, **atomic** migration and recovery strategy. Do NOT mutate historical rows behind the current worker.

## Implementation slice

- `internal/peerscope/name.go` and `name_test.go`: one deterministic, canonical Project+bridge+UUID hash-derived ACL name function, used by both `state` and `install`. This refactors `NativePeerScopedACLName` to reuse the same library rather than copy naming rules. It is a pure identity name **not ownership or permission evidence**; exact Incus ACL UsedBy and Root kernel verification remain separate.
- `internal/state/network_scoped_audit_ledger.go`: `ReadCompleteScopedNetworkAuditLedger(ctx, project,bridge)` is a *new*, strictly read-only, transaction-consistent SQLite view. It demands a nonempty complete owned Project, at most `networklimits.MaxProjectBoxes`, canonical UUID/Incarnation/unique native MAC/IPv4/IPv6, exactly one `PINNED eth0` per Box with **its own deterministic scoped ACL**, matching exact bridge, complete dual-stack RESERVED address fences, no foreign active bridge binding or foreign/stale/released address fence, and no unreviewed history in `network_ipv4_retirements`. Orders results deterministically by Box UUID. Unknown/deleted/retired historical records **fail closed** until a separately developed retirement proof exists.
- The existing v1 `ReadCompleteNetworkAuditLedger`, `ResolvePeerAuditScope`, `box_peer_set` and all original Host/SQLite behavior remain untouched. **Neither new v2 reader nor the pure scoped name is a production migration toggle.** Old shared-ACL database returns `ErrResourceLocked` rather than being mistaken for converted data. Conversely, the old shared-ACL reader continues to reject fully per-Box-v2 fixtures.
