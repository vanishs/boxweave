## Effective architecture

- Explicit fresh-only opt-in, not the legacy installer default. No adoption or online migration. Reviewed candidate requires --scoped-peer-fresh, explicit --apply, exact --scoped-fresh-review-sha256 from trusted local native-scoped-fresh-plan and matching host/binary digests. Native scope is derived. See scripts/n2_installed_lifecycle.sh and [N2](V1_PR178_N2_FRESH_SCOPED_LIFECYCLE_2026-11-23.md).
- Scoped mode refuses legacy upgrade, rollback, backup commit and uninstall. Preserve original guard/journals; scoped retirement/reinstallation not accepted. Legacy regression mode remains separate.
- New Box default boot.autostart=true, explicit false preserved. Create uses stopped quarantine then UUID-derived independent ACL, exact readback and requested boot choice before conditional start. Delete removes only its own ACL after absence proof; addresses held against reuse. Same-name reincarnation gets new UUID, ACL, MAC and addresses.
- Trusted setup installs boxweave-scoped-guard.service before Incus and boxweave-scoped-lifecycle.service for bounded Root work. Authenticated controller supplies exact original, not arbitrary Root commands. Root independently validates actor, claims, ledger, native UUID/ACL/ETag and kernel inventory. Routine scoped Peer needs no further Host approval.
- Grant prepares A/B ACL and exact directional conntrack cleanup under deny, guard allows last; revoke denies first then cleans direction/A/B ACL. Reverse and unrelated connections and boot flags stay intact. Four verified steps, durable intent/readback and published typed boot policy precede atomic SQLite settlement. Guard boot restores trusted chain before Incus; no whole-Project STOP fallback.
- Incomplete Root history refuses boot. Controller Wants/After rather than Requires helper keeps MCP read/recovery accessible when possible; native guard/Incus and Root requirements remain fail-closed. Mutations stay fenced.

## Capacity

- Inherited 1,024 owned Box bound, not physical capacity or address availability. Retired identity readback bounded at 8,192; held addresses may exhaust sooner. No scoped address reuse.
- Up to 32 retained directional peer_grants rows per Project, including REVOKED. Exact same-incarnation regrant reuses row; 33rd distinct direction refused before native effects. Not a 32-Box limit or unlimited churn.
- Root policy chain bounded at 8,192 records (each completed grant/revoke including regrant). SQLite stage and independent Root pre-effect checks enforce used+1+active_after <= 8192, preserving one future record for each active direction. At valid consistent capacity, new grants cannot strand necessary revokes. No safe automatic history compaction/reset; never delete journal to reclaim capacity. Partial/unpublished original independently fences work.
- Capacity regression seeds synthetic terminal audit history near boundary, not 8,192 real native transitions. Tests last eligible grant, rejected grant without Root invocation or new pending/live claims, reserved revoke, arithmetic boundaries. Full-scale native/performance and safe compaction remain outside acceptance.
