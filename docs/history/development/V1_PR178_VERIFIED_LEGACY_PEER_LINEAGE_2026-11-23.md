# PR #178 — Verified legacy Peer history through scoped v2 (2026-11-23)

**STATUS: DURABLE SQLITE LEGACY-PROVENANCE COMPATIBILITY CODE TESTED; NOT an installed MCP or Root Peer writer, and NOT production ACL migration acceptance. PR #178 remains Draft.**

This fixes an actual legacy v1/v2 compatibility bug discovered by inspecting the production **Root finalizers**, not by guessing at historical data. The previous scoped v2 implementation modeled all existing CONFIRMED/REVOKED rows with an empty `operation_id` and no terminal original; real RC13 SQLite behaves differently.

## Actual production terminal lineage

- `FinalizeRootPeerGrant` and successful read-only UNKNOWN grant reconciliation set `status='CONFIRMED'`, `desired=1`, **`operation_id=''`** and **`last_verified_operation_id=<SUCCESSFUL_ORIGINAL>`** atomically with the source Operation's SUCCEEDED state and a kernel-verified completion event.
- `FinalizeRootPeerRevocation` and successful read-only UNKNOWN revoke reconciliation set `status='REVOKED'`, `desired=0`, **`operation_id=last_verified_operation_id=<SUCCESSFUL_REVOKE_ORIGINAL>`**. The retained revoke original is intentional; it is not an unresolved PENDING operation.
- Staging a regrant reuses the same exact REVOKED source/target and leaves the historical `last_verified_operation_id` pointing to the previous **revoke** until new native authorization is independently completed. Staging a revoke keeps the previous **grant** provenance. A new fresh grant alone has no verified history.
- Previously committed v2 `StageScopedPeerOriginal` required `operation_id=''` even for REVOKED, and v2 `ReadRootScopedPeerOriginal` accepted only blank historical operation IDs; both falsely blocked real post-revoke histories and failed to prove historical terminal kernel completion.

## New fail-closed read-only verification

- `internal/state/network_peer_scoped_lineage.go`: `scopedPeerVerifyHistoricalOperationTx` checks the **exact** previous terminal original ID, SUCCEEDED action, Project, source UUID/incarnation and actor/token nonempty, canonical historical `RootPeerRevokeSafeIntent` or independently versioned `ScopedPeerOriginalIntent`, matching bridge, direction and both incarnations. For v1, the exact legacy ACL must be `bw-*`, correspond to the original typed `acl:default/<acl>` lock and its two exact `box:<uuid>` claims. For v2, require the proposed full five scoped resources. No untrusted old ACL is inferred from new per-Box ACL naming; both are distinct immutable evidence.
- A successful historic status is **insufficient**: require a real **SUCCEEDED kernel-verified event** for the correct original. v1 and v2 event classes are strictly segregated. v2 terminal event labels are presently *reserved only*, and cannot be emitted by the current installed worker.
- `scopedPeerVerifyTerminalLineageTx` requires exactly the schema's native finalization convention: CONFIRMED must have blank operation ID + valid verified grant original, REVOKED must have **identical** operation ID and last verified revoked original. UNKNOWN, duplicate/foreign/partially verified, uncanonical intent, unclaimed/foreign original or missing original completion all deny.
- `ReadRootScopedPeerOriginal` now pulls `COALESCE(last_verified_operation_id,'')` under the SAME read transaction as the original, five resource claims, full per-Box SQLite owner/fence inventory and every active/revoked direction. It verifies the historical original of **every sibling** (e.g. C→A), then any pending target A→B. A fresh grant must have no stale historical original; a revoke needs an exact previous successful grant; a regrant needs an exact previous successful revoke + its persisted `SCOPED_PEER_V2_REGRANT_FROM_REVOKED` marker.
- `StageScopedPeerOriginal` performs the equivalent complete-lineage checks under ONE SQLite mutation transaction. Exact revoked regrant now matches `operation_id=last_verified_operation_id` and non-null verified ID; it **does not** blank out or fabricate the historical revoke. These changes do not grant Root privileges, modify network/ACL state or restart any Box.
