## New code and invariants

- `internal/install/network_peer_guard_journal.go`: per-immutable-original JSON journal in a proposed separate root scope `/var/lib/boxweave-native-peer-guard-v1`. Intended `nativePeerGuardJournalScope` binds exact lowercase hex32 original ID, Project/bridge/ACL, two distinct canonical UUIDs, ledger/native digests and the before/after nft guard SHA256. This struct is currently package-private input; **future Root mediation MUST derive it independently from protected SQLite and revalidate actor/token and native ownership**.
- Exclusive `O_CREAT|O_EXCL|O_NOFOLLOW` 0600 file in an exact 0700 owner-pinned directory; fsync the unknown intent file, its containing directory and directory creation parent **BEFORE** the callback that might write to nft. A previously existing symlink, truncation, corrupt file or even a completed original blocks any effect reuse. Read-only journal loader bounds JSON to 64 KiB, rejects trailing/unknown fields, unsafe owner/inode/link count or contradictory state. No arbitrary reset/delete API is created.
- Only successful independently witnessed kernel guard step can replace `DISPATCH_UNKNOWN` with **`GUARD_STEP_KERNEL_VERIFIED`** via atomic file write, directory sync and strict readback. This is **not** `COMPLETE_VERIFIED` for the whole Peer (which still requires Incus ACLs, exact A/B conntrack cleanup, root native/audit, application continuity and operation worker finalization). On any ACK loss, cancellation, incomplete kernel witness, unexpected digest, journal completion fault or crash, the original remains `DISPATCH_UNKNOWN` and cannot be retried.
- `internal/install/network_peer_guard_journal_transition.go`: package-private composition of the exclusive persistent Root intent and exactly-one-direction `nativePeerGuardReplaceOnce` effect; refuses mismatched original pre/post digests before writing. **Not called by** the current Root helper, CLI, MCP or systemd. Root collector and lock/actor verification are still missing.
- `*_test.go` fixture and failure matrix: secure journal inode/dir, wrong UUID/Project/bridge/ACL/SHA, symlink, malformed existing journal, state readback, fsync-before-effect witness, duplicate completed/unknown originals, applied-but-ACK-lost, kernel poststate unavailable, completion write failure, and composition no-replay under native uncertainty. ## Key blockers before integration

1. **Production authorization**: precise protected SQLite actor/token/isolation, global bridge and per-Box ACL/UsedBy/IPv4/IPv6/MAC/Incarnation evidence; new Root journal must be derived from these, not from an MCP-supplied intent or test struct. Must hold original and global/per-affected-Box locks through every stage.
2. **Durable full Peer state machine**: per-Box ACL provisioning/migration, guard install + persistent boot ordering, grant/revoke A/B ordering, exact affected conntrack invalidation, lost Incus SDK ACK and batch ACK reconciliation, safe UNKNOWN rechecks and idempotency. This file currently records **one guard stage only** and should not be used to falsely finalize the full MCP operation.
3. **Least-privilege once-only Host setup and MCP**: systemd helper/sandbox, authenticated local `SO_PEERCRED`, no generic shell, original-based repeated Root preflight, crash/reboot recoveries; current RC13 `native-peer-root-serve` still pins one manually approved original, and its shared-ACL stop barrier still interrupts C/D and retains autostart=false. Keep it as conservative protection until the new path is independently signed.
4. **Installed candidate fault matrix and independence**: old Host and v1 MUST remain unchanged, all C/D IPv4+IPv6/UDP/Forward long-lived services must survive; interrupted/partial nft and Incus, exact conntrack TCP, secure original no-replay after process crash and Host reboot, concurrent grants, reused addresses and foreign users must be proven. Outer nested AppArmor `unconfined` is not an enforcing recursive security proof.
