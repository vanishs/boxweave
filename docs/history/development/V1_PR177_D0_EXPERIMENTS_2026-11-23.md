## 4. Decisions and remaining limitations

D0 resolves architectural approach, not D1 implementation. Highest-priority discovery is existing RO reader can create cold WAL/SHM; immutable avoids that but loses live committed WAL. A safe new read-only path must pass BOTH no-source-side-effects and freshness gates, or fail closed/partial. Do not relax security or guess from stale data. A snapshot strategy requires independently established quiescence/stability, correct WAL treatment and proof; D0 does not certify one. No source modification of actual databases for these experiments. Existing healthy fixture confirms tombstone handling in generic view; do not create an unnecessary rewrite. Empty scoped reader has different contract from mutation-grade guard. Native fault coverage inherited from exact baseline CI; D1-D5 require new diagnostic-specific native cases rather than repeating all #178 development.

No full diagnostic field/report or repair-plan implementation yet. No physical reboot/LAN/public IPv6, full native capacity, safe address reuse, full simultaneous writer/snapshot correctness or all permission races proven by D0. These are explicit limitations, not hidden PASS. Read [stage gates](V1_PR177_D0_D5_DEVELOPMENT_PLAN_2026-11-23.md) and [post-#178 contract](V1_DOCTOR_RECOVER_POST_PR178_CONTRACT_2026-11-23.md) for next work. Stop at D0 CI submission; independent D0 CI results must be checked before D1.
