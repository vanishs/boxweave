# Security and ownership — small fixed policy

**Invariant:** A BoxWeave MCP caller, including an `admin` token, can inspect or mutate **only** this layer's BoxWeave-owned Incus resources and their approved consequences. It cannot acquire host shell, foreign Incus admin, host file, parent BoxWeave or arbitrary network/Caddy authority.

## Owned native boundary

- Confirm exact Incus instance UUID/incarnation and local SQLite ownership before sensitive calls. Names/IPs are not identities; reuse cannot attach old peer grants or forwards. A restricted Incus Project assists isolation but is not by itself ownership or private packet isolation proof.
- Only BoxWeave-owned Boxes, native forwards, single directional peer grants and relevant operation receipts may be exposed. Existing unrelated Incus instances/projects/networks remain unmanaged. SQLite loss/corruption fails closed and requires host-local independently verified recovery.
- Guest-root `box_exec` can read/write/delete guest files even if those file actions are not individually exposed. Guest root is not host root: deny privileged container configuration, host mounts, Unix socket bind, devices, raw Incus API pass-through or arbitrary host shell/file operations.
- Private Bridge NIC ACL rules rely on native address matching because Bridge ACL group selectors are unsupported; make current Box UUID -> NIC -> IPv4/IPv6 bindings and anti-spoof controls an explicit proof obligation. Revoke/withhold grants if addresses change without verified atomic policy convergence. Never claim a Box UUID is itself a native ACL selector.
- Private traffic between managed Boxes is denied by default with actual IPv4/enabled IPv6 enforcement; controlled IPv6 disable or Box creation/start refusal if enforcement is unsupported. Simple `box_peer_set` may explicitly allow/revoke one directional owned Box pair. Never edit arbitrary CIDR/IP/host firewall.
- Native TCP/UDP forwards accept only owned Box UUID + guest port. `box_delete` must also clean up and verify **only** that Box's managed dependent forwards and peer grants. A partial delete keeps the original incident evidence and refuses unsafe rollback or foreign cleanup. In the P0 instance-owned proxy-device backend, deleting an instance also removes its native device; verify no stale BoxWeave ledger claim or unrelated host listener. Orphan *network-forward objects* are only relevant if that separate backend is explicitly introduced later. Explicit host public bind is an administrative exposure event; default local bind where possible, reject foreign port/device claims and collisions.
- Independent nested installations receive no inherited socket, Token or parent service authority. A Box containing an inner BoxWeave is an ordinary parent-owned Box with standard lifecycle/destructive rules.

## Native SDK security boundary

Incus v7.6.0 distinguishes local `incus-admin`/root (full Incus authority) from a non-root `incus`-only user (native per-user Project confinement). First design candidate: dedicated BoxWeave service user in `incus`, **not** `incus-admin`; host-local administrator provisions a `restricted=true` Project and permits only necessary features. `restricted.devices.proxy` and `restricted.containers.nesting` default to `block`, so explicitly verify approved exceptions and that forbidden native calls remain denied. `UseProject` alone is not authentication/authorization; application UUID ownership and actual same-bridge traffic separation remain necessary. Restricted TLS and native Scriptlet were subsequently **tested**: [exact-ACL authorization](../verification/INCUS_ACL_AUTHZ_TLS_SCRIPTLET_2026-11-08.md) and [selected three-Box shared ACL](../verification/SINGLE_SHARED_ACL_SCRIPTLET_ACCEPTANCE_2026-11-08.md). The product owner **accepted daemon-global Scriptlet routing with an explicit README warning**; installation still requires host-local approval, policy backup, client compatibility regression, and verified rollback. Do not silently change host-wide authorization or grant the public MCP runtime native administrator power.

**Bridge ACL authorization is a separate P0 least-privilege gate.** Real official Incus Go SDK tests proved that a native Scriptlet can allow a dedicated TLS client to edit **one exact existing ACL** while denying unrelated ACL GET/PUT/DELETE. Native `UpdateNetworkACL(...,ETag)` returned **412** on a stale write. But this `can_edit` privilege covers the entire target ACL ruleset, so a dedicated TLS client must not receive a broadly reused or foreign-attached ACL. `can_create_network_acls` is checked on the **effective Project** before decoding the requested name; one real test created an arbitrary-named ACL after a temporary Project-level creation grant. Native Scriptlet also replaces automatic restricted-TLS certificate Project restrictions for **all** clients routed through the daemon-global class setting. A product implementation must **not** claim per-object create authorization or modify that global routing on an unapproved shared host. Preserve native non-admin instance/proxy confinement and fail closed until exact ACL provisioning/other-client policy are resolved. The real experiment's credentials, Scriptlet and HTTPS listener were fully removed.
Use MCP `auth.RequireBearerToken` with a BoxWeave revocation-aware verifier; **typed MCP tool handlers MUST authorize `req.Extra.TokenInfo` from the current call**. `auth.TokenInfoFromContext` is for HTTP middleware handlers, not the source of tool identity. Set non-secret `TokenInfo.UserID` for SDK legacy-session principal binding and deny missing/expired/revoked token metadata. Preserve SDK localhost Host/DNS-rebinding protection and built-in request-body cap. Add explicit Origin and trusted-proxy validation; `ToolAnnotations` are hints, not ACLs. See [SDK native mapping](../research/SDK_TOOLS_NATIVE_MAPPING_2026-11-07.md).

## Selected single shared ACL / Scriptlet security contract

[Actual Incus 7.6 three-Box native acceptance](../verification/SINGLE_SHARED_ACL_SCRIPTLET_ACCEPTANCE_2026-11-08.md) verified one installer-created ACL referenced by all three owned NICs, IPv4/IPv6 A→B-only packet traffic, revoke, SDK stale ETag **412**, host-loopback TCP/UDP proxy and a simulated legacy TLS client's identical pre/post authorization/guest Exec matrix. This proves the selected native **mechanism**, not a compiled BoxWeave v1 controller.

**Privilege boundary:** local installer creates exactly one exclusively owned ACL and obtains explicit consent for global `authorization.client.tls-restricted=scriptlet`. The dedicated **restricted TLS** key only authorizes GET/PUT of that exact ACL using server certificate pinning; deny create/delete/other ACL/instance/foreign Project. Normal `incus`-only OS identity controls only owned Boxes and their native devices. Never grant `can_create_network_acls` or any root/`incus-admin` power to a network-facing MCP process.

**Shared-host security:** every existing restricted TLS client now uses Scriptlet instead of built-in Project filtering. Inventory existing certificates/policies, backup exact old route/scriptlet, compare positive **and negative** rights before/after, preserve unrelated client authority and rollback on divergence. An unrecognized certificate must not receive permissive fallback. Owner acceptance of global change does not make an incompatible policy safe.

**Network guarantees:** validate each referenced NIC belongs exclusively to BoxWeave, bind peer grants to UUIDs and currently observed IPv4/IPv6 addresses, recalculate whole ACL ruleset and use native ETag. Native Bridge ACL updates reload affected NICs individually; on failed/partial propagation, IP reuse/spoof risk or unreadable provider state, withhold new peer grants and preserve UNKNOWN. Long-lived connection revocation, production anti-spoof, scale, real shared-host migration and native Cowsql reliability remain unaccepted gates.

## Minimal access control

- Local bootstrap creates super-admin; multiple independently revocable MCP credentials are `admin` or `viewer`. No per-Box Token grants, separate file/delete/cancel/tool rights or general RBAC platform. Admin can issue authorized mutations and guest-root Exec only within this controller's ownership domain.
- Viewer **cannot mutate or Exec**, but can read owned Box metadata, files and bounded Exec output, which can contain secrets. Never market viewer as a privacy/redaction role; revoke/limit issuance as appropriate.
- Revocation rejects new requests and provably undispatched queued operations. It does not imply that a dispatched/possibly dispatched operation was stopped, rolled back or resolved. A revoked Token cannot fetch old receipts; a valid admin can inspect redacted audit evidence.

## MCP and async safety

- Bind authenticated Streamable HTTP MCP to `127.0.0.1` by default. Inner BoxWeave's localhost MCP is not reachable by addressing its bridge IP from the parent; a guest-local, separately authenticated test client may run as ordinary software under the parent's authorized guest Exec. Operator-managed HTTPS proxy/Cloudflare Tunnel is separate; enforce Token, size/rate and Origin/trusted-proxy checks regardless.
- Every mutation requires caller-provided reusable idempotency key; same actor/key/intent returns original Tracking/Operation IDs and conflicting reuse is denied. Go context is propagated through native adapters, but disconnected caller context does not undo accepted durable work.
- All accepted mutations persist safe intent before effect, cap output and retain UNKNOWN on ambiguous native results. **UNKNOWN manual claim release is host-local only**, requires exact target/operation review, short-lived one-use challenge, second explicit risk acknowledgement and protected audit; it never changes/retries/cancels the original operation. See [approved procedure](../process/UNKNOWN_MANUAL_RECOVERY.md). Verify post-state; no blind replay of create/delete/Exec/forward changes. `operation_get` includes small redacted diagnostic summary. Detailed logs and recovery stay in local protected CLI; **no separate diagnostics MCP service**.
- Guest file list/read/create/replace/delete are restricted to guest regular files with size/race/path checks. No built-in patch engine or host fallback. Fail UNSUPPORTED when native safe overwrite/delete cannot be verified.
- Automatic dependency reconciliation is host-local and explicitly invoked. Reuse/manage an existing Incus daemon without unapproved shared service disruption, and never adopt arbitrary existing instances. No Caddy dependency or automatic host reboot.

## Negative acceptance

Test foreign Box UUID/host file, raw Incus settings, old IP/name reuse, unsafe guest file symlink/hardlink, token viewer Exec/write, revoked queued/active operations, uncontrolled IPv4/IPv6 paths, foreign port listener, public bind authorization, nested parent/sibling privilege, duplicate idempotency and UNKNOWN. Refusals must have independent no-side-effect evidence.
