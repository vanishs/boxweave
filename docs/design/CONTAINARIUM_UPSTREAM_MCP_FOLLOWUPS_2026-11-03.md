## Origin and boundaries

The upstream maintainer's [Containarium issue #3500](https://github.com/FootprintAI/Containarium/issues/3500) investigated BoxWeave as an **external** MCP client. Its "Out of scope" section means that the issue does not undertake to change BoxWeave, maintain BoxWeave's vendored `containarium-shell`, certify version pairs, or promise compatibility. This is a scope/ownership statement, **not proof that host-hop SSH is inherently incorrect**.

Upstream [#3474](https://github.com/FootprintAI/Containarium/pull/3474), [#3490](https://github.com/FootprintAI/Containarium/pull/3490) and test-only [#3501](https://github.com/FootprintAI/Containarium/pull/3501) have merged. Containarium `v0.127.0` includes #3474; #3490/#3501 merged **after** that release and must not be assumed present in its published binaries. The former BoxWeave evidence is pinned to its exact test revision and environment. No original Provider upgrade or new integration acceptance follows from a GitHub merge.

## Decision A — installation and failure contract (2026-11-03)

The owner explicitly selected **Option A**, preserving the previous *managed local Provider auto-install* user experience while removing vendored wrapper bytes from future BoxWeave Release artifacts. The code migration is **not yet implemented**.

| Provider ownership / condition | Intended behavior |
| --- | --- |
| **BoxWeave-managed local Provider**, wrapper missing | Automatically retrieve the version/commit-pinned upstream source, extract only the reviewed wrapper, verify the pinned SHA-256 and guarded host ownership/permissions, then install/register it. Do not require a new operator flag for this owned-provider path. |
| **Externally managed Provider**, wrapper missing | Read-only report by default. Download/install only on **explicit operator repair authorization** (keep a compatible, clear CLI flag or replacement action). Never silently adopt external host ownership. |
| Existing wrapper, already reviewed and compatible | Preserve it; do not rewrite or reset login shells just to refresh the file. |
| Existing wrapper differs, is symlinked, unsafe or is managed by someone else | Do not replace or take ownership automatically. Report an actionable conflict. |
| Unsupported/unknown installed Containarium version | Do not blindly install an older wrapper. Report the missing compatibility pin and keep the existing Provider unchanged. |
| Pinned download unavailable, offline, source structure changed or SHA-256 mismatch | **Do not install any unverified script.** Mark only the optional host-hop setup incomplete with a clear, non-secret diagnostic; retain the working core BoxWeave/MCP install when it can run independently. Do not claim SSH host-hop verified or silently fall back to floating refs. |
| Upgrade from a release that recorded the wrapper in `managed_files` | Preserve the existing script and working login path, reconcile old tracking without bypassing foreign-file safeguards, and avoid forcing a download of a file already safely present. Do not auto-uninstall or remove its `/etc/shells` entry. |

**Responsibility split:** Containarium owns wrapper behavior and source; BoxWeave owns the **safety of its optional installer integration**, immutable pin mapping, correct Provider ownership classification and accurate diagnostics. Download-time hash verification does not substitute for host-hop SSH authorization/testing. No broad Incus sudoers, SSH daemon changes, or new public listener are authorized as part of this feature.

## Why the host-hop packaging decision matters

BoxWeave source `v0.42.9` included an upstream-source-copied, SHA-256-pinned `bwmini/containarium-shell`. Its installer can place it at `/usr/local/bin/containarium-shell` on a BoxWeave-managed local Provider and optionally repair an external Provider with `--repair-containarium-shell`. That **already published historical behavior remains factual**; the owner-selected future design supersedes it, not the immutable release itself.

This script is an **official Containarium host-hop SSH wrapper**, not a BoxWeave-created MCP protocol. It uses SSH login identity to map to an Incus container and calls Incus tools, including for wake-on-SSH. Vendoring it causes BoxWeave to own an additional privileged host lifecycle path, duplicate upstream fixes, and maintain pinned compatibility as Containarium evolves. An exact old-script digest proves provenance, **not future compatibility or secure operation**.

**Retrieval detail (verified upstream source):** The wrapper is currently embedded as a heredoc inside upstream `scripts/setup-ssh-container-proxy.sh`, not supplied as a standalone versioned raw script in that location. A first delivery slice can retrieve that setup script from an **immutable upstream commit**, extract only the wrapper, and validate its **pinned SHA-256** before installing; do **not** execute the upstream setup script. Prefer asking upstream to publish a separately versioned wrapper/asset so BoxWeave can download it directly. Fetching a script from a fixed ref still gives BoxWeave responsibility for installer safety and for checking the wrapper against the actually installed Containarium version. Use no floating `main`/`latest` downloads.

Code-level audit consideration: the reviewed upstream wrapper uses `sudo incus start` and `sudo incus config set/unset` during SSH wake, whereas the corresponding upstream setup script example grants passwordless `incus exec/info`. Actual per-account privileges and SSH wake behavior need explicit positive and negative tests; **never remediate by granting unrestricted Incus privileges**. Also, the wrapper's direct Incus actions require scrutiny for consistent authorization, lifecycle receipts and troubleshooting relative to Containarium API calls.

BoxWeave's authenticated, target-pinned Provider MCP `connect(exec)` route has separate live evidence and does **not** require this host-hop wrapper. It remains the preferred Agent operation route when available. Host-hop SSH stays an **optional upstream-managed transport**, not a prerequisite for working direct MCP execution. No claim is made that HTTP wake automatically wakes `connect(exec)` or resumes an interrupted Agent task.

## Future packaging migration (NOT implemented)

1. Inventory every downstream reference: `bwmini/containarium-shell`, release/installer manifests and digest pins, `bwmini/online.py`, `install.sh`, `--repair-containarium-shell`, source tests, README, operator guidance and managed-file state. Confirm what the **actually published** release contains; do not infer from current source.
2. Remove the wrapper **file** from new BoxWeave Release assets. **Option A:** if the wrapper is missing on a positively identified **BoxWeave-managed local Provider**, automatically download the exact approved upstream source and install only the SHA-256-verified extracted wrapper after safe host/version checks. Do not gate this owned-provider path on an extra user flag. On **externally managed Providers**, default to read-only diagnosis and require explicit operator opt-in to repair. An absent network dependency, unknown Provider version or digest mismatch must leave the helper **uninstalled**, with a clear optional-host-hop incomplete status while preserving otherwise usable core BoxWeave/MCP installation. Never run the full upstream setup script, grant broad Incus sudoers or silently change `sshd`, SSH accounts or listening ports.
3. Provide an explicit migration policy for installations where BoxWeave previously marked the script as managed. Preserve the binary and existing login paths by default; never delete a shell referenced by a host account. Reconcile old managed-file checks and the legacy repair flag without silently ignoring the operator's request. Any removal or reassignment needs host-specific authorization and a rollback plan.
4. Validate release-manifest exclusion and pinned fetch/extraction/hash checks. Test a clean **managed local Provider** with missing wrapper (automatic install without flag), a managed Provider with matching existing wrapper (no download/rewrite), an **external Provider** without repair flag (no write) and with explicit repair flag (guarded install), plus offline/error/checksum/unknown-version/foreign-wrapper cases. Test upgrades from a wrapper-containing release with legacy `managed_files` entries; direct MCP `connect(exec)` should remain working even if optional host-hop fails. Where specifically authorized, exercise real host-hop login/wake and cross-target denial. Verify no broken user login shells, broad sudoers, or collateral host changes. Record exact Provider/runtime version, exits and unverified cases.
5. Only after separate source, CI and **installed** validation may a new BoxWeave release be claimed to implement the dependency-download decision. Do not modify the stable pin or existing host during documentation work.
