# S4-B2 — Native Incus 7.6 stateful ACL revocation and exact conntrack invalidation

**2026-11-17 UTC. Stage: `S4_B2_PARTIAL`, B3 NOT STARTED.** This document distinguishes a disposable privileged native experiment from an installed production MCP implementation. Only the existing [Draft PR #153](https://github.com/vanishs/boxweave/pull/153) is authorized.

## Reproducible critical finding

- [Original native CI #44072000187](https://github.com/vanishs/boxweave/actions/runs/44072000187), job `134000280475`, exact commit `4c5c937ce146f7294529e6162e7e44940cc5c52b` **FAILED intentionally on real fail-open behavior**. It started actual TCP and UDP connections, IPv4 and IPv6, from A `10.248.83.11/fd83:248::11` to B `10.248.83.12/fd83:248::12`. All four were established, with client progress counters at least 8. The product Go ACL compiler emitted exact A↔B dual-stack DROP tombstones; the official Incus Go SDK ACL ETag PUT and readback both succeeded. However, IPv4 TCP kept transferring data for at least 15 seconds; test failed at `S4_B2_NATIVE_LIVE_TRACKED_tcp4=NOT_BLOCKED`. Merely removing Allow or adding explicit ACL DROP **must never be advertised as terminating existing sessions**.
- Downloadable original [native evidence ZIP](https://github.com/vanishs/boxweave/actions/runs/44072000187/artifacts/14323581380) includes `s4b2-quiescent-live-symmetric-drop.nft`, and real `conntrack -L -p tcp|udp` before dumps. Example actual TCP `ESTABLISHED src=10.248.83.11 dst=10.248.83.12 dport=19091 [ASSURED]`; UDP tuples included both address families. In Incus-generated per-NIC `in/fwd/out` chains, **`ct state established,related accept` precedes all user-defined exact DROP rules**. Within-ACL DROP-vs-ALLOW priority does not override the earlier stateful acceptance.
- [Incus ACL documentation](https://linuxcontainers.org/incus/docs/main/howto/network_acls/) warns bridge rules can only constrain intra-bridge peers when ACLs are applied directly to their NICs and baseline rules precede user ACLs. This project's tests use correct per-NIC ACLs but **native established conntrack remains relevant**.
- [Companion earlier CI #44065264009](https://github.com/vanishs/boxweave/actions/runs/44065264009) showed stale IPv4 ICMP after revoke, manually added DROP blocking ICMP, native static IP rotation denying dual-stack and exact scope conntrack deletion, but *not* a TCP/UDP long-lived session termination proof. This explains why previous ICMP-only successes were not sufficient.

## Confirmed exact-pair mitigation (disposable host only)

- [Native CI #44073562476](https://github.com/vanishs/boxweave/actions/runs/44073562476), original job `134005629199`, exact source `3693e02692b752385c7fc1868e8204d1f086ddf0`, **SUCCESS**. All four continuous real sessions were established (`ESTABLISHED_COUNT_8`). After official Incus ACL DROP ETag PUT, all four were **still transferring** (`tcp4 count=29`, `tcp6 count=29`, `udp4 count=29`, `udp6 count=30`). Then root-side `conntrack -D` was scoped to the verified A→B source/destination, `ipv4|ipv6` and `tcp|udp` destination ports 19091/19092; **all four exact deletes were observed**. Subsequent client markers were `tcp4 BLOCKED_AFTER=31`, `tcp6 BLOCKED_AFTER=30`, `udp4 BLOCKED_AFTER=30`, `udp6 BLOCKED_AFTER=30`. No global flush was performed before this proof. Native ACL original state and disposable fixture later restored/cleaned. This proves a *mechanics candidate*, not a safe production privilege boundary.
- The same run later used the previous test's global `conntrack -F` on the **disposable CI daemon only** for unrelated comparison. Production **must not** perform global flushes. A secure production implementation needs independently root-verified bridge/lease ownership, full shared ACL consumer set and held operation/SQLite claims, the all-Box native stop/autostart barrier, exact intended ACL readback, a tightly bounded root-only per-pair conntrack operation, negative foreign-flow noninterference, ACK loss/restart and kernel convergence verification. Do **not** give MCP or restricted nonroot client arbitrary `conntrack` or root shell privileges.
- Never release/reassign A or B native static IPs while old ACL grants, dropped-state uncertainty or conntrack flow status remain unresolved; durable `UNKNOWN` and no retries for uncertain root mutations.

## Separate cross-Project source spoof P0

- [Native isolation CI #44072000205](https://github.com/vanishs/boxweave/actions/runs/44072000205) exposed `S4_B2_FOREIGN_UNFILTERED_NIC_FORGED_A_SOURCE_V4=REACHED_B_SECURITY_BREAK` and the same IPv6 spoof, when an unauthorized-for-BoxWeave Project could attach an unfiltered NIC on the bridge. Normal non-spoofed foreign addressing was denied. This is why an independent host-root *actual* bridge/ACL `UsedBy` and network/lease exclusivity check must precede every ACL write. The root-only `NativePeerBridgeAudit` exists but is **not yet wired to the production worker**. It cannot be replaced by checking only the restricted Project's local instance list or by trusting an MCP-supplied address. Failure must hold all claims and refuse the mutation.
- A checked snapshot is not a global lock: concurrent out-of-band privileged bridge attachments after the check remain a safety concern. Native root integration and denial/fault testing must explicitly cover this.
