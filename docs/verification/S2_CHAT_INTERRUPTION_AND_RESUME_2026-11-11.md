## Changes to how interrupted work is handled

1. **One short canonical checkpoint** in `docs/development/EXECUTION_LOG.md`: include latest exact PR source SHA, latest fully verified source + binary hash and CI jobs, next action, current failure class, environment and immutable original task IDs. Update **before/after risky mutation or long CI**, not only in free-text conversation.
2. **Bound tool batches**: prefer one focused GitHub or Box command per step, inspect `result` before branching, avoid large cross-app composite calls and giant tool-log outputs; use explicit GitHub original-commit/check-run reads to recover after transport failure instead of blindly replaying a write.
3. **Local first, native second**: reuse authorized `bwracc-1106-v2` for Go 1.26.9 + CGO unit/race/vet/probe compilation. It does **not** emulate Incus 7.6 or physical power loss. Full signed Incus/Project/quota/MCP jobs must remain truly disposable isolated CI.
4. **Limit futile reruns**: after two repeated same-class harness/environment failures, mark exact scenario `UNVERIFIED_TESTER` or `BLOCKED`, preserve logs, disable the experimental test in the required full suite, and continue independent other S2 cases. Never downgrade product fail-close, disk quota or auth just to turn CI green.
5. **Side effect recovery**: if any create/delete/guest native effect or tool transport returns UNKNOWN, inspect its original durable task/UUID **read only**; no new-key resend, forced unlock, adoption, opportunistic deletion or changing a preexisting original. For purely read-only tool timeout, rerun only read operations.
6. **Tier-specific phase exit**: CI job SUCCESS is not blanket S2 PASS. Independent TC-001–010/A-case rows still need explicit closure and external hardware/WAN limitations remain visible. Do not promote PR #130 to non-Draft, merge `v1` or touch shared Incus.
