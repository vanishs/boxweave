## Why this patch does not require an operator design decision

D4 must distinguish three observations without altering security boundaries:
1. Exact `exit_code: 0\\n` with check=logs means the authorized fixed `journalctl` successfully returned no lines; a bounded empty log observation is honest.
2. Exact bounded stderr-only numeric nonzero means the fixed guest command **failed**; preserve `not_verified` with fixed `PROJECT_COMMAND_EXIT_NONZERO` and a clamped number, without inspecting/returning stderr.
3. Incomplete, spoofed, oversized or unrecognized replies stay `PROJECT_READ_FORMAT_UNSUPPORTED`; all D4 root policy, Box identity, no-raw-log, and fixed-command rules remain unchanged.

**Release gate:** source candidate v0.42.7 is version-aligned in VERSION, Python, Web, lock, README and Gateway serverInfo; stable PUBLISHED_RELEASE stays v0.42.1. Only mark live v0.42.7 FIXED after an immutable release, exact pinned upgrade in the isolated Box, actual D4 response checks, doctor and cleanup or retained UNKNOWN evidence. Do not promote generic Phase 2/3 or E2–E4.
