## BH-018 uncovered crash boundary: Exec output and terminal receipt are **two SQLite commits**

Source audit in this branch after the narrow 126/127 classifier change:

1. [`internal/control/box_tools.go`](../../internal/control/box_tools.go), `box_exec` verify closure checks original `final.ID == nativeID`, translates the final native operation to a bounded exit/output evidence value, validates paths against exact Box and native ID, and then calls `Store.SaveExecOutput(ctx, r.ID, ...)`. This stores the evidence and returns `nil`.
2. [`internal/state/lifecycle.go`](../../internal/state/lifecycle.go) `SaveExecOutput` uses **a standalone `s.db.ExecContext`** `INSERT INTO exec_outputs ... ON CONFLICT UPDATE`, committed independently.
3. [`internal/state/worker.go`](../../internal/state/worker.go) `Worker.Execute` calls `w.Store.Verified(context.Background(), operationID)` **after** the successful verify closure. [`internal/state/store.go`](../../internal/state/store.go) `Verified` makes a **second independent transaction** transitioning `VERIFYING -> SUCCEEDED` and appending the operation event.
4. `Store.Recover`, on restart, transitions **all** `VERIFYING` operations to `UNKNOWN / PROCESS_RESTART_OR_LOST_ACK`. Hence a process crash *after* a valid final native result + `exec_outputs` SQLite commit but *before* `Verified` commit leaves an original **UNKNOWN** and prevents any new Box operation, even though the exact output row is already durable. This is a genuine **false UNKNOWN / unnecessarily retained lock** possibility, not a duplicate-dispatch vulnerability. Conversely a two-transaction redesign that simply auto-unlocks every saved output row without strict original-ID evidence and crash tests is **not acceptable**.

**Next code/acceptance requirement (not implemented here):** a single SQLite **`FinalizeVerifiedExec`** operation must atomically (a) verify original `box_exec` state `VERIFYING` and **its original native Operation ID, Box UUID/incarnation/name/project**; (b) validate exact native output paths, numeric terminal Guest exit and final status/error semantics already checked by the native verifier; (c) insert immutable/protected `exec_outputs` final evidence and (d) update operation to `SUCCEEDED` with event—all in one committed transaction. Arrange `Worker.Execute` control flow so an atomically finalized Exec is **not** redundantly finalized or classified UNKNOWN. Tests must use real SQLite crash/fault injection on both sides of the single COMMIT, with the original operation ID and fresh-key Box claim checked after restart, and no native redispatch. Distinguish SQLite `COMMIT returned error` from **verified durable committed receipt**: a lost SQLite ACK may still require read-only reconciliation and UNKNOWN if uncertain.
