## Two distinct verdicts, never collapsed

**LAB_PASS** means BH-001–BH-016 passed on a real, isolated native host (with BH-010 executed as L0 on that disposable native host). It is **not** physical `dev` host ready. A physical host without explicit authorization is **HOST_NOT_AUTHORIZED**; failed shared-host baseline is **HOST_NO_GO**, not a pass.

**BRIDGEHEAD PASS / HOST_GO** requires **all BH-001–BH-017** on the **actual authorized real host** as appropriate, with independent physical host postflight and a proven fallback. A previous LAB_PASS is necessary but not sufficient. Each case result must explicitly carry PASS/FAIL/BLOCKED/UNKNOWN, `I/N/V` proof, original native identifiers, environment, tool inventory, host/Incus and source/binary SHA, timestamp, test verifier, and unresolved risks. Missing evidence is not a PASS. Any new v1 code between lab and host requires repeat acceptance of its affected cases and exact binary binding.

**Non-regression:** S4 still owns full one-ACL native Scriptlet/peer/forward/IPv6/LAN/full L0/L1/L2 controller-parity/dependent delete; S5 still requires independent **20/20 MCP+CLI** and release hashes. A BH result is *only* a bounded early development-base deployment result. Host approval is never implied by the plan itself. If blocked, record evidence, use existing isolated development options and continue safe S3 without borrowing host GO.
