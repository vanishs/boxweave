## Observed friction and disposition

- The BOI-1 tool description says paths are under the Box user's home but does not explicitly say they **must be relative**. Passing an absolute path or a symlink is safely refused, but the public gateway sometimes returns the generic `TRUST_OR_WORKLOAD_KEY_GATE` rather than a bounded path-validation error; this can misdirect troubleshooting. **P3 UX/diagnostic improvement recommended**, not a security-bypass finding. Preserve the symlink-deny rule. No executable-code change was made here.
- `selftest run` requires its plan file to be readable by the installed app user; a file saved under a mode-0700 unrelated home returned `SELFTEST_PLAN_INVALID`, with no child created. Moving the identical approved plan to a separately readable temporary test path permitted the expected wrong-confirmation rejection and the complete positive test. No privilege weakening was used.
- The installed streamed installer was invoked in a background guest shell so its **numeric wrapper exit code is U**; the success banner, v0.42.2 installed provenance, healthy services, authenticated MCP, real nested action and cold restart were independently observed. Do not fabricate an exit 0 for the initial background installer process.
- Repository and host acceptance statements must include the **exact version and test class**. Do not promote the optional R-04/E2-E4/external OAuth tracks to general PASS from this release.
