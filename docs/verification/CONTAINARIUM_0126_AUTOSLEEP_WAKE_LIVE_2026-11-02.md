## Baseline reproduction, routing topology and fix

1. **Prior unpatched v0.120.1:** newly created Box had neither `LastStartedAt` nor network signal, so enabling auto-sleep did not stop it even after more than three minutes. An explicit **test-only** Stop/Start stamped `LastStartedAt` and enabled real sleep; that was a workaround, not a valid birth-time acceptance.
2. With Caddy installed but Provider `--standalone` without `--app-hosting`, setting the Caddy admin URL, Postgres and base domain enabled a wake handler but **did not wire the ContainerServer route store**, so idle-stop left Caddy on the dead target. Configuring **`--app-hosting`** (still within the disposable outer Box) wired the route store, proxy and wake hooks. The test-only distro Caddyfile initially had a default catch-all `file_server` that took precedence and produced 404; the test operator removed only this test-owned fallback.
3. **Unpatched wake first-response failure:** with a genuine route `probe.wake.lab.invalid` and HTTP client guest, the actual sleep ticker stopped target, Caddy swapped `10.203.0.2:8080 → 10.203.0.1:18080`, and an HTTP request started the Box but returned **502**. The original app was not yet listening: the generic `StartContainer(wait_for_ready=true)` can fast-path when its first post-start IP is empty and falsely report readiness. Source was traced to `internal/server/wake_starter.go`.
4. **Patched v0.126.0:** enabling auto-sleep on an already running, newly created Box first writes a durable UTC `user.containarium.last_started_at` before the enabled flag; birth-time `idle_stop_minutes` does the same. If the durable stamp fails on a running Box, the toggle rejects before enabling. HTTP `WakeStarter` now independently waits for the **live guest IP and trusted stored route port** to accept TCP under the same readiness budget and cancellation, instead of trusting the fast-path.
5. Target HTTP route was present, private and reached via Caddy. Before the decisive request **independent Incus state was STOPPED** and Caddy upstream was **`10.203.0.1:18080`**, confirmed again immediately in the one-shot watcher. At **2026-11-03T04:12:00Z**, a real `curl -H 'Host: probe.wake.lab.invalid' http://10.203.0.1/wake-proof.txt` **inside the separate client Box** returned **HTTP/1.1 200 OK**, exact `WAKE_PROOF_1102` body, exit **0**, measured **1.65 seconds**. Post-request independent Incus showed the target **RUNNING**, with the same createdAt. Caddy subsequently pointed directly to `10.203.0.2:8080`. **First-request HTTP wake L PASS**.
6. New `bwwake-cold` was created through **one authenticated BoxWeave MCP create**, then enabled through **one authenticated Provider `toggle_auto_sleep(enabled=true, idleThresholdMinutes=1)`**; **no stop/start or restart intervened**. The real guest metadata recorded `last_started_at=2026-11-03T04:10:08Z`, enabled=true. At **04:13:45Z**, the actual patched daemon ticker logged `[autosleep] stopping username=bwwake-cold reason="idle 1m >= threshold 1m"`; independent Incus showed **STOPPED**, and the one-shot verifier exited **0**. The elapsed interval is greater than the configured threshold because of anti-thrash/network activity rules and the daemon ticker schedule; do not promise a precisely one-minute sleep. **Cold-created Box idle-stop L PASS**.
7. Negative guardrail: direct `/wake/wake-proof.txt` from the untrusted client guest source (`10.203.0.3`) to the daemon's port **18080** returned **HTTP 403** and the server logged `[wake] refused: ... not in trusted-proxy allowlist`. Trusted Caddy path remained allowed. No raw secrets or token payloads were recorded.
