## 4. Open decisions vs confirmed remediation

**Confirmed documentation fixes (R-01, safe in present scope):** remove false Phase 7 not-started claim; make `main` v0.9.1, four supported Windows client profiles, external Provider/SSH/TLS dependency and fixture vs live evidence unambiguous; remove obsolete old-main `install.sh` entry; maintain links to current authoritative reports. README may document this audit but must not become a second `PHASE_STATUS` or `FEATURE_MATRIX`.

**Not authorized to implement solely from this audit:** (a) restore all-in-one Ubuntu/Provider bootstrap; (b) restore macOS, Cursor or Claude enrollment; (c) restore old Tenant metadata CRUD/selection UI, Box resize/bulk, arbitrary jobs, HTTP proxy or monitoring dashboard; (d) restore historical upstream patch or deploy it; (e) perform data migration, host changes or public route creation. Those need the product owner's explicit prioritization and specific acceptance requirements. This audit records these as possible differences, not silent P0 bugs.

**Unverified evidence:** old-vs-new installed workflows, fresh browser screenshots, Windows Agent GUI loading, actual ZCode model execution, Provider network/isolation behavior, clean Ubuntu boot/install, public TLS, historical production migration, and status/README consistency automation. The old report in [COMPARISON_REPORT](COMPARISON_REPORT.md) gives prior limited comparisons; it **did not establish universal parity**. Existing [OPEN_RISKS](OPEN_RISKS.md) RISK-604–609 remain open. Do not edit old evidence hashes or re-label those reports as new runs.
