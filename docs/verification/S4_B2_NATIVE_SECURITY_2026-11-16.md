## 2026-11-16 PT follow-up — source-exact P0 root causes, new safeguards and remaining blockers

**Current scope:** `S4_B2_PARTIAL`, **no runtime Peer authorization enabled**. The initial results below are preserved in their original order. This section supersedes the older initial description of IPv6 dynamic NDP as completely unsupported; later source-exact, fresh Incus 7.6 tests found a usable candidate, but not a finished installed security design.

### P0-1: exact IPv6 NDP mechanism and directional policy

- **Incus rule precedence is action-based:** `drop` → `reject` → `allow`, not YAML order ([official ACL specification](https://linuxcontainers.org/incus/docs/main/howto/network_acls/)). Kernel nftables captures showed B's NDP Neighbor Advertisement destined to source A could hit S1's private *destination* reject before the fallback neighbor-discovery allow. The original compiler exempted only B's address, so the reverse NDP address A was still rejected.
- Pure unexposed compiler now subtracts **only each confirmed endpoint's exact IPv4/IPv6 host address** from S1's private destination rejects, keeping all other bridge addresses in the reject set and retaining explicit A-source→B-destination ingress/egress grants. No whole-bridge private-prefix carve, arbitrary ACL editor or public MCP mutation.
- [Native run 44024807712](https://github.com/vanishs/boxweave/actions/runs/44024807712): first IPv6 A→B packet PASS with `internet=false`, no static neighbor. [Run 44025118912](https://github.com/vanishs/boxweave/actions/runs/44025118912): first IPv6 attempt DENIED, then after a subsequent ACL update (test-only NDP rules) PASS. **This is a real native convergence timing / rule reload uncertainty**, not evidence to mark the entire gate PASS. Both runs confirmed IPv4 allow, B→A and C→B dual-stack denial, stale ETag rejection, and revoke-before-IPv4-reuse denial; both ended `exit 75` by design because other P0 gates remain open. Their old terminal marker wording mentions NDP and is an out-of-date stage-label, not proof later v6 was permanently blocked.
- [Independent NDP runner 44025452681](https://github.com/vanishs/boxweave/actions/runs/44025452681) **SUCCESS**: native A→B IPv6 NDP reachable initially, five consecutive passive reruns without any ACL rewrite reachable, and after A/B restart reachable. No static neighbor was installed in that proof. Diagnostic-only additions of MLD rules, bridge multicast-snooping off and NIC default-allow were **not required** for initial/repeated successful traffic; **do not ship them**. Earlier MLD/ND failure logs [44024189751](https://github.com/vanishs/boxweave/actions/runs/44024189751) remain preserved.
- **Confirmed mixed-trust security breach** [native 44025118912](https://github.com/vanishs/boxweave/actions/runs/44025118912) and [earlier 44016672654](https://github.com/vanishs/boxweave/actions/runs/44016672654): a different Project's **unfiltered** NIC on the same bridge forged A's source IP and actually reached B in **IPv4 and IPv6** despite the specific IP-based allow. Normal foreign addresses denied, but this is not secure source authentication. Peer grants on a shared, mixed-trust bridge remain **FORBIDDEN**.
- **Operator-owned dedicated bridge remedy**: [fresh Incus 7.6 run 44024247271](https://github.com/vanishs/boxweave/actions/runs/44024247271) confirms `restricted.devices.nic=managed` and project `restricted.networks.access` deny foreign restricted Project's `network=` and raw `parent=` attaches. [Further run 44025595691](https://github.com/vanishs/boxweave/actions/runs/44025595691) **SUCCESS**: an unrestricted host administrator can still attach by both managed and raw `parent=bwbr0`; the full root `Network.UsedBy` showed the foreign instance **and the raw-parent Profile**, with its real bridge port observed. Host root remains trusted above BoxWeave, but a new/unknown consumer must make controlled Peer operations fail closed until reviewed. An active attach after an earlier safe snapshot still requires authorized rereread or explicit trust assumptions.
- New `internal/install/network_peer_bridge_guard.go` (and tests) supplies a **necessary-only** fail-closed native `UsedBy` consumer check. It is **NOT wired to enable Peer** and does not by itself verify native UUIDs, effective devices, MACs, kernel bridge ports, IP lease ownership or TOCTOU / host-root changes.

### P0-2: native dual-stack fixed address and reuse evidence

- Official Incus [NIC documentation](https://linuxcontainers.org/incus/docs/main/reference/devices_nic/) and [proxy static-IPv6 prerequisite](https://linuxcontainers.org/incus/docs/main/reference/devices_proxy/) identify NIC `ipv4.address` and `ipv6.address`; native static IPv6 on a managed bridge requires `ipv6.dhcp.stateful=true`.
- [Disposable signed Incus 7.6 run 44025845932](https://github.com/vanishs/boxweave/actions/runs/44025845932) **SUCCESS**: actual B guest received fixed `10.246.173.42` **and** `fd17:246::42`. A second NIC configuration claiming the same IPv4 while B existed was natively refused with `IP address ... already defined on another NIC`. **After B stop/delete**, a different UUID obtained *both* of B's former addresses. This is decisive proof: static NIC allocation prevents the tested simultaneous config collision but does **not** reserve an address across deletion or protect IP-based ACL grants on its own.
- **Safety contract remains:** BoxWeave-only actor must hold ordered ACL + both Box + lease claims; revoke and confirm effective bidirectional policy/kernel new-flow denial **before** any stop/delete/native NIC detach that could free addresses; protect an IPv4/IPv6/MAC/UUID/incarnation tuple; never release quarantined leases after crash/timeout/ACK loss without independent native audit. The SQLite-only `network_address_fences` implement local hold/quarantine but are **not** native DHCP ownership. Out-of-band unrestricted host admins remain above this trust boundary.

### Still missing before formal B2 PASS

Native dedicated-bridge **combined** exact-Peer + negative spoof (including unknown same-Project NIC) and installed actor/ACL convergence under races; continuous trust and all effective NIC checks, source IPv6 change/restart/lease collision; ETag concurrent fanout, partial NIC reload, lost ACK/UNKNOWN; owner-specific restricted TLS/Scriptlet compatibility/rollback and approval for any host-global setting; installed BoxWeave MCP/OAuth role/integrated negative verification; an independent separate Verifier reviewing final same-head original receipts. `internet=false` retaining an explicitly granted Peer while blocking general egress is **a proposal**, pending owner semantic decision. Do **not** change `S4_B2_PARTIAL` or begin B3.

## P0-1: S1 egress vs peer

Native run 44015656120 used actual `nativePrepareACL` S1 output (two private/reserved destination rejects), actual A/B/C filtered NICs and distinct native UUIDs. Before the grant, A→B IPv4 and IPv6 packets were denied. Exact host-prefix subtraction and source+destination-specific ingress/egress allows were accepted with native SDK Get/ETag/UpdateNetworkACL/readback. A→B **IPv4** packets passed with NIC egress-default `reject` (preliminary `internet=false` behavior). B→A, C→B and A→C IPv4/IPv6 denied with explicit test-only IPv6 neighbor entries. The bridge gateway IPv4 remained inaccessible when egress-default was `reject`. Egress-default `allow` still did not establish actual gateway ICMP reachability; gateway ICMP is not proof of public Internet access.

A→B **IPv6** initially failed with `Address unreachable`. Guest A's B IPv6 neighbor state was `FAILED`. Even adding broad test-only ICMPv6 135/136 ingress/egress rules did **not** restore dynamic resolution. Test-only permanent A/B IPv6 neighbor entries did allow real IPv6 A→B packets, proving the unicast ACL path works with neighbor resolution supplied independently. Changing only B, then both A/B, egress-default to allow with those static neighbors still passed, but **is NOT a native dynamic-neighbor solution**. The broad ICMPv6 rules and manual neighbor entries must never be deployed as unreviewed production fixes.

**Product semantic proposal, still requiring owner confirmation:** `internet=false` denies general routed/Internet egress but does not cancel explicitly authorized managed Box peers. B2 cannot claim this semantic works for IPv6 yet. The compiler remains **unwired to any product mutation, explicitly unsafe for real peer admission** until native lease/exclusivity and both-family NDP/packet proof are solved. It never removes the entire bridge subnet from S1's protected private-destination set.

## Other Project and address reuse

On run 44015656120, a fourth instance in a **different Incus Project** attached to the same bridge without the BoxWeave-owned NIC ACL. With its *ordinary* addresses, A→foreign-D and foreign-D→B IPv4/IPv6 packet tests remained denied (`S4_B2_FOREIGN_PROJECT_NORMAL_ADDRESS_DENY=PASS`), after manual IPv6 neighbor preflight to prevent trivial ND-only false negatives. This **does not prove the foreign NIC cannot spoof the authorized A source IP/MAC**. Foreign source spoof, simultaneous attachment/race and external administrator changes are **NOT TESTED** in this runner.

On the same runner, ETag-authorized native ACL revoke restored the unchanged S1 ACL, readback verified exact rejection, and new A→B packets were denied **before B stop/delete**. C, which had a different native UUID and MAC, was then assigned B's former IPv4 by a controlled Incus NIC override and restart. The actual C address read matched B's prior IPv4; A's old IPv4 neighbor was cleared; A→C new packets stayed denied: `S4_B2_NATIVE_REVOKE_BEFORE_OLD_IPV4_REUSE_DENY=PASS`. Explicit native cleanup `S4_B2_NATIVE_EXACT_CLEANUP=PASS` was logged. This proves one ordered happy-path revoke-before-reuse procedure, **not** crash/ACK-loss correctness or native lease reservation by the product.

## B2 code delivered without exposing network grants

- `internal/state/store.go` schema **v3** introduces exact owned network bindings, address fences, directional grants, native proxy claims and multi-resource operation claims. Per-network SQLite admission acquires Box/ACL/resource claims atomically, and holds UNKNOWN locks.
- `internal/state/replay.go` preserves the original S2/S4-A digest for old single-resource operations; multi-resource intents bind canonical sorted resource keys and reject changed replay. Existing schema v2 databases are deliberately refused rather than silently migrated. **Installed upgrade/migration compatibility remains unverified and blocked** until a supported approach is accepted.
- `internal/state/acl_sync.go` adds a typed synchronous SDK effect receipt without inventing Incus native Operation IDs; post-send SDK error, postread mismatch, timeout and durability ambiguity stay UNKNOWN, not retried as an uncontended success. This is **not yet a complete native ACL/per-NIC convergence controller**.
- `internal/state/network_fences.go` offers local reserve/quarantine with no automatic release, including after different UUID/incarnation and restart. The address holds are explicitly **SQLite only**, not Incus static DHCP reservations, NIC anti-spoof ownership or host-wide lease exclusivity.
- Box Start/Stop/Update/Delete admission blocks on any non-revoked peer/forward and active/quarantined address claims. This provides safe local ordering groundwork, **not protection from out-of-band privileged Incus changes**.
- `go test ./...` and targeted Go race tests passed in the isolated work Box before the final documentation and native-reprobe commits; rerun on final HEAD and preserve actual Actions outcomes.
