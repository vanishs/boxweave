## P0-1: S1 egress vs peer

Native run 44015656120 used actual `nativePrepareACL` S1 output (two private/reserved destination rejects), actual A/B/C filtered NICs and distinct native UUIDs. Before the grant, A→B IPv4 and IPv6 packets were denied. Exact host-prefix subtraction and source+destination-specific ingress/egress allows were accepted with native SDK Get/ETag/UpdateNetworkACL/readback. A→B **IPv4** packets passed with NIC egress-default `reject` (preliminary `internet=false` behavior). B→A, C→B and A→C IPv4/IPv6 denied with explicit test-only IPv6 neighbor entries. The bridge gateway IPv4 remained inaccessible when egress-default was `reject`. Egress-default `allow` still did not establish actual gateway ICMP reachability; gateway ICMP is not proof of public Internet access.

A→B **IPv6** initially failed with `Address unreachable`. Guest A's B IPv6 neighbor state was `FAILED`. Even adding broad test-only ICMPv6 135/136 ingress/egress rules did **not** restore dynamic resolution. Test-only permanent A/B IPv6 neighbor entries did allow real IPv6 A→B packets, proving the unicast ACL path works with neighbor resolution supplied independently. Changing only B, then both A/B, egress-default to allow with those static neighbors still passed, but **is NOT a native dynamic-neighbor solution**. The broad ICMPv6 rules and manual neighbor entries must never be deployed as unreviewed production fixes.

**Product semantic proposal, still requiring owner confirmation:** `internet=false` denies general routed/Internet egress but does not cancel explicitly authorized managed Box peers. B2 cannot claim this semantic works for IPv6 yet. The compiler remains **unwired to any product mutation, explicitly unsafe for real peer admission** until native lease/exclusivity and both-family NDP/packet proof are solved. It never removes the entire bridge subnet from S1's protected private-destination set.

## Other Project and address reuse

On run 44015656120, a fourth instance in a **different Incus Project** attached to the same bridge without the BoxWeave-owned NIC ACL. With its *ordinary* addresses, A→foreign-D and foreign-D→B IPv4/IPv6 packet tests remained denied (`S4_B2_FOREIGN_PROJECT_NORMAL_ADDRESS_DENY=PASS`), after manual IPv6 neighbor preflight to prevent trivial ND-only false negatives. This **does not prove the foreign NIC cannot spoof the authorized A source IP/MAC**. Foreign source spoof, simultaneous attachment/race and external administrator changes are **NOT TESTED** in this runner.

On the same runner, ETag-authorized native ACL revoke restored the unchanged S1 ACL, readback verified exact rejection, and new A→B packets were denied **before B stop/delete**. C, which had a different native UUID and MAC, was then assigned B's former IPv4 by a controlled Incus NIC override and restart. The actual C address read matched B's prior IPv4; A's old IPv4 neighbor was cleared; A→C new packets stayed denied: `S4_B2_NATIVE_REVOKE_BEFORE_OLD_IPV4_REUSE_DENY=PASS`. Explicit native cleanup `S4_B2_NATIVE_EXACT_CLEANUP=PASS` was logged. This proves one ordered happy-path revoke-before-reuse procedure, **not** crash/ACK-loss correctness or native lease reservation by the product.
