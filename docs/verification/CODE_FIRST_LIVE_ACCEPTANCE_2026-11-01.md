## Scope, inventory and evidence classes

Code-first baseline inventories **37** `bwmini` Python modules, **41** unittest files, **23** developer/support scripts, **56** local Web API method+path entries, **9** remote HTTP MCP/OAuth method+path entries, **4** BoxWeave-owned MCP tools, **9** client Apps, and **8** frontend views. This includes the developer-only local source-bundle script and its tests; the upstream Containarium MCP catalog contains many additional Provider tools that are **not** individually implemented BoxWeave product features. The CI code-first guard checks the checked-in inventory against source; source presence and tool advertisement are not proof of successful operations.

Classification: **S** = source/inventory, **T** = executed unit/contract/browser fixture or CI, **L** = genuinely executed Box/Provider/client operation; **D** = older historical evidence, **U** = untested. **PASS** is always scoped to the exact observed criterion, **PARTIAL** means only a subset passed, **FAIL** is a reproducible failure, **BLOCKED** is a missing prerequisite or execution route, **UNKNOWN** is an operation with unconfirmed effects. Tests blocked by unsupported external client, host authority, paid model access or proven parent nesting must be recorded and skipped so other remediation proceeds.
