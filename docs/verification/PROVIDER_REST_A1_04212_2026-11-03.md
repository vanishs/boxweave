# v0.42.12 — App-owned Provider REST basics and D1 API diagnostic spans

**Date:** 2026-11-03. **Status:** source implementation; CI and installed-host gates remain distinct. Do not treat planned tests as executed evidence. Containarium installer pin remains `v0.120.1`, unchanged.

**Scope:** A limited first migration for the application/worker's `get/list/create/start/stop/delete/resize` calls. The external Agent-facing SSH/HTTP MCP Gateway stays unchanged. Network/Guard, auto-sleep, SSH `connect(exec)`, agent-box and restore still use their existing MCP paths. The specialised **create with `_nesting`** remains explicitly on upstream MCP because the pinned Containarium REST create request does not provide the same independent nesting operation.

## Code locations

- `bwmini/provider_rest.py`: bounded, no-redirect/no-proxy, loopback-only `http://127.0.0.1:<port>` Containarium REST transport; per-request read of the app-user-owned 0400 token file; GET List/Get and POST Create/Start/Stop, DELETE Delete, PUT Resize.
- `bwmini/provider.py`: app Provider selects REST only when `provider_api={url,token_file}` is explicitly provisioned; existing `mcp` mode and launcher remain for identity checking/SSH, specialist paths and gateway.
- `bwmini/access_provider.py` and `environment_observe.py`: app-level container Get reads use REST when enabled while other native/Guard/capability tools retain the upstream MCP.
- `bwmini/bootstrap.py`: fresh install writes private `provider_api` config; reviewed, app-owned existing `config.json` gets only an additive API binding, preserving other operator configuration. Existing unsafe/foreign files stop the install rather than silently changing ownership. Managed and external Provider URLs remain restricted to pre-reviewed loopback.
- `bwmini/lifecycle.py`, `app_runtime.py`, `diagnostics.py`: API spans correlated to existing durable environment operation `trace_id` and receipt; `provider_api` diagnostic component is secondary and best-effort.
- `bwmini/deploy_check.py`: when the app config selects REST, independently check an authenticated REST list alongside the existing authenticated MCP list. Unavailable REST blocks installation instead of masquerading as success.
- `tests/test_provider_rest.py`: isolated fake HTTP transport tests for CRUD wire paths, exact identity, rotating token, denial/timeout UNKNOWN, response shape, incomplete inventory, nesting fallback and trace redaction.

## Safety and evidence boundaries

- **No implicit HTTP write retry.** Mutating transport loss remains UNKNOWN; acknowledgement alone is not state convergence, SSH readiness or backup verification. Existing lifecycle reconciliation and claims continue to own these distinctions.
- **No arbitrary endpoints or automatic provider upgrades.** API JWT never appears in command arguments, debug traces, host logs, outgoing URLs or error text; no redirect/proxy allowed.
- **REST is the *app control-plane* only.** The existing Agent MCP direct tool relay is not moved in this release. Even on the same Box, the two independent entry paths retain their previously documented coordination limits.
- **No legacy Box deletion.** No Box is deleted by installation or transport migration. The absence of customers reduces historical migration work but does not add missing daemon endpoints.
- **Upstream source vs installed runtime.** Protobuf routes were source-read for Containarium v0.120.1; real app-token scopes, host package, exact state enums and features must be validated against an installed host separately.
- **D3 remains active for inbound MCP**, with its existing seven-day private gateway journal; D1/D2 gains metadata-only REST spans. D4 remains exact-Box gated and unchanged. There is no daemon-internal distributed trace claim.

**Release rule:** Publishing an immutable `v0.42.12` release is not equivalent to L1–L4 acceptance or promotion of the stable default installer. Keep `PUBLISHED_RELEASE=0.42.1` until a separately reviewed real-host acceptance. Install this candidate only by specifying `--version 0.42.12` after publication.
