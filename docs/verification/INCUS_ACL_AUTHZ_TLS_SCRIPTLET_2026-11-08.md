# Native Incus ACL authorization — tagged-source investigation and real TLS/Scriptlet SDK probe

**Date:** 2026-11-08  
**Status:** **partial P0 capability validation** in one already-authorized **nested** Incus 7.6 laboratory, **not** a BoxWeave v1 controller acceptance or a production authorization deployment.  
**Repository:** `vanishs/boxweave` branch `v1`. Earlier native lifecycle and Bridge NIC packet tests: [SDK native batch](SDK_NATIVE_BATCH_RESULTS_2026-11-08.md).

## Executive conclusion

- **Plain restricted TLS credentials are insufficient for dynamic Bridge ACL maintenance.** A certificate restricted to the Box Project cannot edit ACLs physically owned by `default`; a certificate restricted to `default` can edit those ACLs, but has **Project-wide** powers, not object-only ACL permissions.
- **Official Incus Scriptlet Authorization works for an existing exact ACL.** It allowed `can_view/can_edit` on **`network_acl:default/bwv1-acl-1108-a`**, while the official Go SDK could not view/edit/delete a second inert ACL or switch to an unauthorized Project. No separate OpenFGA server or custom privileged process was used in the experiment.
- **Go SDK native ACL ETag works:** `UpdateNetworkACL` with a current ETag succeeded; using the old ETag returned **HTTP 412**, leaving the current rule object unchanged. Prefer this native optimistic concurrency check.
- **Dynamic ACL creation remains project-granular.** `POST /1.0/network-acls` checks `project:default#can_create_network_acls` **before decoding the request body/name**. When a test Scriptlet briefly allowed this entitlement, the restricted client created a new arbitrary-named ACL despite the otherwise exact-object allowlist. It could not then read that ACL. This is **an authorization-granularity limitation, not a vulnerability claim**.
- **Global routing is a serious deployment constraint.** Changing `authorization.client.tls-restricted=scriptlet` diverts *all* restricted TLS clients to the scriptlet and **no longer automatically enforces certificate Project restrictions**. An exact-test-only scriptlet deliberately denied the second existing test certificate. Any production policy must also preserve all legitimate existing client permissions safely, or use a separately approved alternative architecture. Do not apply it automatically to a shared Incus host.
- **No v1 P0 `box_peer_set` PASS yet.** Dynamic creation/ownership validation, shared-host policy compatibility, address changes, rule/body validation and crash behavior remain unresolved. No approval for a privileged helper or broad `default` credentials follows from this test.

## What this means for v1 (not a change of P0 contract)

**Keep the normal application runtime confined to a native Project.** Existing [real SDK batch](SDK_NATIVE_BATCH_RESULTS_2026-11-08.md) proved this for instance lifecycle, Exec, guest file calls and TCP/UDP native instance-owned `proxy` once the owned Project had `restricted.devices.proxy=allow`. No reason to create a general Incus wrapper.

**Native Scriptlet can replace the proposed custom privileged component for updating an already-existing ACL** provided all of the following are established in the real host:
1. The ACL object is separately created, **exactly and exclusively owned by BoxWeave**, and attached to only the intended owned NIC(s); check `used_by` before changes. `can_edit` authorizes the *entire ACL object's rules*, **not** just one desired pair rule, so the application must validate the full outgoing ruleset, current IP/MAC/IPv6 ownership, host service allowances and native ETag.
2. A dedicated credential with TLS server pinning, private-key protection and rotation is used for this narrow operation; it must never be exposed to ordinary MCP tool clients.
3. The **global** `authorization.client.tls-restricted=scriptlet` route must not silently change authorization for other existing restricted TLS clients. A production Scriptlet would have to **faithfully reproduce every original certificate's Project restriction**, or use a separate, explicitly approved authorization topology. Merely returning `true` for non-test certificates is unsafe; returning `false` will break legitimate clients.
4. Its own policies, traceability, config update/rollback and shared Incus ownership must be reviewed. **The local test's single-fingerprint deny-everyone-else policy is not production-ready** and must never be copied unchanged.

**Crucially, the creation path is still unresolved.** Since ACL creation checks a **Project entitlement before parsing the name**, Scriptlet cannot distinguish a legitimate new Box ACL name from an arbitrary one at the point of authorization. In a dedicated single-tenant Incus deployment, authorizing the dedicated credential to create ACLs in `default` and enforcing exact BoxWeave business rules might be an explicit *risk-accepted* choice; it is **not least-privilege native authorization**. On shared hosts, an out-of-band narrowly owned bootstrap/creation boundary, preprovisioned limited ACL slots (with a capacity policy), or an owner-approved dedicated control mechanism may be needed. Do not quietly choose one or resurrect historical general admin helpers.

**The current requirement remains P0 BLOCKED/PARTIAL**, not `UNSUPPORTED` for native ACL edits. A single owner-facing choice about **shared-host ACL creation permission and acceptable daemon-global Scriptlet routing** remains after this research. Do not change the permanent Bridge/no-general-ACL/no-extra-API scope by default.

## Smallest further acceptance

1. Design-review whether configuring the **daemon-global** Scriptlet route is permitted for a shared pre-existing Incus host; pin the exact authorized credential policy and preserve existing cert restrictions. Avoid changing L0 until approved.
2. Resolve **dynamic ACL creation** granularity using upstream capabilities/explicit owner threat model; code proof must deny unauthorized ACL creation as well as edits and verify only owned NICs are attached.
3. Only then integrate the two narrow native SDK credential paths into an actual v1 runtime, test ACL mutation concurrent ETag and identity changes, compromised/expired credential denial, rollback and audit; run L0 independent LAN/IPv4/IPv6 witnesses separately.

No additional L0 Box was created. The v1 source branch remains documentation-only.
