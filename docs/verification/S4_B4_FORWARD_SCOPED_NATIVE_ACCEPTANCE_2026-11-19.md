## Implemented guarantees and boundaries

1. Three new public MCP Tools `port_forward_list`, `port_forward_create`, `port_forward_delete`; inventory 21 including earlier Activity and Peer; legacy/native SDK and S3 discovery inventories adjusted. No new root proxy, generic ACL editor, or foreign Project access.
2. Only exact-owned instance `proxy` device `bwpf-<original ID prefix>` is modified. Conditional ETag mutation, exact field/UUID/native postread and original durable asynchronous Operation remain separate; native uncertainty is not collapsed into success.
3. `forward_claims` reservation and resource claims are committed atomically with the original admission; host/protocol/port conflict stays blocked, including old UNKNOWN. Verified final `CONFIRMED`/`REVOKED` and original SUCCEEDED event are one SQLite transaction. Independently proven no-dispatch failures may release a PENDING claim; an uncertain native dispatch cannot.
4. **Only host loopback binds** `127.0.0.1` or `::1` are currently supported. An MCP `confirm_external_exposure` flag is **not** trusted host-local authorization for an external host interface. No wildcard, public or arbitrary LAN listener may be enabled by this B4 implementation until a separately approved exact-host authorization design and native acceptance exist.
5. `port_forward_list.native_verified` is **false** for pending/unverified claims; the boolean certifies only the exact current device postread for a CONFIRMED record, **not** a live packet, external LAN reachability, or permanent host-level attestation.
