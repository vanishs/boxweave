## Reproductions, repairs, and executable checks

### R-04 dispatch intent misclassified after interruption

A previously recorded genuine live interrupted tracked execution retained a task store row in `dispatch_intent` (read externally as UNKNOWN) and an identical shared coordinator `dispatch_intent` row, despite one actual guest-side write. On v0.44.8 the next Agent could be told `RESOURCE_BUSY` indefinitely, because a fresh process cannot distinguish a still-running dispatch from its crashed predecessor by row state alone. The unused `recover_dispatched` helper cannot safely be invoked globally on gateway startup: independent gateway processes may still be running.

**Fail-before-fix reproduction:** added `test_dispatch_intent_requires_original_outcome_reconciliation` to `tests/test_operation_coordination.py`. Original code failed exactly `RESOURCE_BUSY != RECOVERY_REQUIRED` (1/10 cases failed). **Patch:** `OperationCoordinator.acquire` now classifies either `dispatch_intent` or `unknown` as `RECOVERY_REQUIRED` for a competing resource, leaving the original claim, state, receipt, and all guest writes untouched. An accepted but not dispatched operation and an independent unexpired lease still report `RESOURCE_BUSY`. This is only a conservative diagnostic classification, **not** proof that the original operation has finished, nor an automatic recovery or an extra authorization.

Regression checks added at the gateway boundary: a second tracked task under another Web/Agent dispatch-intent receives `RECOVERY_REQUIRED`, its receipt becomes `failed_before_dispatch`, and zero Provider `connect` writes are forwarded. Adjusted previously sampled in-flight test expectations to the more conservative classification. Focused `test_operation_coordination.py` 10 PASS, `test_operation_leases.py` 5 PASS, `test_gateway_tasks_gateway.py` 10 PASS, `test_lifecycle_shared_claims.py` 13 PASS and `test_box_actions_shared_claims.py` 10 PASS.

### Ambient host policy contaminated Gateway fixtures

With the isolated host's root-owned `coordination-policy.json` genuinely enabled, the unmodified test suite failed 20 of 740 cases (18 assertions and two errors), although the same source had passed in a policy-free CI host. Several Gateway test classes had silently expected legacy routing while inheriting machine-wide protected mode. They consequently reported unrelated `COORDINATION_USE_TRACKED_TASK` / `COORDINATION_TOOL_UNCLASSIFIED` instead of exercising their intended paths.

Six affected test classes now use scoped class-lifecycle mocking to select legacy-mode defaults explicitly; their protected-mode tests override the fixture with protected-mode controls. Source code never acquires a test-only environment bypass, and no root policy is disabled or edited. Under the unchanged enabled policy, the rerun passes **742/742** after the two new R-04 regression cases.
