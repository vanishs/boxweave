### Safety limitations and scope boundaries

- This is **not** permission to upgrade a shared daemon with existing guest instances or unrelated consumer Projects: the v1 native migration intentionally refuses **all native instances and unexpected Projects**, including stopped instances, before daemon stop or APT. More disruptive maintenance needs separate host/version-specific authorization; that is not a missing implicit public MCP feature.
- Mid-**dpkg** process termination while packages are half-configured was **not** performed. The proven windows are (a) simulated failure **before** APT invocation side effects and (b) real package upgrade **completed** with parent process abruptly exited **before** durable ACK. The intermediate half-configured state must remain honest `UNKNOWN`/manual recovery if dpkg refuses. Do **not** claim an arbitrary broken package database was automatically repaired.
- The newest binary/Go revision has independent systemd + MCP + native **read** verification; prior genuine Incus mutation/crash/manual-UNKNOWN test and legacy MCP/48-concurrent verification remain pinned to [earlier real evidence](S1_FOUNDATION_LATEST_2026-11-09.md) and unchanged state/control implementation. The new native maintenance tools are **host-local**, not additional public MCP tools.
