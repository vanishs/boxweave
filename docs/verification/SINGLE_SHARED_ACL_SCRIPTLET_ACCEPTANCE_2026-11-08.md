# Single shared Bridge NIC ACL + native Incus Scriptlet: actual three-Box acceptance

**Date:** 2026-11-08  
**Branch:** `v1`  
**Decision:** **SELECTED v1 native backend design**, **not** a v1 controller/release PASS. The isolated nested Incus 7.6 laboratory passed the targeted normal-flow tests; native database-stall recovery and missing production security/lifecycle gates remain explicitly tracked.

This report follows the [first native SDK B/C batch](SDK_NATIVE_BATCH_RESULTS_2026-11-08.md) and [exact-object TLS/Scriptlet permission probe](INCUS_ACL_AUTHZ_TLS_SCRIPTLET_2026-11-08.md). The owner **accepts a documented daemon-global `authorization.client.tls-restricted=scriptlet` configuration** instead of eliminating `box_peer_set`, adding a custom privileged helper, or deploying OVN/OpenFGA.

## Chosen product design and trust boundaries

**One precreated, BoxWeave-exclusive native Incus NetworkACL per controlled network/controller**, rather than one dynamically created ACL per Box. The test used one ACL `bwv1-single-1108` owned by the effective Incus network Project `default`. The host-local **installer** creates and identifies this ACL once using approved local administrative authority; **the network-facing MCP runtime cannot create, delete or rename ACLs**. All BoxWeave-owned NICs on the tested bridge attach this same ACL **before first start**, with NIC-local `security.acls.default.ingress.action=reject` and `security.acls.default.egress.action=allow`. Do not attach it to any unrelated/foreign NIC or silently replace existing foreign ACLs.

A dedicated **restricted TLS credential** with its own protected key, verified server certificate and a narrowly targeted **native Incus Authorization Scriptlet** grants **GET + PUT** (`can_view`/`can_edit`) for **one exact shared ACL object only**. Actual Scriptlet authorization must check the authenticated fingerprint and HTTP method, deny unknown operations and Project switching, and never grant `can_create_network_acls`. Normal guest lifecycle/Exec/file/proxy traffic stays in the distinct restricted Incus Project/account. The app exposes only `box_peer_set(source_box_id,target_box_id,allow)`, **not** arbitrary ACL rules, CIDRs, protocols or ports.

The ACL's ingress rules are generated exclusively from current approved **source Box UUID → target Box UUID** grants, resolved to verified current NIC IP addresses. An A→B grant produces two source/destination rules for **IPv4 and IPv6** when both are supported, matching **all ports**; replies were accepted statefully in this laboratory, but independent B-initiated flows remained denied. All grants are removed/recomputed on delete, restart, address/ownership change, mismatched NIC, suspected spoofing or stale identity; do not equate historical IP with a Box identity. The SDK flow is `GetNetworkACL` + native ETag → validate full `used_by` ownership and exact ruleset → `UpdateNetworkACL(...,ETag)` → native readback. Stale ETag **HTTP 412** requires refresh/recompute; an ambiguous mutation receipt requires reconciliation, **not blind replay**.

### Accepted daemon-global change: mandatory warning and safeguard

Incus `authorization.client.tls-restricted=scriptlet` routes **every restricted TLS certificate** on that daemon to Scriptlet, *instead of* the built-in certificate Project restriction handler. This **changes the entire Incus daemon's authorization policy**, not only BoxWeave. The user has approved this capability *as a product choice*, but safe installation still requires explicit notice, inventory and backup of the previous routing/scriptlet/trusted certificates, controlled policy merge or carefully verified replacement, an authorization regression matrix for every known restricted TLS client, native admin recovery/rollback instructions, and no silent privilege broadening. A generic `return True` fallback is forbidden; unexpectedly unrecognized credentials/entitlements fail closed. The compatibility policy in this isolated test is **an example to evaluate**, not production-ready proof of parity for every endpoint, Incus version or concurrent application. A shared-host preexisting incompatible Scriptlet should block installation of the peer feature until safely reconciled, rather than overwrite it.

The installer is responsible for creating the single ACL and setting the global route only after the preceding safeguards. All privileged setup is **host-local**. The MCP runtime never receives root/`incus-admin`, an unrestricted TLS certificate, a generic host firewall API, unrestricted ACL creation, or access to other administrators' projects.

### Critical separate environmental failure during this test

The single original native L2 C creation timed out with **exit 124**. The inner Incus Cowsql database again reported **`no available cowsql leader server found`**; the native `incus` inventory became unreadable while `incus.service` still existed. This closely matches the **earlier** independently witnessed nested Incus database incident but does **not** establish its underlying cause or prove a BoxWeave v1 implementation bug. **Never auto-replay** the ambiguous create: after recovery, native readback showed C **already existed STOPPED** with UUID `706ae153-5e7e-496e-aa41-556cfa4348dd`. The script finished configuring C's NIC and started the **existing** three identities exactly once.

A controlled inner-only normal service stop initially exceeded a **65-second command timeout**, but the daemon subsequently exited on its own. A later reconciliation script checked that the service was already `inactive` and PID=0; **no forced SIGKILL was actually sent**. With inner daemon stopped, it saved a root-only offline backup `single-acl-1108/inner-db-force-recovery-20261108T110247Z.tgz` and SHA256, restarted only inner Incus, then native Project/instance/UUID reads succeeded. This nested reliability problem must remain **OPEN**; do not assert stable Incus behavior under nested bulk creation, infer an upstream bug, or repeat failed mutations on transport status alone.

The outer BoxWeave `main` gateway intermittently returned `UNAVAILABLE`, `TRUST_OBSERVATION_STALE`, and internal errors. Native post-state and saved one-time operation receipts were used to distinguish actual completion from gateway transport errors. No outer L0 instance or Incus restart/upgrade was issued.

## Production-oriented decision (no new backend yet)

**Select** the native one-ACL model for v1 rather than per-Box dynamic ACL creation, a new privileged ACL helper, generic Incus admin authority, OVN dependency or a custom firewall:

1. **Install/bootstrap:** inspect shared Incus host for existing `authorization.client.*`, trusted restricted TLS clients and ACL name collisions. Warn that scriptlet routing is **daemon-global**, save exact old policy/config and validate a rollback. Require explicit local operator consent if installing on a previously configured host. Provision one strictly named, BoxWeave-exclusively-owned ACL with local administrator authority and verify `used_by` ownership; do not give runtime ACL-create privileges. Install a dedicated restricted cert and protected server-pinned TLS client **only for exact ACL GET/PUT**. Normal service user remains `incus`-only and restricted to owned Project.
2. **Auth compatibility:** when routing restricted TLS through Scriptlet, preserve the default TLS-like Project permissions for *non-BoxWeave restricted certs* without relying on an unsafe `allow all`. The restricted-TLS driver's full behavior includes per-endpoint `CheckPermission`/permission checkers and exceptions; **copying the small test policy is insufficient**. For actual pre-existing certs, compare read and denied mutation behavior before/after; abort/rollback on any widening or unexplained loss. If a host already has custom Scriptlet, merge safely or block feature until resolved. Root Unix recovery availability and failure rollback should be proved.
3. **At every Box lifecycle mutation:** ensure private deny at the managed NIC before starting, attach only the exact ACL to owned NICs, verify native `used_by` has **no foreign NICs**, and keep durable Box UUID → NIC/IP/IPv6 grant mapping. Do not assume an Incus Project or the shared ACL name itself is packet isolation. A new Box without a known-safe current ACL is not started.
4. **At `box_peer_set`:** authorize both exact owned UUIDs, resolve current live addresses and anti-spoof settings, compute the **entire** owned ACL rule set from durable directional grants (all ports, IPv4+IPv6), then GET/ETag, exact `used_by`, validated PUT, native readback. Never grant target reused IP/foreign NIC inadvertently. HTTP **412** → recompute; ambiguous native timeout → reconcile before any repeat. Fail closed on partial NIC application or address uncertainty and expose *desired vs native confirmed vs packet verified* status separately.
5. **At stop/delete/revoke:** remove dependent grants before reclaiming addresses, confirm newly initiated flows denied and preserve UNKNOWN if native state cannot be read. The native [BridgeUpdateACLs](https://github.com/lxc/incus/blob/v7.6.0/internal/server/network/acl/acl_bridge.go) applies shared ACL changes **NIC-by-NIC**, not as one atomic three-NIC transaction. Native ACL Update has database reversion on error but this does **not** prove every in-kernel per-NIC packet filter rolled back. A partial reload, unexpected lifetime or IP change must be treated as a real security failure.
6. **Do not add a host allow rule by default:** native **instance-owned** loopback TCP/UDP proxy worked with shared ACL default private ingress deny and no host allow. Keep port-forward authorization independently checked; real public/LAN bind, listener collision, IPv6 native proxy, service restart and L0↔L1 chained routes require independent acceptance.

**Still NOT accepted for a real shipped v1:** multi-client actual shared-host Scriptlet migration including other authorization protocols and API paths; full authorization negative/fuzz/regression under patched Incus updates; guest-IP reassignment, MAC/IP anti-spoof, persistent connections across revoke; high Box count ACL reload performance and partial-NIC-apply failure; native Incus reliability under nested repeated creates; real external LAN client; compiled v1 server/installer/upgrade/rollback. Product direction is selected, but the P0 **implementation/release gate remains open**.
