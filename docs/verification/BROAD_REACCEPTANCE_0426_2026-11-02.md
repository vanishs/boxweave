## Additional observed issue: asynchronous concurrent create response

On the v0.42.4 isolated inner Provider, two concurrent independently named Gateway create_container requests both returned Provider failure/HTTP-500 responses. Independent actual Incus enumeration showed **both Boxes were created and RUNNING**. The root-published registry initially listed only one of those two and subsequently listed both. A later *sequential* fresh Box 4 create returned explicit success. **Do not retry an uncertain create on the same name.** The exact upstream failure cause, async readiness race, and appropriate reconciliation at this Provider version have not been conclusively established; no unsafe post-hoc success response was fabricated. **OPEN / upstream investigation required** (not a reproducible source-only BoxWeave patch). The original uncertain state and claims were preserved on the stopped test Box.
