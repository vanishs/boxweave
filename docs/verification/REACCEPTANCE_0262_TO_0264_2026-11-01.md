The fixed v0.26.3 candidate helper was downloaded by immutable Commit into old v0.26.1 `boxweave-test-ser` and run read-only/unchanged apply as described; it was **not** substituted for a real updated outer gateway/parent configuration.
- Owner-approved `enable_nesting:true` create is *not atomic*: the first tool error must not authorize a second create without observing original state. The test Box eventually appeared RUNNING with exact username `bwaudit2-1101`, source creation timestamp and IP; final deletion readback confirmed absent. `boxweave_nesting` still refused on it; nested execution must not be declared passing.
- In the fresh v0.26.2 Box, actual unauthenticated `GET /api/login` returned **500**, while `/api/projects` returned **401**. Source `@app.errorhandler(Exception)` was swallowing Werkzeug `HTTPException` before fix. Installed v0.26.4 returned **405/404/401**, all expected, and `doctor --mcp` all ten required checks still passed.

Root test errors were caused by exercising tests in an invalid identity profile, not used as proof of a source regression.

Auto-sleep reverted to disabled. The disposable Box was stopped then deleted, absent on final `list_containers`.
