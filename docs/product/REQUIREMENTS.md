# Requirements — behavioral authority

All18 requirement outcomes are selected by developer approval SRC-026, subject to the basic feature boundaries in [SCOPE](SCOPE.md). Selected implementation/evidence through TASK-012/0130.9.0 is complete for developer acceptance; current per-requirement dispositions are in [the matrix](../verification/FEATURE_MATRIX.md) and [release report](../verification/TASK_012_013_RELEASE.md). This is scoped actual evidence, not certification for untested platforms/deployments. Priority P0 = foundation; P1 = required release feature. Design elaborations alone are not runtime evidence. AC IDs link to [ACCEPTANCE](ACCEPTANCE.md); SRC IDs to the [source register](../knowledge/SOURCE_REGISTER.md).

Evidence classes: constraint = current authorized governance; legacy-derived = inferred need grounded in old behavior; new hypothesis = proposed new user outcome needing validation. Approval: SRC-026, 2026-10-28, DEC-001 through DEC-005; Windows native/WSL SSH with Codex and ZCode(GLM), basic Web/Tenant/ports/Graph/model wizard, trusted operator. The conditional feature clauses are now selected and required within SCOPE; all safeguards apply.
